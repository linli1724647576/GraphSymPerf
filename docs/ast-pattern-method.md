# GraphSymPerf 基于随机 AST 与 Pattern 嵌入的方法

方法版本：`ast-pattern-v1`；文档修订：`implementation-r1`；日期：2026-10-26。六阶段方法已接入受限查询片段的实现；对应接口见 [代码技术文档](ast-pattern-implementation.md)，实现范围与验收证据见 [实现验收记录](ast-pattern-implementation-status.md)。

## 1 研究问题与方法概述

图查询中的优化机会既取决于局部运算，也取决于它所处的查询上下文。相同的路径匹配被用于计数、存在性判断或条件分支时，外层对结果的需求不同；相关变量和输入行数又会改变该匹配被求值的机会。为在多样化上下文中检验这些优化机会，GraphSymPerf 将查询结构生成与优化模式选择分离：先随机生成抽象语法树（Abstract Syntax Tree，AST），再在兼容位置嵌入预定义模式（Pattern），按照模式及其上下文构造图状态，最后生成查询对并分析局部工作向外层传播的条件。

设 \(\mathcal L\) 为具有明确类型、作用域和确定性语义的只读查询片段，\(\mathcal P\) 为 Pattern 集合，\(B\) 为结构与图规模预算。方法产生测试用例

\[
\mathcal T=(G,Q_1,Q_2,p,s,\Delta),
\]

其中，\(G\) 是查询对共用的图状态（Graph State），\(p\) 是本次变异的目标 Pattern，\(s\) 是其嵌入位置，\(\Delta\) 记录该位置与外层上下文的依赖关系。查询对须满足

\[
\operatorname{Bag}(Q_1,G)=\operatorname{Bag}(Q_2,G).
\]

这里，多重集（bag）相等保留行的重复次数、值的类型和空值；返回列表时保留列表内部顺序。方法优先生成不依赖最终行序的查询；涉及顺序敏感的内部消费时，另行满足相应的顺序保持条件。测试目标是在结果关系成立的条件下，观察数据库是否消除不必要的候选访问、重复计算或被屏蔽的求值。

方法严格按照以下六个阶段组织。类型检查、条件检查和有限重试属于各阶段内部职责；依赖关系的最终判定位于第六阶段。

```mermaid
flowchart LR
    A["M1 随机生成抽象 AST"] --> B["M2 在兼容位置嵌入 Pattern"]
    B --> C["M3 构造 Pattern-aware Graph State"]
    C --> D["M4 实例化整个查询"]
    D --> E["M5 按目标 Pattern 变异"]
    E --> F["M6 检查内层到外层依赖"]
```

| 记号 | 含义 |
|---|---|
| \(A_0\) | 尚未选择目标 Pattern 的随机抽象 AST |
| \(A\) | 完成 Pattern 嵌入后的抽象 AST |
| \(C[\cdot]\) | 目标位置之外的查询上下文 |
| \(p\)、\(s\) | 目标 Pattern 及其稳定位置标识 |
| \(G\) | 节点、关系、标签、属性及声明的索引条件 |
| \(\beta\) | 全查询抽象终端到图中实体类别、属性和取值的联合绑定 |
| \(\theta\) | 一组实际到达局部位置的外层变量绑定 |
| \(L,H\) | 在指定访问方式下具有较小、较大潜在工作的局部片段 |
| \(N\) | 目标工作区域的扩张参数 |
| \(\Delta\) | 语义依赖、求值需求、输入多重性及物理证据的分析结果 |

## 2 M1 基于 AST 的随机查询生成

M1 借鉴 GDsmith 将查询生成分为子句骨架生成与语义约束下补全的组织方式。GDsmith 的初始骨架保留尚未实例化的匹配项和表达式，再根据类型、变量生命周期及已有图数据补全查询。本方法将其中的结构选择放在构图之前完成：先生成子句骨架，再展开宿主的匹配、表达式和子查询结构，得到抽象 AST \(A_0\)。标签、关系类型、属性键及字面量等与具体图状态有关的终端仍保持符号形式。[GDsmith，§3.2.1，Table 1](https://taoxiease.github.io/publications/issta23-gdsmith.pdf#page=6)

### 2.1 随机生成子句骨架

生成过程首先按照查询语法选择子句种类和合法后继关系，形成由匹配、可选匹配、投影及受支持的其他子句组成的骨架。选择受目标语言能力、随机种子、子句数及嵌套预算约束。每个子句暂时只声明其内部待展开位置的类别，例如图匹配项、布尔条件、返回表达式或行流。

这一阶段决定查询的外层组织方式；下一步继续决定子句内部的运算结构。生成器不接收 Pattern 编号，也不读取具体图中的节点、关系和属性值。Pattern 选择前的宿主候选由同一生成分布产生，候选能否被某个 Pattern 接受则由 M2 的嵌入条件决定。

### 2.2 根据类型与作用域展开宿主结构

对骨架中的每个待展开位置，生成过程按照期望类型和当前作用域递归选择产生式。设 \(\Gamma\) 记录可见符号及其类型、可空性和定义位置，\(\tau\) 是当前输出类型，则生成的表达式须满足 \(\Gamma\vdash e:\tau\)。布尔位置可以展开为比较、布尔连接或存在性子查询；整数位置可以展开为整数属性或计数子查询；行流位置可以展开为匹配、投影、分支或受支持的组合。除预留的 Pattern 插入接口外，这些产生式持续展开至终端。

变量的定义和使用随子句推进。匹配引入新的实体符号，投影确定后继作用域可见的符号，别名建立新的定义关系；相关子查询只继承允许导入的绑定。可选匹配产生的实体类型带有可空信息。例如，经过 `WITH a, b.age AS x` 后，后继只能引用该投影导出的 `a` 和 `x`，而不能继续引用已被丢弃的 `b`。属性访问的结果类型由符号终端的声明约束，具体属性键及其实际取值由 M3 确定。

每次结构展开消耗 AST 节点或深度预算；预算不足时，只能选择仍满足类型与作用域的终结形式，否则本次生成失败。对于嵌套表达式和子查询，使用相同的递归规则及预算计量。AST 的多样性因此来自子句组合、表达式树、嵌套层次和相关关系。

### 2.3 保留嵌入接口与符号终端

随机结构同时保留可嵌入位置及其接口。一个位置的接口包含语法类别、可见变量、输出类型或列结构，以及外层对这些输出的使用方式。位置可以是类型化的扩展空位，也可以是允许整体替换的子树；后者被替换时，必须保持其对外接口。扩展接口与终端占位符承担不同职责：接口允许 M2 嵌入局部运算结构，终端占位符只允许后续绑定具体图元素类别或取值。

例如，随机生成器可以在尚未选择 P3 前产生以下结构：

```text
查询
└─ 返回一个整数
   └─ COUNT
      └─ 行流扩展位置
```

此时已经确定外层进行计数；内层将嵌入何种 Pattern 尚未确定。同一抽象结构可用于不同兼容 Pattern，同一 Pattern 也可进入其他独立生成的上下文。GDsmith 文献中的 pattern 指 Cypher 图匹配项；本文的 Pattern 则指带有适用条件与变异关系的测试规则，M2 将这些规则嵌入 M1 的接口。

## 3 M2 在抽象 AST 中嵌入 Pattern

Pattern 描述局部测试关系。其定义由六部分组成：局部源结构、变异结构、输入与输出接口、语义适用条件、图状态要求和目标工作特征。P3 规定无向有界路径的反转关系及允许的路径观察；S7 规定已有非空前缀的回退表达式及其可替换部分。这些定义约束局部优化机会，外层查询结构由第一阶段产生。

嵌入过程枚举 \(A_0\) 中的兼容位置，依据类型、作用域和输出观察选择 \((p,s)\)，随后将 Pattern 的源结构置入该位置。局部变量使用新符号，只有显式输入接口才绑定到外层变量，以避免变量捕获。Pattern 的输出必须满足原位置的类型与列结构要求；若原子树的输出在其他位置被引用，还须保持这些引用的意义。

嵌入后，完整抽象查询写作

\[
A=C[p^{\mathrm{src}}].
\]

除插入区域及必要的接口绑定外，\(A_0\) 的其余结构保持不变。若某个 AST 没有兼容位置，则重新选择位置、Pattern 或随机 AST；不通过为该 Pattern 重建固定外层查询来补救。

短路 Pattern 的边界必须包含使替换合法的完整局部上下文。例如，S7 的边界是包含非空前缀的整个 `coalesce`，而非仅被替换的最后一个参数。两份回退参数可以返回不同的值，等价性建立在包含前缀的完整表达式上。

一次生成选择一个显式嵌入的目标 Pattern。按行流观察定义的局部结构可以通过计数或存在性观察适配到整数或布尔接口；按标量值定义的 Pattern 则直接嵌入类型相容的表达式位置，保留其值观察。局部标量形式可以使用符号字面量表达决定性条件，图工作子查询保留自己的变量定义。适配与局部形式均在插入边界内确定，并参与后续图状态求解。若外层已有运算结构满足其他 Pattern 的形状与前提，则依赖分析将其识别为外层模式上下文，检查它对目标的求值需求与工作传播的影响。多个嵌套位置同时变异需要额外的组合条件，不由单点规则自动推出。

## 4 M3 根据 Pattern 构造图状态

### 4.1 从局部要求形成全局构造条件

模式感知图状态（Pattern-aware Graph State）将局部测试目标落实为具体图事实，同时实现随机外层查询所需的数据。设 \(\mathcal C_p\) 为 Pattern 的适用条件与工作要求，\(\mathcal C_A\) 为整个 AST 的语义要求，\(\mathcal C_{\mathrm{share}}\) 为共享绑定和读取区域的相容条件，则构造目标为

\[
\mathcal C_p(G,\beta)
\land\mathcal C_A(G,\beta)
\land\mathcal C_{\mathrm{share}}(G,\beta)
\land\mathcal C_B(G).
\]

\(\mathcal C_B\) 约束图规模和构造预算。联合绑定 \(\beta\) 覆盖整个 AST，而不只覆盖 Pattern 内部。它还涵盖第二阶段 Pattern 定义已声明、第五阶段将应用的变异形式所需的关系类型、参考区域或对应结构，使两条查询在同一图上有定义。

Pattern 提供“需要什么图事实”，通用构造过程负责将这些事实与外层要求组合。例如，P3 可以要求一条被接受的路径以及随 \(N\) 增长的失败候选；S7 可以要求每个输入绑定上存在非空前缀，以及大小不同的两个回退读取区域。外层若引入相关匹配，则必须同时构造能到达这些输入的连接；外层若对计数施加阈值，则相应的数量约束也必须满足。

共享变量代表同一实体，不能分别构造后仅因名字相同便视为相连。图区域合并还可能产生新增匹配，因此局部图的并集必须重新接受完整查询的约束检查。相互矛盾的属性、空值或数量要求导致构造失败，而不是通过忽略某个外层条件获得用例。

在条件求解中，方法借鉴 GDsmith 将表达式要求分解到子表达式的思路。GDsmith 利用记录的变量值引导条件生成；本方法沿 M2 已固定的 AST 分解要求，将其转化为图事实与终端绑定约束。[GDsmith，§3.2.3，Algorithm 3](https://taoxiease.github.io/publications/issta23-gdsmith.pdf#page=7) 例如，要求 \(a\land b\) 为 TRUE 时，两项均须为 TRUE；要求 \(a\lor b\) 为 TRUE 时，形成“\(a\) 为 TRUE”或“\(b\) 为 TRUE”的备选约束；要求 \(\neg a\) 为 TRUE 时，\(a\) 须为 FALSE。计数比较则转换为其直接输入行流的数量区间。备选条件在联合构造中选择并验证，不能合并为必须同时满足的条件。

约束目标由 Pattern 及外层消费关系决定，包含 TRUE、FALSE、NULL、空输入和数量要求。需要被过滤的候选与需要被保留的见证分别赋予相应目标。NULL 按三值语义传播；尚未求得或无法证明的事实标记为未知，不以 NULL 或默认成功代替。

### 4.2 语义见证与潜在工作

构造过程先建立语义见证，再扩大目标工作区域。语义见证包括满足存在性要求的路径、达到计数下界的匹配、保持非空前缀的属性值，以及两种匹配形式之间的一一对应关系。扩张规则根据 Pattern 的语义理由保留结果：被排除的候选不贡献有效行；被决定性条件屏蔽的片段可以有不同内部结果；对称变换保持可观察匹配及其重复次数。

所有条件都针对实际输入绑定验证。若 `coalesce(u.answer,E)` 的前缀须非空，则每个实际到达该表达式的 \(u\) 都必须满足要求。若外层 `COUNT` 要求至少三行，则约束施加于它直接计数的行流，不能以全图存在三条关系替代。可选匹配（`OPTIONAL MATCH`）的未匹配输入还须保留空值扩展；过滤器的 FALSE 和 NULL 均不保留行，但二者在其他表达式中仍须区分。

低成本与高成本描述特定访问或求值方式下的潜在工作，不是节点的固有属性。对于路径扩展，可以增大某一端的候选数；对于相关子查询，可以增加外层绑定的重复次数；对于短路表达式，可以增大语义上无需消费的回退区域。索引、统计信息和查询计划共同影响实际访问方式，图结构本身不决定数据库的最终执行成本。

### 4.3 构造与实例化之间的边界

第三阶段输出 \((G,\beta,I)\)，其中 \(I\) 保存构造成立的见证和约束事实。\(\beta\) 是联合相容的绑定方案，不是若干可独立抽取的候选列表。共享标签、属性值、计数阈值和参考区域之间的关联必须保留。

图中的具体见证可以用于选择属性与常量，但涉及决定性条件的证明须覆盖实际输入域。例如，一个根节点上的非空属性不能代表所有根节点都满足 S7。构造结果同时保留见证值及其适用的绑定域，使实例化能够重用取值依据，而依赖检查能够核验条件的覆盖范围。

第二阶段完成后，所有会影响图需求的算子结构均已确定。第三阶段可以选择与该结构一致的终端绑定；第四阶段将其落实到整棵树中。若需要改变路径长度、增加子查询或修改计数阈值，则该变化产生新的构造任务，不能在既有图状态之后直接补入。这一边界使“先构图、后实例化”具有明确的数据依赖方向。

## 5 M4 依据图状态实例化整个查询

实例化按照变量的定义与使用关系遍历完整 AST，将 \(\beta\) 中的标签、关系类型、属性键和字面量写入所有对应位置。共享符号使用同一绑定，相关子查询继承其输入接口，投影和别名按照已有作用域连接。由此得到

\[
Q_1=\operatorname{Instantiate}(A;G,\beta).
\]

实例化不仅填充 Pattern，也填充外围匹配、过滤、聚合与投影。若外层随机结构还存在未绑定位置，当前用例尚未完成。M1/M2 已完成宿主展开及局部嵌入，M3 已确定联合绑定；M4 按定义—使用关系落实这些绑定，不再选择表达式产生式。实例化后的查询必须保持 \(A\) 的运算符结构，并满足 \(I\) 中的要求；新的结构选择返回前面的生成或构造阶段处理。

在构造阶段验证过的终端表示可以保留有限的写法选择，但这种选择不能引入新读取、新算子或新的空值行为。实例化结束时，完整查询及其输入图共同固定，后续比较均基于这份状态。

## 6 M5 应用 Pattern 定义的变异

第五阶段复制完整的 \(Q_1\)，只在目标位置应用 \(p\) 的变换，得到 \(Q_2\)。变异保留图状态和其他位置的绑定。两类变异分别具有不同的等价性依据。

### 6.1 对称变换

对称变换（symmetry transformation）改变匹配或表达式的表示方式，同时保持允许观察的结果。路径反转通过路径对应保持计数和反转不变谓词；布尔操作数交换保持三值逻辑结果；匹配重排要求共享变量和各输入上的连接结果保持一致。

语法交换必须满足相应的观察条件。例如，P3 中路径反转会逆转节点序列，因此可保留路径长度和节点局部的全称谓词，却不能直接保留原路径序列的投影。`OPTIONAL MATCH` 的交换则需要逐输入保持空值扩展。P13 交换 `CASE` 分支时，需要对 NULL 原本进入 ELSE 的行为作空值安全处理。

### 6.2 短路变异

短路变异（short-circuit mutation）在完整的短路上下文内，以较大潜在工作的片段替换较小片段。写作

\[
Q_1=C[D[L]],\qquad Q_2=C[D[H]],
\]

其中 \(D\) 是使替换不改变观察结果的局部上下文。对所有相关输入 \(\theta\)，要求

\[
\operatorname{Obs}(D[L],G,\theta)
=\operatorname{Obs}(D[H],G,\theta).
\]

不要求 \(L\) 和 \(H\) 本身相等。例如，非空前缀确定 `coalesce` 的结果后，回退分支的计数可以不同。布尔吸收依赖 TRUE OR 与 FALSE AND 的三值语义，不能由文本位置推定物理求值先后。[Cypher 布尔算子文档](https://neo4j.com/docs/cypher-manual/current/expressions/predicates/boolean-operators/) 给出了相应真值表。

有限需求也可形成短路机会，但其等价条件不同。存在性判断要求保留见证；无序 `LIMIT k` 若在不同候选中任选行，则只有数量充足并不足以保证结果相同，还须保留被返回的值及重复次数。例如，各分支都返回同一常量行且至少提供 \(k\) 行时，结果均为 \(k\) 份该行。这样的条件属于 Pattern 定义，并在第三阶段实现。

所有可替换片段均须只读、确定，并在所构造输入域上有定义。变异完成后重新验证适用条件以及从完整局部边界向外的结果关系。

## 7 M6 检查内层 Pattern 到外层的依赖关系

### 7.1 分别追踪结果与求值需求

第六阶段判断内层变异在完整上下文中的意义。其组织方式借鉴 ValScope 的近似传播分析：从变异位置出发，通过实际输出使用关系，将局部关系逐层传至查询根部。ValScope 的传播对象是集合与值语义；GraphSymPerf 在结果关系之外增加求值需求和潜在工作分析。[ValScope，§4.4，Algorithm 1，pp. 394–395](https://www.usenix.org/system/files/osdi26-lin-li.pdf)

依赖关系同时包括父子消费、变量定义与使用、相关子查询输入，以及共享图区域。仅检查 AST 中的包含关系不能确定一个值是否影响外层，也不能发现一个别名被多个位置消费的情况。

对目标位置 \(s\)，分析以下四类信息：

| 分析对象 | 回答的问题 | 典型证据 |
|---|---|---|
| 结果依赖 | 局部值、行或路径观察是否影响外层结果 | 输出接口、别名使用、逐输入结果对应 |
| 求值需求 | 外层需要全量结果、部分见证，还是无需该片段 | COUNT、EXISTS、LIMIT、守卫、非空前缀 |
| 输入多重性 | 目标位置有哪些可达绑定，各出现几次 | 外层匹配、相关变量、空值扩展、行的重复次数 |
| 工作交互 | 内层变异或图扩张是否改变其他 Pattern 的工作条件 | 共享锚点、交叠读取区域、其他守卫及见证 |

“可达”在这里表示关系语义中的输入机会。数据库可能将它去相关、缓存、物化或消除，实际执行次数由物理证据确定。

### 7.2 逐层传递规则

每个外层算子结合当前图事实，对内层摘要作转换。常用规则如下。

| 外层结构 | 结果与需求的传递 |
|---|---|
| 投影、别名、WITH | 通过实际被使用的输出传递；删除的输出不再具有外层值依赖 |
| 相关子查询 | 按实际外层绑定及其多重性分析；逻辑重复机会不直接等于物理调用次数 |
| COUNT 子查询 | 结果取决于直接子查询的行数；逻辑上需要确定全部行数，物理计划可以采用等价计数优化 |
| EXISTS | 找到见证即可确定 TRUE；无见证时需证明为空；一个见证不意味着只访问一个候选 |
| LIMIT k | 只需求至多 k 个输出行；输入扫描量仍受过滤、排序和阻塞算子影响 |
| CASE、coalesce、布尔吸收 | 根据每个输入上的守卫或前缀，标记被需要与被屏蔽的子树 |
| OPTIONAL MATCH | 分别处理匹配行和无匹配时的空值扩展行 |
| 聚合、DISTINCT | 区分输入多重性和输出数量；输出减少不代表内部工作已经减少 |

行流消费还须区分行的存在与列值的使用。`COUNT { RETURN E AS x }` 的直接子查询返回一行，而无 DISTINCT 的计数不需要观察 E 的值；EXISTS 同样不需要未被其他消费者使用的投影值。COUNT 上的 DISTINCT 可能使行数依赖投影值，因此须保留相应需求。WITH 的表达式则根据后继匹配、过滤及必要投影追踪其别名使用。Pattern 整体位于未使用的投影内时，标记为外层屏蔽，与 Pattern 内部的短路保护分别报告。

`COUNT { ... }` 统计其直接子查询返回的行数。例如，`EXISTS { RETURN COUNT { MATCH ... } AS n }` 中，内层匹配为空使计数为0，但外围 RETURN 仍产生一行，所以 EXISTS 为 TRUE。需求传播必须经过每个中间算子，不能将最内层的空结果直接传至最外层。[Cypher COUNT 子查询文档](https://neo4j.com/docs/cypher-manual/current/subqueries/count/)

为描述相关上下文，令 \(\Theta_s\) 是到达位置 \(s\) 的不同绑定集合，\(m_s(\theta)\) 是绑定的多重性，\(c_i(\theta)\) 是查询版本 \(i\) 在假设局部片段被枚举时的候选量。则

\[
W_i^{\mathrm{potential}}(s)
=\sum_{\theta\in\Theta_s}m_s(\theta)c_i(\theta)
\]

刻画未经缓存、去相关或短路消除的潜在枚举规模。它用于定位候选工作从哪里被放大，不作为物理工作量或运行时间的下界。无法确定的基数使用区间；缺少传递规则的关系记录为未知。

对于以压缩证明图核验的大规模图族，证明图上的输入和候选计数单独标注其观察范围。结果保持证书不自动给出完整图上的精确输入次数；缺少对应基数证书时，完整图的数量区间保持未知。证明图中的一个见证可以支持构造条件，但不能替代完整图的数量推导。

### 7.3 嵌套 Pattern 的相互影响

当内层 Pattern 位于外层 Pattern 的子树中时，分别检查外层的语义前提和工作目标。内层变异可能保持外层返回值，却改变其候选访问方式、重复机会或共享读取区域。因此，“结果依赖已保持”与“工作条件保持”是两个检查结果。

例如，将 P3 放入 S7 的回退分支，且 S7 的前缀始终非空，则 P3 的结果不影响 S7 的输出。以 S7 为目标时，扩大回退工作仍是有效的短路测试；以 P3 为目标时，该对称变换的内部执行机会受到外层 S7 屏蔽，需要记录这一上下文。不能因回退分支的逻辑需求为零而删除 S7 用例，否则恰好失去检验多余求值的机会。

依赖检查可以发现目标位置无输入、受到外层屏蔽、被有限需求截断或存在重复机会。语义条件不成立的用例被拒绝；缺少语义传递依据的用例不能作为已通过等价检查的性能用例。结果关系成立而求值需求或物理效果未知的用例保留相应状态，交由执行验证。若一个目标要求非空输入，构造结果却完全不可达，则返回第三阶段重新构造或拒绝该目标配置。

### 7.4 将静态依赖与性能证据连接

静态分析输出依赖路径及待确认的工作假设。执行验证首先检查完整查询对的结果，再通过实际计划中的行数、访问计数和相关算子判断目标片段是否执行。计划无法与 AST 位置可靠对应时，局部物理关系保持未知。优化器决定实际算子及次序，不能将 AST 顺序直接解释为执行顺序。[Cypher 执行计划文档](https://neo4j.com/docs/cypher-manual/current/planning-and-tuning/execution-plans/)

运行时间在同一图状态及数据库配置上，经过预热、平衡执行顺序和重复测量获得；计划采集与常规计时分开。对嵌套工作机会，可分别改变内部规模 \(N\) 和外层输入规模 \(m\)，保持各规模下查询对的结果关系，再检查工作证据与总耗时是否共同变化。性能差异及其原因由这一证据链建立，静态分析负责提出并定位可检验的依赖关系。

## 8 贯穿示例

### 8.1 P3 从随机计数结构到对称查询对

**随机 AST 与嵌入。** 第一阶段产生第2节的计数结构。第二阶段在其行流位置嵌入 P3：两端具有角色约束的无向二跳路径，附加节点属性的全称谓词。这里二跳是本例的结构选择，不是 P3 的固定长度。P3 的源与变异形式共享端点变量和谓词，外层 COUNT 保持不变。

**图状态。** 对 \(N\geq1\)，构造节点

\[
V_N=\{s,a,t,b,z_1,\ldots,z_N\}
\]

及关系

\[
E_N=\{(s,a),(a,t),(s,b)\}\cup\{(b,z_i):1\leq i\leq N\}.
\]

所有关系类型为 `T`，路径匹配不要求方向；\(s\) 是唯一具有 `Start` 标签及 `id=1` 的节点；\(t,z_1,\ldots,z_N\) 带有 `Target` 标签。除 \(b\) 的 `keep=false` 外，所有节点的 `keep=true`。图中共有 \(N+4\) 个节点和 \(N+3\) 条关系，没有额外连接。

从 \(s\) 到 `Target` 的二跳候选共有 \(N+1\) 条。其中 \(s-a-t\) 通过谓词，其余 \(s-b-z_i\) 均因 \(b\) 而失败。因而候选规模随 \(N\) 增长，有效路径数始终为1。这个事实同时实现路径见证、失败候选和外层计数所需的图状态。

**完整实例化。** 标签、关系类型、属性及取值全部由该图的联合绑定确定，得到：

```cypher
RETURN COUNT {
  MATCH p=(s:Start {id: 1})-[:T*2..2]-(t:Target)
  WHERE all(x IN nodes(p) WHERE x.keep = true)
} AS n
```

**局部变异。** 仅反转标记路径的书写位置，变量及其约束随原变量保留：

```cypher
RETURN COUNT {
  MATCH p=(t:Target)-[:T*2..2]-(s:Start {id: 1})
  WHERE all(x IN nodes(p) WHERE x.keep = true)
} AS n
```

**依赖检查。** 每条源路径与反转路径一一对应；`all` 仅观察各节点的 `keep`，反转不改变其真假；COUNT 只观察有效匹配的数量。因此，两条查询均返回一行 `n=1`。候选区域具有单一 `Start` 与多个 `Target` 的不对称入口，但数据库可以为两种写法选择相同计划。该图例建立的是结果推导和访问机会，是否出现性能差异需要实际执行。

### 8.2 S7 的短路替换及外层输入依赖

考虑随机 AST 中一个返回整数的表达式位置，外层匹配产生 \(m>0\) 个 `Root` 节点。M2 选择无隐式导入的 S7 局部形式，决定项保留为符号字面量；M3 将其绑定为非空整数0，并为图工作子查询构造唯一 `WorkRoot(id=1)` 及其 \(N>1\) 个 `HIGH` 邻居。这些工作节点不带 `Root` 标签。源查询为：

```cypher
MATCH (u:Root)
RETURN coalesce(NULL, 0, 0) AS value
```

第五阶段仅将最后的低工作参数0替换为读取 `HIGH` 区域的计数子查询；该子查询自行定义工作锚点，不捕获外层 u：

```cypher
MATCH (u:Root)
RETURN coalesce(NULL, 0, COUNT {
  MATCH (r:WorkRoot {id: 1})-[:HIGH]->(v)
}) AS value
```

对所有实际输入，非空前缀确定值0；两条查询均返回 m 份 `{value: 0}`，保留重复行的数量。低工作参数自身为0，高工作参数的计数为 N，二者不需要相等。这里使用 `coalesce` 返回首个非空值的语义。[Cypher coalesce 文档](https://neo4j.com/docs/cypher-manual/current/functions/scalar/#functions-coalesce)

S7 表达式有 m 个逻辑输入机会，回退参数的语义需求为0。若对每个输入都枚举高工作参数，其潜在候选总量为 mN；低工作参数不读取图。数据库也可能消除回退求值，或把独立子查询去相关、缓存，因此 m 不等于物理调用次数。若 m=0，整个 S7 位置没有输入，这与“位置被到达，但内部参数应被短路”是不同的依赖状态。

## 9 六阶段之间的正确性关系

六阶段的结果保持依赖于三个连续条件。首先，嵌入后各位置的类型与作用域合法，图状态和联合绑定满足完整 AST 及 Pattern 的前提。其次，对每个相关输入绑定，源结构与变异结构在 Pattern 声明的观察边界上相等，或存在保持这些观察的匹配双射。最后，外层每个消费者都保持该关系，包括空值、重复次数和被使用的顺序。

在这些条件下，从目标局部边界开始，沿实际消费者逐层应用语义保持规则，即可归纳得到根部的多重集相等。短路变异的归纳起点是整个决定性上下文；P3 的归纳起点是保持路径观察的双射。若某一消费者不保持当前关系，例如直接返回反转后的路径序列或对不同值使用无序 LIMIT，则不能继续推出根部相等。

整个过程可概括为：

```text
输入：查询语法、Pattern 集合、目标语言能力、随机种子、预算
1. 随机生成子句骨架，再按类型和作用域展开宿主结构，得到含嵌入接口与符号终端的 AST A0。
2. 选择兼容位置并嵌入 Pattern，得到 A 和目标标记 s。
3. 联合 A、Pattern 及其变异形式的要求，构造 G、β 和事实 I。
4. 用 G 与 β 实例化整个 A，得到 Q1。
5. 在 s 处应用已定义的局部变换，得到 Q2。
6. 检查结果关系及内外层依赖，形成 Δ；执行验证补充物理证据。
输出：(G, Q1, Q2, p, s, Δ)，或带原因的构造失败。
```

失败后的回退使所有依赖该产物的后续结果失效：改变 AST 后重新构图，改变图或联合绑定后重新实例化、变异和检查。有限预算控制生成与构造的终止，未找到满足条件的图表示本次构造失败。

该设计将预定义知识集中在局部 Pattern 的结构、前提、图需求和变换中。查询上下文来自独立随机语法，图状态来自局部与全局条件的组合，实例化和依赖传递按统一语义处理。通用构图过程消费可组合的图义务，不按 Pattern 编号选择独占的整图构造器。检验这种分离时，既要确认同一 Pattern 能进入不同随机上下文、同一兼容 AST 能承载不同 Pattern，也要确认改变外层约束会使同一组构造规则生成相应的新图状态。新增局部规则若仍使用已有语义与图义务，应无需改写通用外层生成、构图和传递规则。具体支持范围由已定义的语法、构造能力和传递规则共同确定。
