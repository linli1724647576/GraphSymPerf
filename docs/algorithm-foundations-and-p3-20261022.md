# 查询目标驱动构图：文献依据、两算法草案与 P3 推导

日期：2026-10-22。本文是调研和方法草案，不修改现有源码或论文。代码事实按本轮读取核对；既有 P3 存档的 105 份源码、测试、配置及论文摘要均与冻结记录一致。本轮没有重新运行数据库实验。

结论：可以将新目标路线整理为“完整骨架分析 → 语义及工作需求下降 → 有限构造族实现 → 接受同一状态和绑定 → 实例化与局部变异”。QAGen、RQP、Qex 支持其中若干基本思想，但当前实现不是三者的代码复现；图路径构造、潜在工作目标和扩张检查属于本项目的设计。本文两算法只概括已迁移的目标路线，不覆盖仓库所有历史入口。

## 2. 三篇实际做了什么

### 2.1 QAGen：先控制算子结果，再求具体值

查询分析器根据输入特征判断哪些算子基数或分布可调，并选择对应符号算子；这些参数由用户指定或使用默认值。符号执行收集约束：例如选择算子的成功元组满足谓词，其余元组满足反谓词；共享连接键对应相同符号。最后求解相关谓词，统一实例化共享符号，再插入真实数据。见 §2、§3.2.2–3.2.3、§4。

对我们有用的是“分析输入特征、区分成功与失败约束、共享绑定一致取值”。其参数化关系代数计划不是目标数据库实际执行计划，也不是我们当前的向内需求推导算法；原文对去嵌套、重复读取及可用算子都有范围限制。

### 2.2 RQP：从指定结果反向构造输入

RQP 给定查询 Q、结果 R 和模式约束，寻找 D 使 Q(D)=R。它先自底向上标注类型、完整性和依赖，再自顶向下使用反向算子生成数据。反向投影和聚合建立属性及行数约束，通过模型检查器求实例。见 §2.2、§4.1–4.2。

§3.2 的逻辑反向选择允许补充被谓词排除的元组；但 §4.3 的 SPQR 最小数据库实现可采用恒等选择，并未据此实现大规模负例扩张。同表多次读取时还限制额外加行。这支持整查询读取检查的必要性，不提供图路径扩张的现成实现。

### 2.3 Qex：把查询与测试条件编码成模型生成问题

Qex 用保留重复记录的列表表示表，以递归公理描述查询求值。它将结果目标和模式条件交给 Z3，在系统增加的表大小范围中求模型，再提取具体表和参数。§5.1 是表生成流程；第11页有断言、求模型、读值的 API 片段；Example 4 使用聚合计数条件。

它的 NULL、关联查询及连接支持有明确限制，也没有“小实例成立后将失败区放大到 N”的阶段。我们当前的有限需求枚举、图族和参数化增长不属于它的现成算法。

## 3. 方法对象：先把输入和输出说清楚

### 3.1 输入

- S*：已经包含外层 COUNT、EXISTS、WITH 或条件分支的完整递归源骨架及锚点接口。
- μ：带明确位置标记的局部变异律，含其类型、绑定、语义前提及需要的替换候选接口。P3 不需要额外替换体；短路律可能需要。
- O：语义目标，例如完整输出至少一行、某表达式为 FALSE、某绑定非 NULL。
- W、N：潜在工作种类及预算，例如所标记读取中需要 N 个额外失败路径候选。
- B：语法、值域、逻辑分支和模型搜索预算。

完整上下文必须在算法1之前进入 S*。否则算法1不知道外层 COUNT 的阈值，无法据此决定有效匹配数。论文原算法2中的 Embed 不能仍是第一次加入该上下文的时刻。

### 3.2 输出

算法1返回 (G_N, σ, K)：

- G_N：实际规模的共同图状态描述，可采用压缩节点／边组；尚不等于已经装载的数据库。
- σ：本次接受的查询符号及孔位赋值。
- K：接受记录，包含标记、源／副本绑定对应、需求和数量解、构造依据、小规模解释实例及必需检查。

图属性及数量解与查询符号赋值有不同作用。查询阈值4不能被求图过程改成另一个数；匹配数5则是为满足该阈值求出的状态参数。

算法2消费同一个 (G_N, σ, K)，返回查询对及运行前必需检查。物理装载、编译后的实库结果核对、计时和诊断保留在既有执行流程中。

### 3.3 接受目标

在支持语言和构造族中寻找满足以下要求的实例：

1. 查询类型、作用域及局部变异前提成立。
2. 语义目标 O 成立于真实绑定和行域。
3. 原查询与变异查询的完整类型化结果多重集相同。
4. 由所选构造规则定义的潜在工作量达到预算。
5. 规模相关图组对所有有关读取和观察满足保护条件。

第4项不是优化器成本估计，也不保证数据库实际执行 N 次操作。性能差异由后续测量判断。搜索失败只表示本次预算内未接受模型，不是一般不可满足性证明。

## 4. 算法1：需求驱动的共同图状态构造

输入：S*、μ、O、W、N、B。输出：(G_N, σ, K) 或 Reject。

```text
 1  σ ← SampleAssignment(S*, μ)                    // 源与替换候选共用一次赋值
 2  A ← Substitute(S*, σ)
 3  if not WellTypedAndScoped(A, μ.mark): return Reject
 4  (A′, ρ) ← PreviewMarkedRewrite(A, μ, σ)
 5  D ← AnalyzeDefinitionsAndUses(A, A′, ρ)
 6  F ← SelectSupportedOperatorRealizer(A, A′)
 7  for C in BoundedDemandPlans(D, O, W, N, B):
 8      (Ĝ, G_N, θ, E) ← SolveAndRealize(F, C, N, B)
 9      if construction failed: continue
10      if not ProtectedReadClosure(A, A′, F, θ, E): continue
11      if not CheckProofInstance(A, A′, Ĝ, C, E): continue
12      if SmallEnough(G_N) and not CheckFullInstance(A, A′, G_N, C): continue
13      K ← Record(S*, μ, σ, G_N, ρ, C, θ, F, Ĝ, E, mandatory checks)
14      return (G_N, σ, K)
15  return Reject
```

这些名字是论文概括，不代表代码已有同名通用证明器。它们至少需要在正文展开为下面三组规则。

### 4.1 需求下降不是一个不解释的黑箱

| 算子／观察 | 向内传递的要求 |
|---|---|
| 要求 COUNT(B)>k 为 TRUE | B 的输出行数至少 k+1；一般比较形成区间及其交集 |
| WITH 别名 | 沿实际定义—使用关系回到生产者；同名遮蔽不能按名字合并 |
| 要求 EXISTS(B) 为 TRUE／FALSE | B 至少一行／零行 |
| 必选匹配 | 一个输入的输出数为其实际匹配数 m |
| OPTIONAL | 一个非 NULL 输入产生 max(1,m) 行；m=0 时新增绑定为 NULL |
| ALL=TRUE／FALSE／NULL | 全 TRUE／至少一个 FALSE／无 FALSE 且至少一个 NULL |
| length(p) 比较 | 与 p 的语法长度范围相交；当前选择一个统一长度见证 |
| 标记位于条件分支 | 同时约束守卫，使该分支成为本次需要观察的位置 |

COUNT 的值不等于包含它的查询行数。例如 RETURN COUNT{B} 产生一个标量投影行；再在外层计数应得到1，而不是把 B 的匹配数再次当作行数。

### 4.2 SolveAndRealize 的实际含义

当前首先对真假选择和匹配数量作有界分配，再由构图后端搜索有限属性值和一致的绑定域。

- 固定匹配使用共同绑定图构造器，不按 pattern 名称选择一张图。
- 有界路径先降低为端点关系原子，复用前者求数量和属性，再提升为所选长度的唯一树路径。
- Ĝ 是另一份小规模解释实例。与规模相关的工作组按证明规模解释，包括失败候选或被屏蔽的有效匹配；其语义见证、绑定及结果必须保持可核查。小实例的数量按证明规模检查，不能要求它已经具有完整 N 个工作候选。
- G_N 直接按参数化节点／边组实现；不要求先将 Ĝ 逐节点扩成大图，也不要求 Ĝ 是 G_N 的字面子图。

这是有限规则及模型搜索，没有将全部 Cypher 语义编码进 SMT，也没有完整联合回溯所有语法、模式和拓扑。

### 4.3 ProtectedReadClosure 的最小内容

对每个随规模变化的节点／关系组，在源树及变异树中检查每个可能读取它的位置：必须有不相容的标签／属性／关系约束将它排除，或者有已建立的局部筛选／语义屏蔽保护。不能认证的读取拒绝。

路径提升还要求：新内点标签避开完整 AST 的标签读取；额外固定关系不能使用该路径的关系类型形成捷径；树结构及关系不复用排除路径绕行和后缀重组；普通属性在整个构造组保持所需真假。依赖 UID 的 ALL、OPTIONAL 路径、多物理路径联合等目前没有相应构造依据，应拒绝。

CheckProofInstance 检查原始 AST 的实际绑定／标量／数量／长度事实及完整结果多重集。规模允许时再对全图解释；更大规模依赖受限构造规则和组级读取检查，并在算法2中保留实际装载检查。有限测试不替代这些构造规则的可靠性论证。

## 5. 算法2：复用接受方案的实例化与局部变异

输入：S*、μ、(G_N, σ, K)。输出：(Q1, Q2, T) 或 Reject。

```text
 1  if accepted S*, σ, G_N or mark has changed: return Reject
 2  Q1 ← Substitute(S*, σ)
 3  site ← LocateAcceptedMark(Q1, K)
 4  Q2 ← ApplyMarkedLaw(Copy(Q1), μ, site)
 5  if Q1 = Q2 or not WellTypedAndScoped(Q1, Q2): return Reject
 6  if not LocalLawAndContextConditionsHold(Q1, Q2, K): return Reject
 7  T ← InstantiateMandatoryFacts(G_N, K)
 8  if not CheckAcceptedProofResults(Q1, Q2, K): return Reject
 9  if SmallEnough(G_N) and not CheckFullResults(Q1, Q2, G_N, K): return Reject
10  return (Q1, Q2, T)
```

算法1中的 A、A′是求图时使用的候选分析树；算法2才根据同一接受赋值形成最终查询对。这里不存在构图后重新挑阈值、数量或变量的自由选择。两阶段预览和最终变异复用同一个局部律及标记；不能分别独立随机选变异。

局部律及其上下文条件说明为什么应保持等价，解释器和数据库核对检查具体实例是否实现正确。本文草案没有把接受记录写成一个适用于任意 Cypher 的形式化证明系统。

返回之后继续既有流程：编译 → 装载 G_N → 执行 T → 核对完整类型化结果 → 性能筛选与诊断。算法2不会重新构图。

## 6. P3 完整推导：COUNT、长度、ALL 与失败工作目标

### 6.1 从真实案例开始

采用已存档的[独立 AST 案例](../results/path-goals-validation-20261022/examples/native-count-length/query_a.cypher)。该完整 AST 经 prepare_case 和两算法处理；不是声称公共随机语法已经能生成任意长度过滤。

```cypher
MATCH (u:PathInput {id: 1})
WITH u, COUNT {
  MATCH p = (u:PathInput {id: 1})-[:PATH_LINK*1..4]-(v:PathOutput)
  WHERE all(x IN nodes(p) WHERE x.keep = true)
    AND length(p) = 2
  RETURN 1 AS c
} AS n
WHERE n > 4
RETURN u.uid, n
```

人为指定：局部变异律是 P3 无向路径两端反转；外层阈值为4、路径过滤长度为2；需要一个非空输出；失败候选预算 N=7；语法和构图范围有限。不是系统从零发现了测试目的。

### 6.2 AST 依赖与需求下降

依赖链为：最终过滤使用 n → n 由该 COUNT 产生 → COUNT 读取内层行流 → 内层行流由指定路径和两个过滤条件产生。

- u 从外层必选匹配导入；内层不能另造一个同名但不同来源的锚点。
- v、p 为内层绑定；ALL 的 x 是逐节点量词变量。
- 反转副本中的 u、v 与源树保持相同物理来源，位置交换不代表身份交换。

要让外层保留一行，n>4 必须为 TRUE。设 m 为过滤后的实际路径数，则 n=m，得到 m≥5。长度满足 1≤ℓ≤4 且 ℓ=2，故 ℓ=2。每条有效路径的 ALL 必须为 TRUE，因此起点、内点、终点三个节点均满足 keep=true。

外层返回一行 `(u.uid, n)`；这不等于仅需一条内部路径。当前分配搜索选择本例较小可行数 m=5，不声称全局最小图优化。

### 6.3 工作目标与共同求解

当前工作目标要求所标记读取有7条额外失败候选。它从实际正合取 ALL 保护中选择路径工作轴。于是原始候选路径数为 m+N=12，过滤后为5；工作轴的输入重复系数在此为1。

先在端点原子层求得：一个真实输入 u，5个成功端点，其谓词为 TRUE；7个失败端点，其谓词为 FALSE。根及普通内点选择共同 TRUE 赋值。这使端点上的局部谓词能够代表整条成功／未插入失败前缀路径的 ALL。

这一降低依赖当前构造族，不是 ALL 的一般等价变换。例如根固定 FALSE 而目标也为 FALSE，可能存在合法图，但不满足共同 TRUE 根的族时仍会被当前实现拒绝。

### 6.4 从端点原子提升成真实图

成功部分为5条独立的二跳树路径；失败部分让7条二跳路径共享第一个 FALSE 内点。实际失败端点也保持 FALSE：

```text
成功：u(T) -- a_i(T) -- v_i(T)    i=1..5，各自独立的内点和端点

失败：u(T) -- b(F) -- f_j(F)      j=1..7，共用一个 b，各自独立的端点
```

T/F 表示该节点对当前谓词的实际真假，不依赖名字。合计：一个根＋5个成功内点＋5个成功端点＋一个失败内点＋7个失败端点＝19节点；成功边10条、失败边8条，共18条边。

失败深度1是当前策略；不是根据任意代价模型求出的最优位置。当前把失败端点也保留为 FALSE，而不是声称只有一个节点失败。

### 6.5 为什么扩张没有改变这个例子的结果

1. 根与端点标签分离，内点使用查询未读取的新鲜标签。
2. 每个端点与根之间只有一条树路径；关系不复用，不会组合出绕过 b 的成功路径。
3. 五条成功路径均为二跳且所有节点 TRUE。
4. 七条新增路径均经过 b，ALL 为 FALSE；故不进入有效计数。
5. 此查询其他位置只读固定根和内层 COUNT，没有未保护的第二读取。

因此本例实际有效计数为5，原始路径数为12，输出为一行 `{u.uid: 1, n: 5}`。如果加入另一个不带 ALL 的路径计数，或会读取新增端点的扫描，不能直接沿用这项结论；当前对无法认证的此类读取拒绝。

这一步与 RQP 负例元组的逻辑有联系，但树路径唯一性、共享 FALSE 前缀及跨读取检查是我们自己的图上构造条件。

### 6.6 算法2生成的变异

只把已标记路径改为：

```cypher
MATCH p = (v:PathOutput)-[:PATH_LINK*1..4]-(u:PathInput {id: 1})
```

外层 WITH、COUNT、阈值、ALL、长度条件和输出保持不变。仍使用同一个19节点图。

对每条无向路径取逆序，得到一一对应的路径；两端变量仍指原来的节点，长度不变；节点局部 ALL 的三值合取对逆序不变。因此本例过滤后的5条路径及外层结果相同。这是 P3 局部律的理由，不是从“小图跑相等”推导出来的。

### 6.7 接受事实与现有证据

必需检查保留实际过滤后匹配数、未过滤候选数、路径长度及 ALL 事实。本例小规模解释实例只需较小失败组；完整图的检查仍使用12个候选要求，不能把小图候选数当成完整 N。

存档[结果记录](../results/path-goals-validation-20261022/examples/native-count-length/result.json)中，算法1/2使用同一赋值摘要和图摘要，完整结果为一行 `n=5`。这是以前冻结验收的实库案例证据，本轮仅独立读回核对，没有重新运行或增加新实验结果。既有[验证汇总](../results/path-goals-validation-20261022/summary.json)不替代上面的语义论证。

| 查询目标约束测试数据 | RQP、QAGen、Qex 有直接先例 | 已在支持范围内实现；不是三者代码复现 |
| 成功满足谓词、失败不满足谓词 | QAGen 正／负符号元组；RQP 逻辑反向选择 | 已用于当前图候选及过滤检查 |
| 外层 COUNT、别名、真假向内传播 | RQP 的反向算子思想相关；Qex 用完整目标公式 | 我们自行写的算子规则，已有实现；不等同 QAGen 的人工 knobs |
| 源与变异副本共同约束同一图 | 三篇不是本项目的变异查询对算法 | 我们的设计；已有显式来源对应和共同状态 |
| 路径降低、共同求图、树提升 | 不属于三篇的现成图算法 | 我们的设计；已实现受限单路径族 |
| ALL 三值、长度及逐输入路径数 | 查询语义需要独立定义 | 已有相应传播和实际事实检查，支持范围有限 |
| 固定 FALSE 内点和安全候选放大 | 与 RQP 逻辑负例存在联系 | 具体共享树族属于我们；不能说 SPQR 已实现 |
| 全查询读取范围保护 | RQP 重复读表限制说明必要性 | 当前采用保守组级读取及原始路径检查，不是任意公式证明器 |
| 任意 Cypher SMT 编码和求模型 | Qex 对有限 SQL 有相应方法 | 未实现；当前不使用 Qex/Z3 编码 |
| 多路径、环、混合长度、OPTIONAL 路径、UID 型 ALL | 不能由关系型论文直接推出 | 没有一般构造规则；当前相关情形拒绝 |
| 一般前缀代价约束与最佳失败位置 | 本轮文献未提供我们的图上现成算法 | 未实现，当前失败深度固定1 |
| 所有语法／模式／拓扑联合回溯 | 不能借有界求解名义宣称 | 未实现；先采样一个查询赋值，再搜索状态 |
| 全部23个 pattern 统一目标分配 | 不是这三篇能替我们证明的覆盖 | 当前11个 ID 已迁移，12个及 legacy 路线仍另行处理 |

11个已迁移 ID 为 P3、P4、P5、P10、P11、P13、S1、S2、S3、S4、S7。构造器中仍有算子语义和有限策略的人工实现，这本身合理；应避免的是将按 pattern 写死的数量配方冒充查询约束推导。

## 8. 与当前代码的对应及论文写法

| 论文步骤 | 当前可核源码 |
|---|---|
| 算法1固定符号、预览副本、共同接受图 | [symbolic.py](../src/symbolic.py)，construct_state |
| 完整 AST 的绑定、来源及局部律消费者 | [dependencies.py](../src/dependencies.py) |
| 需求下降、有限真假及数量计划 | [requirements.py](../src/requirements.py)，derive_requirement_plans |
| 绑定图求值域及数量、原始观察与增长检查 | [relational_population.py](../src/relational_population.py) |
| 路径原子降低与树路径提升 | [path_population.py](../src/path_population.py) |
| 算法2消费同一状态、赋值与标记 | [symbolic.py](../src/symbolic.py)，instantiate_pair |

建议方法章按“完整递归骨架与局部律 → AST 依赖和算子需求 → 有限图族及安全构造 → 接受状态的实例化与变异”组织。算子需求用一张规则表，图族适用条件用另一张表；不按 Python 文件顺序叙述，也不再让 Populate、Skew、Preserve 承担全部未解释内容。

可用总述草案：

> GraphSymPerf 在支持的递归查询语言中，将测试实例生成表述为受限的图状态构造问题。系统先解析完整符号骨架及其局部变异位置，根据变量来源和算子语义，把结果条件与潜在工作目标下降为绑定、值、数量和路径约束。随后在有限构造族中寻找并检查共同图状态，保留其符号赋值和必需事实。查询生成阶段复用该接受方案，仅在标记位置应用局部变异，并在执行前核对图状态与完整结果。

这段总述的方向有文献基础；具体传播规则、图族及其可靠性属于本项目，需要逐条论证。不能据此宣称任意 Cypher、任意嵌套或全部23个 pattern 已由同一个完备求解器处理。
