# 面向组合查询的生成与图状态构造

本文记录新的生成机制及迁移边界。它不替换 `docs/Approach.md`，也不将规划能力计作已实现能力。现有执行、结果比较、性能确认和后端支持门槛继续适用。唯一规范源为 [paper/vldb27-GraphSymPerf.pdf](../paper/vldb27-GraphSymPerf.pdf) 第 6 页表 1 及第 7–8 页算法 1/2。代码历史编号显式写作 `code:P*`；`docs/Approach.md` 不替代该 PDF。

新路径的公共目录为 `Src/paper_patterns.py`，统一阶段实现在 `Src/symbolic.py`。第12节记录全部23项及P10三种形式进入公共流程的冻结批次，第13节记录2026-10-21首轮语义目标重构，第14节记录2026-10-22递归行语法批次，第15节记录标量语法及一般值批次；各批测试与持久案例仅对应该批源码。P10全部形式与P11的当前匹配策略、逐输入数量及NULL扩展在第16节登记，更早五项记录保留于第11.6节。全目录配置为 [configs/symbolic-paper.yaml](../configs/symbolic-paper.yaml)，原 [configs/compositional-paper.yaml](../configs/compositional-paper.yaml) 保留为P3/P4/P10示例。连接可清空的独立Neo4j实例后，可在项目根目录运行：

```sh
.venv/bin/python Src/main.py --config configs/symbolic-paper.yaml
```

## 1. 当前机制与改造目标

现有查询中间表示（Intermediate Representation，IR）、类型与作用域验证、变换适用性检查和测量流程继续复用。旧路径按pattern编号直接安排拓扑，再从有限表达式候选池中选择与该拓扑相容的形式。此前P3/P4/P10原型先组合具体查询，再从查询需求求解状态；首批五项统一符号路线加入了S6/S8。全目录批次将同一S → 图状态 → 实例化查询对接口扩展到全部23项，新增带类型AST对象的数量意图、标量前提和逆边配对需求。该批仍由骨架指定部分逐边数量及增长位置；这与依据抽象语义和成本目标自动分配数量是不同能力。历史测试批次不合并计数。

目标依赖为：

```text
测试意图 + 目标语言能力 + 生成预算
    → 构造含上下文、类型占位符、符号和显式变换标记的骨架 S*
    → 记录类型、作用域、相关输入及外层语义/工作量目标
    → 算法 1 构造图状态，并固定共同赋值与验证记录
    → 算法 2 消费同一赋值、物化已接受的 Q1
    → 复制完整查询，在标记位置进行 L→H 或对称重写
    → 实际加载、结果检查、性能测量与计划解释
```

所谓“根据 pattern 构图”，应指根据真实 IR 中的运算语义和测试需求推导约束；pattern 编号只标识测试关系与来源。构图核心不得据编号选择 `GspBad`、固定节点数、固定跳数或某张预写拓扑。

## 2. 论文与代码编号映射

论文表 1 为 **13 个 P pattern + 10 个 S pattern**；旧代码目录为 **16 个 P 编号 + 10 个 S 编号**。新路径统一使用论文编号：`paper-v1` 为新目录，`legacy-v1` 只解释旧生成路径和历史存档。无前缀的 P11 始终表示论文的 OPTIONAL MATCH 分支交换。

| 论文编号 | 现有代码编号 | 机制及迁移说明 |
|---|---|---|
| P1 | P1 | 无向单边端点交换 |
| P2 | P2 | 一一配对的正向/逆向关系 |
| P3 | P3 | 有界无向路径端点交换；路径观察须对反转不变 |
| P4 | P4 | AND 操作数交换 |
| P5 | P5 | OR 操作数交换 |
| P6 | P6 的等号子集 | 论文列属性–常量等号交换；代码还含 `<>`、`<`、`<=`、`>`、`>=` 的操作数及比较符对偶，不能全部计入论文表述 |
| P7 | P7 | 同一节点的标签合取重排 |
| P8 | P8 | 关系类型选择项重排 |
| P9 | P9 | 必选匹配间的谓词附着位置调整 |
| P10 | P10、P11、P12 | 论文合并三个必选 MATCH 形式：互不相交绑定、共享锚点分支、两边链 |
| P11 | P13 | 两个独立 OPTIONAL MATCH 分支交换；保留空值扩展 |
| P12 | P14 | UNION ALL 分支交换；保留重复次数 |
| P13 | P15 | CASE 分支交换和空值安全的条件补集 |
| S1–S10 | S1–S10 | 历史编号相同，但结构必须逐项按 PDF 核对；旧 S6/S8 不自动成为含 Q0 UNION ALL 的新路线证据 |
| 不在论文 13P 中 | P16 | 列表全称量词的输入组交换；保留旧案例兼容性，单列为代码补充能力 |

因此，`16 - 2（三个编号合成一个）- 1（P16 未入表）= 13`。此计数表示模板/变换目录，不能等同于独立优化机制或独立缺陷根因数量。历史存档按原目录解码；新路径记录 `pattern_catalog`、`paper_pattern`、`legacy_pattern`、`pattern_form`。其中 `legacy_pattern` 只用于定位兼容规则，不能覆盖由 `paper-v1` 确定的对外语义。P10 的具体子形式须另外记录为共享锚点、互不相交绑定或两边链。

## 3. 组合生成：P3 基线与 P4/P10 扩展

### 3.1 已有实现

`Src/generator.py::_build_p3()` 的 `pruning_path` 分支直接创建成功见证、`keep=false` 入口及其后续分支。`Src/state.py` 中的对应配方按编号和状态变体重建同类图。它们证明旧案例可生成，不证明生成器会从任意 `all(...)` 推导图状态。

应保留的语义边界包括：

- `Src/ir.py::_node_local_predicate()` 对全称量词内层表达式的限制：只观察量词绑定节点的标量属性及受支持组合，不观察路径位置或随扩展变化的路径量。
- `Src/mutator.py` 对有界无向路径及反转不变观察的适用性检查。
- 原有历史案例、旧图配方与归档解码；是否走新路径必须显式记录，不能把自动生成失败后悄悄返回旧配方的结果标成自动构图。

### 3.2 当前接入记录

当前组合生成路径为：

```text
main.prepare_case(..., composition=...)
  → generator.instantiate(..., composition=...)
  → paper_patterns.compositional_rule(): 按论文目录选局部规则与形式
  → symbolic.build_symbolic_skeleton(): 选择符号结构种子并组合上下文
  → symbolic.construct_state(): 选择共同赋值，解析依赖并求解图状态
  → symbolic.instantiate_pair(): 复核同一解，实例化并局部变异、传播关系
  → main.prepare_case(): 保留该查询对，进入编译与完整结果核查
  → 既有编译、执行与归档流程
```

`generation.composition`使用`paper-v1`的P1–P13、S1–S10，不与旧`empty_low`、`multi_low`、`pruning_path`配方混用。指定composition而未写`pattern_catalog`时，目录默认设为`paper-v1`；没有composition的旧配置默认按`legacy-v1`解释。显式组合`legacy-v1`与composition会被拒绝。`paper-v1`要求composition，不能只换目录名就调用旧构图器。下表限定为P3/P4/P10共享锚点原型的能力；新增规则见第12节，不据此沿用其单锚点边界。

| 当前源码能力 | 边界 |
|---|---|
| `composition.py` 按当前结果种类组合 `exists`、`count`、`with` | 这是三类运算的递归上下文组合，不是任意 Cypher 语法的递归生成器；外部配置顺序为从内到外 |
| `dependencies.py` 记录作用域、符号定义/引用及结构地址 | 词法位置通过地址和符号身份区分，不以相同文本或相同 AST 值充当同一绑定 |
| `population.py` 接收实际查询及结果/规模需求 | P3 路径分支限制为一个绑定锚点、一个由正向必选 ALL 条件保护的有界路径组件；无有界路径时，另一分支解析 1–3 个共享同一词法锚点的有向一跳组件 |
| 搜索节点局部谓词的真/假属性赋值 | 布尔域以及整数比较的常量/相邻边界有限域；一跳组件按词法绑定提取属性域，不支持任意数值函数、字符串或完整 NULL 属性合成 |
| 搜索有效路径数量、路径长度、失败深度及共享/独立失败前缀 | 此行专属 P3；一跳构造族搜索各组件的有效匹配数、属性赋值和可扩张组件，不使用 ALL 前缀 |
| 一跳组件的联合数量与真假搜索 | 端点局部过滤、全新端点、共同词法锚点及隔离读取域；最多 3 个组件、有效见证总数不超过 64，额外候选只加入一个具显式假赋值的组件 |
| 外层 `COUNT > 2` 等需求影响内部有效匹配数量 | 有界路径及一跳组件均使用 COUNT 消费需求；见证数量的有限搜索域上限为 64，超过当前预算显式拒绝 |
| 完整查询的小图解释与扩图不变量 | 小图规模探测用于找错，不能单独代替结构性证明；不支持额外不受保护的路径读取 |
| 输出 `GraphSpec` v2、预期结果、状态检查和生成证据 | 旧 v1 配方继续兼容；新图标识为 `AST`，来源为显式节点/关系组，不由 pattern 编号重新猜图 |
| 在选定嵌套位置应用局部规则，并记录外层关系传播 | 本表原型覆盖P3端点镜像、P4 AND操作数重排、P10共享锚点必选分支交换；P11 OPTIONAL属于第12节新增路线 |

表中路径和一跳过滤构造族描述 P3/P4/P10 的底层能力。S6/S8 另经 `synthesize_symbolic_state` 求解共同锚点、Q0 见证及 L/H 区域，复用谓词求值、依赖分析、显式图规格和完整结果解释；具体边界见第 11 节。

公开配置入口的路径界限为 `1 <= min <= max <= 6`；构图还需要至少两跳空间容纳失败后的候选区域。`depth` 取 0–8，可由种子选择上下文；它与显式 `contexts` 二选一。旧 `complexity` 必须为 0。`threshold` 是非负整数，其可满足性还取决于实际嵌套语义和有限搜索预算。默认最多尝试 50,000 个模型；预算耗尽只表示未知，不表示全局不可满足。

构造期的具体解释限制为 5,000 个节点；大图保留为参数化组，在保存的 `validation_graph_spec` 上核查变异，并使用读取闭包及路径/一跳组件的结构证书支持扩张。实际执行仍会检查完整图上的事实与完整答案。较大图的建边阶段临时使用 UID 索引，加载结束后移除并恢复声明的访问索引，不将这些辅助索引带入计时。

当前检查产物包括 `dependency_analysis`、`population_constraints`、`population_evidence`、`mutation_record`、图规格，以及第 11 节的三份符号阶段记录。`COUNT` 消费子查询的行数，不能把内部返回的标量数值误当作行数。例如，内层子查询只返回一行 `COUNT(...) AS n`，再外包一层 COUNT，观察到的是一行而非 n 行。

对应离线覆盖位于 `tests/test_composition.py`、`tests/test_dependencies.py`、`tests/test_population.py`、`tests/test_composed_generation.py`、`tests/test_composed_paper_patterns.py` 和 `tests/test_paper_catalog.py`；真实数据库测试位于 `tests/test_composed_neo4j.py`、`tests/test_composed_paper_neo4j.py`。新路径目前仅向 Neo4j 开放，包括没有额外包裹的 v2 状态；其他后端没有由语法相似性自动获得支持。编译或本地解释通过不能替代数据库证据。

### 3.3 新路径入口与 P3 阈值示例

三规则入口使用文件 `configs/compositional-paper.yaml`：`patterns: [P3, P4, P10]`，`contexts: [count, with]`，`threshold: 0`。路径界限属于 P3，不能在该三规则公共配置中显式填写 `path_bounds`；P4/P10 接口会拒绝这一无效参数。

以下 P3 专用阈值示例用于可清空的独立 Neo4j 测试实例。程序会重建图；`dedicated` 和 `allow_reset` 的含义必须与实际实例一致。将 YAML 保存为项目根目录下的 `config.composition-p3.yaml`，连接地址和凭据环境变量按独立实例填写：

```yaml
pattern_catalog: paper-v1
database:
  dbms: neo4j
  language: cypher
  uri: bolt://127.0.0.1:7687       # 替换为独立测试实例的地址
  user: neo4j
  password_env: GRAPHSYMPERF_NEO4J_PASSWORD
  database: neo4j
  dedicated: true
  allow_reset: true

patterns: [P3]
scales: [10, 100]
seeds: [0]
cases_per_pattern: 2
seconds_per_pattern: 60
schedule_seed: 0

generation:
  log_files: []
  data_seed: 0
  complexity: 0
  state_variant: original
  composition:
    contexts: [count, with]       # 从内到外：先 COUNT 路径结果，再 WITH 绑定和过滤
    threshold: 2                 # 过滤条件为当前 COUNT 值 > 2
    path_bounds: [1, 3]

measurement:
  timeout_seconds: 10
  collect_plans: true
output: results/composition-p3
```

使用已安装项目依赖的 Python 环境，在项目根目录执行；当前工作区的虚拟环境命令为：

```sh
.venv/bin/python Src/main.py --config config.composition-p3.yaml
```

该配置已通过 `read_config` 和 scale 10、100 的纯生成检查：均无编译错误，`valid_paths=3`，预期结果为 `[{"u.uid": 1, "gsp_value_0": 3}]`。此检查未连接数据库。

`[count, with]` 配合阈值 2，会要求 COUNT 所消费的内部查询至少产生 3 行；当前最小满足模型选择 3 条有效路径，并额外生成随 `scale` 变化的失败候选。若改为 `[count, count, with]`，第二个 COUNT 观察的是中间查询行数，不能仍按“有效路径数大于 2”解释。应查看保存的具体查询和 `population_constraints`，不能只根据上下文名称推测含义。

### 3.4 P3 独立验收用例

| 验收问题 | 应观察的行为 |
|---|---|
| 将 `keep=true` 改成受支持的 `disabled=false` | 失败赋值随真实谓词改变；不得机械写入 `false` |
| 改成受支持的整数比较 | 根据真假要求求值或报告不支持，不继续使用旧属性配方 |
| 改变长度上下界、失败深度需求 | 重新选择合法结构；明确区分不支持、有限域未找到模型与已证明冲突 |
| 改变失败候选数 | 结果见证保持，逻辑候选规模按约束增长 |
| 检查候选间实体共享 | 搜索证据中包含真实共享/独立候选及前缀预算淘汰原因；不虚构当前尚无的公共开关 |
| 将全称谓词改成恒真，却要求存在失败路径 | 明确不可满足 |
| 删除“保留非空结果”的需求 | 可以出现不同解；不能仍强制保留原三节点见证 |
| 检查代码中对 pattern 编号的分支 | 局部符号骨架允许由目录选择；population 不按编号选整张拓扑或属性配方 |

有限小图测试可以找错，但不能独自证明任意规模下的扩图保持性。若输出参数化图组，应另外检查复制内部实体分离、共享接口受限、无绕行连接、标签/类型匹配域不泄漏等不变量。

### 3.5 与 P3 基线对应的受限算法

以下两个版本保存查询先行 P3 原型的历史机制，区别于第 4、5 节的论文阶段合同。运算组合、图搜索和局部变异分别对应当时的 `compose_query`、`synthesize_state`、`mutate`；当前公共调用顺序见第 3.2、11.1 节。P3 的路径求解与变异规则继续作为统一符号阶段的底层组件复用。

```text
算法 1-P3：递归实例化和 AST 驱动的受限图合成
输入：局部查询种子 K，锚点绑定 a，上下文运算序列 C，阈值 τ，规模 N，数据种子 kG
输出：Q1、依赖摘要 D、参数化图 GN、检查 I、预期多重集 E、位置 s、扩张证书 π

1  Q1 ← 按输入/输出类型递归组合 K 与 C；应用 τ 对计数的消费要求
2  D ← 解析 Q1 的词法定义、使用、相关输入和 WITH 导出
3  定位唯一受正向节点局部 ALL 保护的有界路径位置 s
4  利用 D 检查路径起点固定；检查其他读图位置不观察扩张区域
5  从真实谓词常量生成有限属性域，从计数消费生成见证数量域
6  枚举赋值、有效匹配数、合法长度、失败深度和共享/独立前缀
7      若逻辑前缀工作超过预算则继续
8      构造小树模型 G*；独立解释完整 Q1，检查目标结果重数和类型
9      核查新路径必经稳定假前缀、复制分离及全部图读取闭包
10     GN ← 将获证的失败路径族参数化复制 N 次；有效见证保持
11     I ← 由 GN 生成数据事实、身份唯一性和声明索引检查
12     返回 Q1、D、GN、I、E、s、π；将 G* 存入 π.validation_graph_spec
13  有限域/预算未找到模型时退出，不能据此宣称一般不可满足
```

```text
算法 2-P3：局部镜像和依赖关系传播
输入：Q1、D、GN、E、π，以及已核查的 AST 地址 s
输出：Q2 和变换/传播记录 μ

1  在实际 Q1 中重新检查 s 的适用性和路径消费者
2  建立每个相同相关输入下的路径反转双射
3  Q2 ← 仅交换 s 的两个端点，保留变量身份、条件和外层结构
4  沿实际祖先与 WITH 定义/使用逐层传播关系：
       不变路径观察 → 查询输出 bag 相等 → COUNT/EXISTS 值相等
       → 别名值相等 → 过滤及投影的输出 bag 相等
5  若消费者不受支持或无法建立根关系，则拒绝变异
6  在 G* 上独立核验 Q1、Q2 与 E；小规模 GN 另做完整解释核验
7  返回 Q2、μ；实际数据库加载后仍检查完整图事实和完整结果
```

π 对应案例的 `population_evidence`，位置 s 保存在 `bindings.mutation_site`。第 6 步的小图解释是实现校验，不取代第 2–4 步的关系论证，也不单独证明 π。代码保留原执行、结果比较、计时与独立确认流程。

P4 的标量投影与旧 `WHERE C AND EXISTS H` 不同：投影布尔值会保留这一行，WHERE 为假则删除这一行。因此，此次单锚点构造不需要再添加“成功锚点”。若外层 COUNT 消费的是这一行布尔投影，得到的是 1，而不是布尔值；不能为了满足 `COUNT > 2` 擅自增加行数。

P10 的一跳组件与 P3 的路径组件分别具有自己的扩张条件。复用的是绑定解析、谓词赋值、多重集解释、上下文组合、状态导出和变异关系传播，不要求所有规则都包含 ALL 或一个失败前缀。

已经定位的公共 API 为 `dependencies.find_mutation_sites(query, paper_pattern, form)`、`dependencies.propagate_equivalence(query, site)`、`population.synthesize_state(query, ...)`。`synthesize_state` 不接收 pattern 编号：它从实际 AST 判断是否含有有界路径；无有界路径时解析固定锚点的一跳组件。P4 与 P10 没有各自的独立造图函数。

种子 0、scale 10、公共 `COUNT → WITH` 阈值 0 的纯生成结果为：P4 选择 `u.enabled=false`，H 有 0 个有效匹配和 10 个失败候选；P10 选择两个分支各 1 个有效匹配，其中一个分支另有 10 个失败候选。二者外层预期结果均为 `[{"u.uid":1,"gsp_value_0":1}]`。去掉 P4 包裹后，返回的是 `[{"u.uid":1,"predicate":false}]`。这些是当前源码的纯生成观察，不是运行时间结论。

## 4. 论文算法 1：从符号骨架构造图状态

本节对应唯一规范源 `paper/vldb27-GraphSymPerf.pdf` 第 7 页算法 1。骨架 S 是带类型占位符、符号绑定、变换标记及成本角色的参数化结构，不是已经绑定具体数据对象的 Q1。此前 P3/P4/P10 的查询先行原型作为历史记录，不作为论文算法 1 的执行顺序。

### 4.1 骨架携带什么

骨架固定运算结构和变换规律，保留尚未求解的内容：标签、关系类型、属性键、谓词、子查询和数值参数。占位符记录语法类别、类型、变量依赖与所属成本角色；符号标识绑定身份，变换标记定位待替换或重写的位置。外层上下文先提供类型、列结构和相关输入接口，不提前绑定最终查询中的全部对象。

S6 的结构必须包含 `(Q0 UNION ALL QL) LIMIT n`，替换项为 QH；S8 必须包含 `EXISTS {Q0 UNION ALL QL}`。Q0 的见证要求属于 S 的语义义务。它不是在完成构图后为了让测试通过再补入的一条查询。

### 4.2 与实现对应的算法合同

```text
算法 1：Graph state generation
输入：符号骨架 S、论文规则 p、规模 s，以及相关输入/输出需求
输出：已确定状态 G、共同赋值 β、构造验证记录 C；不满足时拒绝

1  Init(S)：为符号角色确定相容的锚点、模式连接和候选 schema 绑定
2  Populate(L)：为低成本角色生成小或选择性区域
3  Populate(H,s)：为高成本角色生成可扩张候选区域
4  若 p 为 SC：
5      SetGuards：联合求解各相关锚点的决定性真假或非空条件
6      AddWitnesses：建立 Q0 的必需见证；S6 每个锚点至少 n 行，S8 至少一行
7  否则：
8      Skew：调整标签频率、邻接度或分支匹配重数
9      Preserve：保持逆边一一对应、分支独立性等语义约束
10 AddIndexes：建立所需选择性访问条件
11 Validate：检查完整候选状态、各相关输入及上下文需求是否满足 S 和 p
12 若失败，继续有限候选搜索或明确拒绝
13 返回 G 与同一个解中的 β、C；算法 2 不另选一套不相容绑定
```

`β` 与 `C` 是实现用于固定和复核论文 G 中已记录 schema、属性与数量的附加记录。构造器可以在候选模型上临时解释查询结构来核查语义，但不能先把所有占位符固化成最终 Q1，再将既有图配方包装成此算法。

S6 的 Q0 有效匹配数随 n 变化。S8 的 Q0 只要求存在见证；两个分支的输出列仍需相容。两者的高成本区域都不能破坏 Q0 的关键事实。若外层需求要求 S6 的 n 行限额结果产生超过 n 行，或要求确定为 true 的 S8 标量取 false，构造器必须报告冲突。

### 4.3 约束方向与验证边界

变量和属性之间可以有联合约束，但执行阶段顺序固定为：符号化 S → 图状态及共同赋值 → 具体查询对。算法 2 只能消费算法 1 返回的解；若改变了符号接口、见证限额或上下文要求，需要重新构造并验证状态。

应分别记录：支持范围外的语义、已经证明的约束矛盾、有限搜索未找到解，以及搜索预算耗尽。有限域搜索失败不构成一般不可满足证明。

本地模型验证说明所求图规格满足要求；装载检查说明数据库中的实际图具有要求的事实。数量、属性、关系对应和索引检查从同一图规格导出，装载后执行。只有实际图的检查及完整查询结果核查通过，案例才进入性能测量。

## 5. 论文算法 2：嵌入、实例化和局部变异

本节对应 PDF 第 8 页算法 2。算法 1 已给出图状态与共同绑定；算法 2 在兼容上下文中填充骨架，复制完整查询后只修改标记位置。SC 按论文方向由 L 替换为 H；SY 执行原规则的对称重写。

实现将上下文的符号放置提前到构图输入中，得到包含外层消费者的`S*`。算法1内部可解析候选AST并计划其局部替换，以共同约束图状态；算法2消费接受的赋值，物化查询并认证最终变异。它不是第一次选择语法/schema候选。若上下文直到算法2才出现，算法1就无法依据其COUNT阈值或读取范围构图，因此两阶段间必须传递同一个上下文及观察合同。

```text
算法 2：Query generation and mutation
输入：S、论文规则 p、算法 1 的 G/β/C，以及可选上下文 Ctx[·]
输出：完整查询对 Q1、Q2 和实例化/变换记录；不满足时拒绝

1  Embed：复制 S 放入 Ctx 的合法位置，重命名局部符号并保留允许的相关输入
2  Instantiate：按 β 和 G 填充类型占位符；先绑定变量，再实例化其使用者
3  Applicable：对每个相关外层绑定，检查规则及完整源查询的前提
4  Q2 ← Copy(Q1)，上下文保持相同
5  若 p 为 SC，只在标记位置把 EL/QL 换成 EH/QH
6  若 p 为 SY，只在标记位置执行相应方向/附着/顺序重写
7  沿实际消费者检查局部关系，保留输出值、列结构、NULL、重复次数及必需顺序
8  检查完整类型、作用域、只读性、确定性及无求值错误
9  拒绝无变化或无法建立完整结果关系的查询对
10 返回 Q1、Q2 及记录；G 不变
```

S6/S8 的标记只涵盖 QL；Q0、UNION ALL、限额或 EXISTS 及外层上下文保持不变。S6 的 LIMIT 是作用于整个 UNION ALL 的全局限额，不能分发进某个分支。S8 返回布尔存在性，不能把它转换为两个分支行数相乘。

### 5.1 消费者需要什么关系

可观察接口至少区分：标量值相等、三值布尔结果相等、匹配绑定多重集相等、路径反转映射，以及受固定需求屏蔽的中间差异。SC 的 QL/QH 允许有不同中间结果；需要相等的是保留其短路结构之后的局部输出。

COUNT 消费子查询行数，标量 false 仍可占一行；EXISTS 消费是否至少一行；WITH 会重新导出绑定并施加过滤。分支输出相同的列类型不足以证明整个上下文合法。P12 禁止顺序敏感外层消费者，P11 要保持可选分支的 NULL 扩展，S3 只允许目标语言支持的查询级 WHEN 结构。

论文的保证针对构造出的 Q1/Q2，不是插入 pattern 前的外部原始查询。外部上下文在两个副本间不变，而局部符号的允许相关绑定和所有可见观察均需重新检查。

### 5.2 当前实现登记

第12.7节冻结批次中的全部23项及P10三形式统一调用符号阶段API，并通过该批的离线及选定Neo4j回归。P3/P4/P10共享锚点复用原型的路径及一跳求解器，S6/S8保留联合见证，其他规则通过第12节的数量、值和结构需求接入。P10链与S3的首轮目标路径见第13节，后续共享递归语法和需求搜索见第14节；第3、10、11节的既有运行数字不计作新批次的验证结果。

## 7. 防止“人工配图搬成配置”的验收准则

- 构图核心不能读取 pattern 编号决定图形；标签和关系名不能承担隐含语义，例如见到 `Bad` 就自动填 false。
- 更换受支持的实际谓词后，求解的属性值应改变；不支持时明确退出。
- 可共享实体、失败位置、合法路径长度至少有部分是候选决策，由约束和逻辑工作目标选择，而不是全由输入枚举出唯一图形。
- 新增数据必须接受完整查询核查；不能认为若干见证图的并集只会产生已有匹配。
- P4 与 P10 共享锚点形式的“候选 N、有效 0/1”使用同一匹配/过滤语义；P3 的属性赋值使用同一谓词规则。
- 预期答案从求解后语义与多重集计算得到，不为每种拓扑手写输出行。
- 用户指定测试目标和资源预算；程序确定满足目标的结构。通用构造原语可以人工实现，但不能把原图的完整连接关系包装成一个名为“自动”的原语。

## 8. 独立验证及证据边界

### 8.1 语义核查

小图解释器应独立计算节点/关系匹配、受支持路径、TRUE/FALSE/NULL、相关子查询、投影与重复次数。它读取已确定的具体图，不直接相信构图器写下的 `candidate_count` 或 `expected_rows`。对于路径和扩图，应检查绕行、平行关系、共享标签、额外端点、零跳路径以及重复关系限制。

类型测试不能代替数据语义测试。至少包含共享属性的冲突、相同关系类型引发的跨分支匹配、空值属性、零匹配 OPTIONAL、多重集重复、有限长度不可满足及空输入聚合等反例。

### 8.2 逻辑工作与物理执行

构造器可以证明“完整枚举有 N 个候选，给定早期谓词检查策略访问更少前缀”。这必须注明假设的访问起点、枚举方式和计数单位。它不能证明数据库选择该计划、一定产生某个 DB Hits 或达到某个运行时间比。

实际性能判断继续由已有流程完成：加载同一已求解状态、检查事实与索引、比较完整结果、普通运行计时、独立确认，以及计时之外的计划/工作量解释。未运行后端只能报告生成与本地语义核查通过。不同后端的路径、属性缺失、相关子查询和 LIMIT 支持不得互相推定。

### 8.3 单一图状态来源

建图语句、批量后端装载、状态检查和归档都应从同一份已求解图状态导出。不能保留一套新求解图，又让另一后端按旧 `GraphSpec(pattern, scale, seed, variant)` 重建不同拓扑。旧归档可以继续旧解码，新生成模式需要明确的版本和来源。

## 9. 规范来源与原型记录

`paper/vldb27-GraphSymPerf.pdf` 第 6 页表 1 决定 pattern 语义，第 7–8 页算法决定骨架、图状态与实例化的关系。`docs/Approach.md` 是另外的工作稿，本轮不修改，也不用于覆盖该 PDF。

## 10. P3/P4/P10 的机制复用、残留固定结构及论文算法迁移

### 10.1 复用边界按语义组件划分

三个规则先生成各自的局部符号结构，再进入相同的上下文组合、依赖解析、数据求解、实例化、局部变异和执行链。局部结构选择保留规则知识，原型按完整查询的观察约束搜索部分属性及数量；全目录批次又在部分规则上引入了由骨架直接指定的数量意图。二者不应统称为完整的向内数量合成。此前原型的具体查询构造步骤已由 `Src/symbolic.py` 的结构种子替代，底层求解器继续复用。

| 可复用层 | 输入与作用 | 三个规则的具体使用 |
|---|---|---|
| 运算组合 | 区分行多重集、整数和布尔值；按运算输入种类连接 COUNT、EXISTS、WITH | 同一局部结构可以处于不同上下文；不为每种运算序列再写查询构造器 |
| 词法依赖 | 解析变量定义、相关输入、投影导出与表达式消费者 | 锚点的同名拼写不能替代绑定身份；局部变异必须保持实际导出的绑定 |
| 局部谓词求值 | 从受支持比较常量产生有限属性域，寻找使条件真或假的赋值 | P3 的 ALL 节点条件、P4 的条件 C 和 H 的过滤、P10 的分支过滤复用求值规则 |
| 匹配组件 | 读取真实模式的方向、标签、关系类型、相关键与过滤条件 | P3 使用有界路径组件；P4/P10 使用固定锚点的有向一跳组件 |
| 结果需求 | 在具体小图上解释整个查询，保留标量值、NULL、类型及重复次数 | 外层消费约束内部有效匹配数；不能只检查局部 EXISTS 的真假或最终结果的行数 |
| 图输出 | 将解写成显式节点/关系组，并导出建图、状态检查和归档 | 使用同一已确定状态，后端不根据规则编号另造图 |
| 变异关系 | 按选定 AST 地址做一次局部变异，再沿消费者传播关系 | 分别应用 P3 的反转、P4 的 AND 重排、P10 的分支交换，复用外层 COUNT/EXISTS/WITH 的传播规则 |

路径和一跳组件不需要采用同一拓扑。P3 的失败在路径内部，可借助节点局部 ALL 的扩展稳定性；一跳组件的过滤直接发生在端点。共同点是“哪些绑定有效、哪些候选可增加而不改变完整结果”必须由查询语义核查。

### 10.2 一跳组件为何能同时服务 P4 和 P10

将一个有向一跳模式抽象为：给定相关键 u，沿关系类型 R 寻找端点 v，再用局部条件 φ(v) 过滤。构图器为这个组件选择候选数 n、有效数 m，以及相容的属性赋值。对某个具体模式，候选是“匹配结构后、应用本组件过滤前”的绑定，不能与最终输出行数混称。

P4 用 EXISTS 消费该组件，观察的是 `m > 0`。当投影中的 C(u) 为假时，完整 AND 值与 m 无关，但物理上仍可能提前求值 H。增加失败候选需要同时保持 C(u) 为假、完整投影类型不变及其他图读取不受影响。生成器通过完整查询求值选择满足这些要求的状态，而不是固定创建两个锚点。

当前 `_skipping_facts` 实现了一条与规则编号无关的搜索优先级：若扩大组件处于 AND 的某个子树，就寻找可取 false 的廉价兄弟；若处于 OR 的子树，就寻找可取 true 的廉价兄弟。候选根节点赋值按这类决定性事实排序，扩张组件也按同一事实排序。随后仍须满足完整输出需求；若输出要求阻止这一安排，不能只为满足优先级改写查询。

这里“廉价”有明确的支持范围：常量、固定锚点属性及受支持的纯标量组合。遇到 WITH 别名，代码沿 `symbol_id → producer_node` 找到实际生产表达式，再递归判断。只有该生产链仍不包含图读取，才把它作为廉价兄弟；确定性的 COUNT 或 EXISTS 不能仅因已绑定别名就当作免费值。该规则解释了 P4 中 `enabled=false` 的来源。失败端点的 `keep=false` 则来自端点过滤的显式假赋值；更换受支持谓词后，赋值由同一求值规则重算。

P10 将两个组件按同一 u 连接。若它们的有效匹配数分别为 m₁(u)、m₂(u)，且分支接口满足独立性条件，则中间结果重数为：

\[
\sum_u m_1(u)\,m_2(u).
\]

外层 COUNT、WITH 过滤或 EXISTS 消费这一多重集，因而会对 m₁、m₂ 的组合施加不同要求。大分支的候选数可以增长而有效数保持不变；增加另一个分支的有效数则通常改变输出重数，必须重新求解完整需求。

数量乘积按真实 Query 中的必选 MATCH 链登记。`_quantity_relations` 的 `mandatory_match_chains` 保存该查询地址、组件索引及因子，含义限定为“一个锚点输入行下，投影、DISTINCT 及其他过滤之前的模式组合”。不同相关子查询中的组件不被全局相乘；EXISTS 消费的是布尔存在性，COUNT 的真实消费行数另记在 `subquery_outcomes`。最终结果始终由完整解释器计算，而不是直接拿所有组件的数量连乘代替。

两个模式的变量不同，不代表数据匹配域独立。例如相同 u、相同关系类型和端点标签可能使新增候选同时被两个组件读取。一般求解器需要处理这种重叠；本轮受限构造可以要求匹配域隔离或拒绝未覆盖组合，不能靠偷偷更换查询中的关系类型取得隔离。

### 10.3 仍然固定的部分

本轮演进应按下面四层分别评估，而不是只问“是否还存在 if pattern”。

1. **局部查询种子仍由规则选择。** P3 的路径过滤、P4 的标量 AND、P10 的共享锚点双分支仍是有限的结构入口。递归上下文消除了每种完整嵌套组合的独立实现，但没有自动生成所有合法图查询结构。新路径对导入查询只保留来源记录，`seed_usage` 标明 `provenance_only_not_embedded`；导入文本不会自动成为新的任意查询核。
2. **数据构造族仍有限。** 有界路径采用受限树形族；一跳组件采用固定锚点的邻接族。它们搜索数量、共享安排和属性赋值，而不求解任意环、多锚点连接、可选匹配或任意相关结构。
3. **语义解释器与有限域仍需人工实现。** 运算类型、真假规则、NULL 行为、路径约束及集合/多重集区别需要明确编码。有限属性域、见证域和模型预算控制搜索资源，搜索失败不表示一般不可满足。
4. **工作量目标仍由测试者选择。** 哪个组件需要大量候选、希望暴露早失败还是重复执行、应保留什么结果，不能只从查询语法唯一推出。生成器求出满足目标的状态；计划与实测解释目标是否转化为真实额外工作。

当前一跳实现的工作目标具体为：优先寻找能决定 AND/OR 结果的纯锚点标量兄弟，并扩张一个有显式失败赋值的组件。它尚未联合优化多分支的重复执行次数、选择率差异或计划代价。有限数量搜索先满足完整输出需求，不保证选出代价差最大的状态。

因此，状态构造的实质增量应由可观察变化证明：改谓词会改变求解赋值，改外层阈值会改变内部有效匹配数，改相关键或分支接口会改变可满足组合。仅删除规则名称、保留完全相同的节点和连接步骤，不产生上述能力。

### 10.4 与论文算法 1 的对应

PDF 第 7 页算法 1 以 S、p 和规模为输入，依次执行 Init、Populate、SetGuards/AddWitnesses 或 Skew/Preserve、AddIndexes 和 Validate。统一符号路线需要让 S 在这些步骤中保持参数化，并把数据与查询需要的共同赋值记录在同一个解中。

P3/P4/P10 先前的“具体查询 → 有限模型搜索”提供了可复用的匹配组件和解释器；当前 `construct_state` 将候选符号赋值解释为约束项后调用这些求解器。候选模型解释允许临时替换符号以检查需求；最终 Q1 由 `instantiate_pair` 根据获证赋值生成，主入口直接保留同次返回的 Q2。

S6/S8 需要额外表达 Q0 的义务：S6 的 n 改变 Q0 的最小数量；S8 的 Q0 至少一个见证。高成本区域的增长不能修改见证或相关锚点的决定性事实。

### 10.5 与论文算法 2 的对应

PDF 第 8 页算法 2 先 Embed，再 Instantiate，检查 Applicable，复制完整 Q1 后执行 RaiseCost 或 Rewrite，最后检查 ValidPair。类型占位符按变量依赖顺序绑定，原上下文在两个副本间保持一致。

P3/P4/P10 的局部反转、AND 重排和必选分支交换继续复用已有语义规则。S6/S8 的新局部变异是 L→H；QL/QH 的行多重集允许不同。Q0 UNION ALL、S6 的全局 LIMIT、S8 的 EXISTS 以及外层上下文必须保持不变。

构造记录说明 G 及共同赋值如何满足义务，实例化记录说明 Q1/Q2 确实消费了该解。实际数据库加载检查和完整结果比较随后执行。三个记录层次对应不同证据，不能互相替代。

## 11. 首批五项符号骨架与 S6/S8 两阶段路线

### 11.1 接口合同与状态

公共入口仍为`main.prepare_case(..., composition=...)`。本节记录首批P3/P4/P10/S6/S8的统一过程；第12节的全目录沿用同一阶段接口。非composition的历史路径和旧存档仍保持原解释：

```text
build_symbolic_skeleton(pattern, options, seed) → SymbolicSkeleton
construct_state(skeleton, scale, data_seed) → SolvedSkeleton
instantiate_pair(skeleton, solved) → QueryPair
main.prepare_case → 编译、归档及原执行流程
```

`SymbolicSkeleton`的字段为`paper_pattern`、`form`、`source`、`replacement`、`anchor`、`options`、`seed`，本轮全目录新增`intents`，通过`to_data()`和`from_data()`往返；旧版本缺少`intents`时按空元组读取。`Symbol`为命名的标识符、整数或标量候选域；`Hole`为带名字的行流、谓词或标量候选结构。Q0/L/H角色由孔的身份及传给population的需求表示；变换位置在算法1按实际依赖解析为唯一AST地址并记录为`site`，不存在独立的`mark`、`roles`字段。`SolvedSkeleton`携带population、assignment和construction_record。`QueryPair`返回query_a、query_b、bindings、mutation_record、instantiation_record及必需状态检查。

这些层次的关键区别是：骨架中的 schema 和数据角色尚可求解；算法 1 确定状态与共同赋值；算法 2 消费该赋值并检查绑定摘要，才产生最终 Q1/Q2。不能在完成 QueryPair 后补一份“symbolic”标签来代替阶段分离。

当前候选选择还有一项明确限制：`_assignment` 先按种子选择有限符号/结构候选，图求解器在这份候选赋值下搜索状态。图约束失败时不会自动回溯全部标签、关系类型或孔候选。这是“一份获证赋值与图模型共同归档”的实现，尚不是覆盖全部 schema 候选的联合搜索器。`construct_state` 中的临时替换项只用于约束核查；`instantiate_pair` 复核骨架、赋值、图规格和 population 合同摘要后重新实例化最终查询。`main.prepare_case` 不会再次调用旧变异流程覆盖这次的 L→H 方向。

### 11.2 S6 的限额见证

S6 的未包裹结构为：

```text
Q1 = RowLimit(UnionAll(Q0, QL), n)
Q2 = RowLimit(UnionAll(Q0, QH), n)
```

它对应 PDF 的全局 `(Q0 UNION ALL QL/H) LIMIT n`，而不是单独对 L/H 设置 LIMIT。`row_limit` 是 S6 的正整数参数，当前有限域为 1–64，默认 3；改变它会改变 Q0 的数量需求。Q0 在每个相关锚点上至少产生 n 行；全部分支投影相同常量，且没有阻塞算子。因此允许 QL/QH 产生不同数量的行，完整限额结果仍保持 n 个相同常量行。

外层 COUNT 观察这一局部结果的行数 n，不能再通过扩大 H 把它解释成大于 n 的结果。上下文若提出冲突的数量要求，应拒绝，而不是移动 LIMIT、添加行或改写源查询。

独立入口为 `prepare_case(None, 'S6', scale, seed, data_seed, composition={'contexts': [], 'row_limit': 3})`。`contexts: []` 保留真正顶层的 RowLimit，不额外插入 COUNT；`contexts: ['count', 'with']`、`threshold: 2` 则观察限额产生的 3 行并通过过滤。

### 11.3 S8 的存在性见证

S8 的未包裹结构为固定锚点查询投影：

```text
EXISTS { Q0 UNION ALL QL/H }
```

Q0 每个相关锚点至少一行，输出列与 QL/QH 相容，且无阻塞算子。QL/QH 可具有不同结果多重集，EXISTS 仍为 true。独立形式保留一行布尔投影；外层 COUNT 看到的是这一行，不是布尔 true 的数值化，也不是内部两个分支匹配数的乘积。

S8 不接受 S6 的 `row_limit` 参数；显式提供时应拒绝。见证 Q0 和 UNION ALL 不能被删去或迁移进 H。

独立入口为 `prepare_case(None, 'S8', scale, seed, data_seed, composition={'contexts': []})`。当前构造保持一个固定锚点：Q0 产生 1 个有效匹配，QL 产生 1 个有效匹配，QH 产生 scale 个有效匹配；S6 的 Q0 数量改由 n 决定。三个区域根据真实 AST 中的关系类型、端点标签、属性及相关身份建立，完整查询和替换后的查询在同一模型上联合核查。这里的 scale 控制 H 的有效匹配数，与 P3/P4/P10 中“增加过滤失败候选而保持有效数”的扩张目标不同。

### 11.4 证据和测试登记

新案例在既有依赖、population 和 mutation 记录之外，保存 `symbolic_skeleton`、`construction_record`、`instantiation_record`。实例化核查骨架、共同赋值、图状态及 population 合同的摘要；存档读回核查包含三份记录的扩展摘要，篡改或剥离这些记录不能绕过完整性检查。S6/S8 还把按锚点计算 Q0 行数的查询加入必需装载检查；即使破坏 Q0 后完整查询偶然仍返回相同结果，装载检查也必须拒绝该状态。

新增离线测试位于 `tests/test_symbolic_pipeline.py`、`tests/test_symbolic_skeleton.py`、`tests/test_row_streams.py` 与 `tests/test_row_stream_execution_gate.py`，真实数据库测试位于 `tests/test_symbolic_neo4j.py`。后者只在显式配置的独立 Neo4j 测试实例上运行，由统一验证流程提供连接。新增产物与本轮数字在第 11.6 节单独登记。

### 11.5 递归如何复用同一机制

`build_symbolic_skeleton` 在符号阶段调用 `compose_fragment`。每一层只查看当前接口是行流、布尔值还是整数：COUNT/EXISTS 消费行流，标量需要行输入时先形成带过滤的锚点查询，WITH 为当前标量生成新别名并导出绑定。外层结构在此时保持符号化，使算法 1 能看到其需求；算法 2 按同一赋值物化整棵树，不再重新挑选上下文或为某条嵌套序列调用专用构造器。

S6/S8 的构图器遍历源与替换候选组成的 AST forest，按真实关系域和相关身份合并同一组件的出现位置，同时保留 low/high 数量需求。它为直接处于 RowLimit/EXISTS 下的 UNION 记录饱和或存在性证书，向 Q0 的实际行生产者传递最小数量。外层 EXISTS 若消费的是包裹查询或 WITH 结果，则复用内层证书，并由完整查询解释确认中间标量、别名和过滤结果；不能把所有祖先 EXISTS 都当成另一条 Q0 见证需求。

当前受限族仍是单个固定物理锚点与隔离的有向一跳域：最多 8 个关系域、32 次组件出现，固定见证预算不超过 64 行。Q0 的行数推导支持单个必选一跳生产者；多 MATCH 的见证数量乘积、Q0 内部 WITH 的行数传递、OPTIONAL 见证及任意多锚点连接尚未实现。外层 WITH 的递归组合与“任意 Q0 可以含 WITH”是不同能力。若 H 的增长还被不受饱和/存在性证书覆盖的位置读取，或者非同一组件的匹配域重叠，构造器拒绝该结构。

离线验收对 S6/S8 分别枚举深度 0–3 的全部 EXISTS/COUNT/WITH 运算积，并加入两条深度 8 的代表序列。每次都比较完整类型化结果多重集，并确认 Q0 未变、UNION ALL 未删、QL 与 QH 的有效匹配数确实不同；不能仅凭最终结果相等就把替换退化为两个相同的小分支。数据库验收另外覆盖 Q0 破坏后的拒绝、构造记录的存档回放，以及 H 有效匹配规模 10,000 时的装载和索引恢复。

```python

# form: independent / shared_anchor / chain；默认shared_anchor
```

```python
composition = {'contexts': [], 'match_state': 'left_only'}
# match_state: both / left_only / right_only / neither；默认both，仅P11接受
```

### 12.4 带类型对象的数量意图与两个阶段

`SymbolicSkeleton.intents`把测试需求附在实际AST对象上。数量项的`subject`为Node或Edge，`valid`指定有效匹配需求，`growth`区分增加有效匹配、增加过滤前候选及保持固定；角色名用于说明该需求的测试用途。逆边项另外声明两个实际关系类型及配对键。它们不列节点编号、图组名、边端点UID或一张完整拓扑。

例如，P10链的局部查询先给出`u→v→w`；数量意图将第一组件设为固定的多重匹配，将第二组件设为一个有效后继加可扩张候选。这里“有多少中间绑定”和“扩大哪个组件”是人工选择的工作量目标，不是MATCH语义能唯一推出的事实。当前结构种子使用乘数8；这个数字属于测试意图，不应被描述成P10的语义要求。

算法1先解析真实绑定及唯一变换位置，再把符号需求规范化为按AST地址定位的`MatchDemand`、`ValueDemand`与`InversePair`。它调用`plan_mutation`形成候选替换树，使源与替换候选的读取能够一起约束同一图；此时的候选仅用于求解和核查，不发布最终测试查询。标量前提从变换适用条件产生，逆边需求也作为结构对应关系进入同一解。

算法2消费已经接受的赋值和状态，先核查骨架、赋值、图与population合同摘要，再重新实例化源查询，并依据同一已核查规则生成另一副本。短路规则的决定性表达式及P2的双向逆边对应会生成必需装载检查。主流程保留这次返回的查询对，不重新选取schema、改阈值或运行另一套配图步骤。

这层分离使后续扩展的单位成为“AST组件的数量/值/结构义务”。仍然需要人工维护有限局部语法、规则前提、可执行语义及工作量目标；仅把旧拓扑的节点数和连接表搬进`intents`，不会获得这种能力。

### 12.5 关系构图引擎的实际推导

新关系族由`population.synthesize_relational_state`进入`relational_population.synthesize`。该模块不按论文编号选择拓扑，而是处理源与候选替换树组成的forest，以及规范化后的数量、值和结构义务。其实际过程为：

1. 按词法符号收集Node绑定的标签、固定属性与使用位置。相同变量拼写不直接建立物理身份；跨查询副本依据相容实际域对齐，歧义对齐须明确提供绑定关系或拒绝。
2. 提取Node扫描及固定长度Edge组件，把地址上的需求合并到实际物理匹配域。Edge的方向决定真实源/目标；关系类型选择项拆为有限的类型域；逆边义务共用同一对端点域。
3. 从真实比较常量、另一候选值和NULL形成有限属性域，并检查局部有效匹配条件、短路规则的决定性值及非空要求。属性名本身不决定真假赋值，WITH别名通过词法生产者求值。
4. 沿绑定依赖计算各域需要的见证数，再寻找使两个完整候选结果相同的有限属性模型。每个源绑定需要独立后继时，目标数量由源见证数与相对匹配数共同决定。
5. 先保留全部稳定有效见证，再安排增长的有效域，最后安排失败候选，统一分配UID后才生成连接。失败候选由真实局部条件推导：改变属性使过滤不再为TRUE、缺少标签合取项，或不满足固定属性；不存在按角色名专门创建的失败节点类。
6. 对每个增长族，按实际标签、固定属性、关系组方向/类型及导入绑定检查全部可能读取。该族必须在每个未被屏蔽的位置被局部条件排除；有效增长则必须处于已选择其他分支、决定性布尔兄弟、非空coalesce前缀或零输入/零需求等可核查屏蔽下。不能根据不同角色名或不同内部profile就假定读取域互不相交。
7. 保存小证明模型、完整参数化图、属性/数量赋值和逐位置增长证书。普通规模另做完整解释；大图不能只靠小图结果相等获准，还必须通过读取与屏蔽检查。

P10链说明了第4、5步的必要性。设`u→v`要求8个中间见证，`v→w`对每个v要求一个有效后继，则8个v和8个有效w先保留稳定UID区间；随后才安排每个v下的失败候选区间。边组按每个v的实际UID连接其后继区间。若把第一段的noise插在第二段见证前面，规模变化会移动w的UID，既可能接错边，也会使完整投影与证明模型不一致。当前实现先安排全部见证、再安排候选，统一分配UID后连接，因而复用真实中间绑定，而不是将两段各自配图后拼接。

本地抗词义测试对P6、P7、P10链、P11单侧缺失、S1、S9一致替换全部标识符Symbol候选，经骨架及IR的JSON往返后重新构图和实例化。测试比较图统计以及两对完整类型化结果，证明这些受限实例读取的是实际AST域和谓词，而非`Gsp*`标签或某个属性名的特殊含义。

### 12.6 当前边界

关系引擎覆盖有限的固定长度绑定图、局部标量条件、显式逆边及空值扩展义务；P3有界路径与S6/S8饱和见证继续使用其专门的通用语义构造族。关系引擎拒绝需要独立规则的自环/重复端点、循环绑定求不动点、显式UID匹配及同时无界的两个乘积维度。若数量需求超过目标见证域、需要平行边来实现额外重数，当前也明确拒绝，不把需求截小。有限属性搜索最多12个自由属性、50,000个候选模型，稳定见证乘积受构造预算约束；失败不构成一般不可满足证明。

## 13. P10链与S3：首轮语义目标实现（2026-10-21冻结历史）

本节保留2026-10-21首轮目标实现的机制和冻结证据，范围为P10的chain形式和S3。该批分别使用`_extend_chain`与`_conditional_rows`，工作目标分为`repeat`/`masked`；这些语法入口和默认策略已由第14节的共享`RowGrammar`及`auto`目标演进。以下具体数量与验证记录不改写为后续源码的运行结果。该批入口保持`prepare_case → compile_case → run_case`，算法1负责接受图状态和共同赋值，算法2负责物化查询对并验证局部变异。

### 13.1 语法增长与图数量增长是两个维度

链长描述查询AST里有多少个匹配段。例如`u→v→w`有两段，`u→v→w→n→r`有四段。`symbolic._extend_chain`重复应用同一个“前一端点成为下一段起点”的产生式；每次引入新节点绑定和关系原子，投影保留全部端点。它没有针对两段、三段或五段分别安排图。

该批`composition.chain_length`可以固定本次语法选择，预算为2–6段；未指定时按查询种子在2–4段中取样。S3由`_conditional_rows`递归生成选中分支中的条件行流；`conditional_depth`为1–3层，未指定时按种子选择。二者属于有限语法预算，不指定图节点数、UID或边端点表。

数据规模则在语法固定后由需求求解决定。同一条四段链可以只需要少量见证，也可以因外层COUNT下界而需要更多有效行；`scale`在新目标路径中控制潜在工作量强度，而非沿用第12节中“某条边每输入增加N个候选”的固定解释。

### 13.2 显式变异标记与跨副本对应

`SymbolicSkeleton`增加`MutationMark(site_id, address)`。生成局部结构时就标记要测试的实际词法位置；组合上下文后将它定位到完整源AST。`select_mutation_site`验证该地址的规则适用性，不再要求整棵树只能出现一个同类法则。因此S3套S3可以选择内层或外层的ELSE，其他合法条件结构不被顺带修改。

`plan_mutation_with_correspondence`返回候选替换树及源/目标Node occurrence的对应。MATCH交换按实际子句移动其来源地址；S3替换保留未修改位置的来源，新插入局部节点不冒认原节点。关系引擎在此模式下消费显式`BindingRelation`，不再依据相同标签或属性map猜测两个查询副本的绑定对应。同树绑定身份仍由AST依赖分析的作用域化符号给出。

这使`v、w、n`都使用同一标签`Shared`的链也能保留各自身份。标签相同不等于同一个词法绑定；反之，同一绑定在相邻边中的两个出现位置必须共享同一实体域。

### 13.3 目标接口与向内推导

这两个入口的`intents`不再包含逐边数量项。骨架给出的目标为：

```text
output：最终输出至少一行
work/repeat：在标记的行生产者对中形成非平凡重复，放大额外候选工作
work/masked：扩大被决定性条件屏蔽的替换行流工作
```

目标不包含Node/Edge对象、`exact_matches`、`candidate_matches`或哪个schema名字表示高区。`requirements.derive_requirement_plans`读取完整源/候选AST、标记位置和对应关系，将目标降低为内部的`MatchDemand`与`ValueDemand`，并记录推导步骤、基数不等式、每输入匹配数、增长轴及潜在工作量证据。内部出现精确数量是求解结果，区别于调用者预先填入每条边的数量。

向内规则包括：

- 最终Query的正行数需求要求相关过滤条件为TRUE；WITH别名沿实际producer追溯，不能用同名变量替代来源。
- `COUNT{R}>t`为TRUE时向R传递`rows≥t+1`；反向比较、否定及零上界在支持片段内转换为相应区间。
- `EXISTS{R}`为TRUE要求至少一行，为FALSE要求零行。`NOT EXISTS{R}`为TRUE因而会向图读取传递FALSE/零匹配需求。
- ConditionalQuery将输出行数需求传入选定分支，并要求条件满足所选真假；嵌套条件的需求递归传递，条件中的COUNT/EXISTS也参与行数求解。
- 必选MATCH段把相对匹配数合成为行数约束。有限整数分配器按真实绑定依赖估计实体数量，以较小构造优先搜索满足约束的分配。

`repeat`中的“非平凡重复”表示重复次数大于1，其整数下界为2；这是目标的语义条件，不是新的固定8节点配方。额外候选工作要求至少为`scale`，每输入候选数由重复次数反推。例如重复次数为2、目标为7时，每输入增加4个候选，潜在额外候选工作为8。具体物理执行是否重复及其代价差，仍需要数据库计划与测量建立。

普通WHERE的TRUE需求表示需要存在通过过滤的有效见证，不要求失败候选也满足WHERE。零行需求也可以通过局部过滤失败实现，其FALSE赋值是行生产者内部的构造选择。推导记录把这类要求标为`matching_witness`，不会把局部候选变量错误提升为全称外层状态事实；实际COUNT/EXISTS的零行或存在性才是其外层消费者的观察。决定性guard等值义务标为`input_domain`，必须在适用绑定上成立。这两个量词不同；若把它们都变成“所有物理候选恒真/恒假”，会排除合法构造或产生错误的装载检查。

### 13.4 算法1与算法2的实际分工

算法1接收包含上下文的符号骨架、显式标记及目标。它先选择一次有限语法/schema赋值，构成约束候选；再由共享变异核心计划候选副本和来源对应，向内降低需求，枚举有限基数分配并搜索属性模型。关系构图器实现所得需求，检查最终最小输出、完整袋相等及增长读取闭包。接受记录包含目标推导、对应关系和完整population合同摘要。

算法2复核同一骨架、标记、赋值和图合同，重新物化已经接受的查询，构造实际guard及结构前提检查，再在显式标记处执行最终变异。它不另选数量、改阈值或重新配图。P10链的局部关系按共享变量上的袋自然连接交换解释；S3从整个ConditionalQuery行流的袋相等开始，沿COUNT、别名、WITH及EXISTS等消费者向外传播。

除选定变异点的前提外，算法2还导出所有已接受`ValueDemand`的装载检查。它在实际源树或目标树的地址取出表达式，沿真实WITH producer和绑定关闭别名，再产生判断该表达式是否等于所需TRUE/FALSE的查询；检查同时进入`goal_checks`及不可丢弃的`required_state_checks`。这覆盖祖先S3条件和向内推导出的存在/空性事实，避免只验证最深层guard、却把外层条件留作未检查的假设。普通WHERE的见证构造选择不被导出为外层全称检查。

图依赖guard不能仅凭小证明图上的一次TRUE就屏蔽高区。该批关系引擎在求值前检查guard内部实际Node/Edge读取对所有增长族的可见性；存在未被排除的增长读取时，不将该guard当作规模不变事实。属性条件、COUNT和EXISTS因此共同受物理读取闭包约束。

该批语法/schema赋值是一次有限候选选择，没有完成对所有语法孔候选的联合回溯。图基数与属性的搜索也有明确预算，预算耗尽不等于一般不可满足证明。

## 14. 递归行语法、三值需求与自动工作轴（2026-10-22冻结历史）

本节保留2026-10-22递归行语法批次的机制和冻结证据；后续标量演进见第15节，不能用本节源码摘要代替后续验证。该批继续使用算法1构图、算法2消费同一解并生成查询对的分工。P10链和S3共用`Src/row_grammar.py::RowGrammar`，目标入口默认使用`work/auto`。第13节的`repeat`/`masked`输入仍用于兼容旧骨架；该批新骨架不再通过pattern编号选择这两个模式。这里的“共享”指相同语法产生式、需求规则及图实现，不表示当时其余21个论文ID已完成目标驱动迁移。

### 14.1 同一语法同时生成链和条件行流

`RowGrammar.expand(length, depth, guard_kind, branch_path, projection)`用同一递归展开处理两个局部律入口。`matching`产生绑定连续的必选边段；条件产生式可以将递归子树放入THEN或ELSE。P10选中叶链上的相邻MATCH对，S3选中最内层ConditionalQuery的局部ELSE；选律位置由显式标记保存，不由全树匹配结果是否唯一决定。

- `chain_length`是1–6段的语法预算；P10链要求至少2段，S3可以有多段链叶子，且替换高分支也由相同matching产生式构造。
- `conditional_depth`是0–3层的预算；P10默认0，S3至少1层。因此P10可以处在多层条件行流中，S3的行叶子也可以是多段链。
- `branch_path`对每个非叶条件选择`then`或`otherwise`，长度为`depth-1`；省略时按种子取样，而非只沿THEN递归。
- 独立链可投影节点绑定；条件组合使用兼容常量行接口，保证不同分支的列与类型相容。节点名、guard根名及单边端点名避开已有锚点，防止结构增长引入意外捕获。

例如，`P10 + length=3 + depth=3 + branch_path=[otherwise,then]`与`S3 + length=3 + depth=3 + branch_path=[then,otherwise]`都由这一个行语法生成。不同之处是选择的局部变异律及标记位置，图构造并不另列组合专用函数。

### 14.2 需求是三值与整数区间集合

条件取值区分TRUE、FALSE、NULL。WHEN选择THEN要求TRUE，选择ELSE允许FALSE或NULL；NULL不能被直接改记为FALSE。输入域事实中的NULL通过`IS NULL`观察，装载后检查不使用`expr = NULL`。对于物理属性，Neo4j将NULL存为属性缺失，图状态的计数检查同样使用`WHERE property IS NULL`，而不是属性map中的`property:null`。

COUNT约束保留整数区间集合：`COUNT>2`给出`[3,+∞)`，`COUNT<>3`给出`[0,2]∪[4,+∞)`，二者交集为`[4,+∞)`。共享WITH生产者的多次观察作用于同一数量变量，不能把排除一个值误写成只有一个区间。矛盾交集拒绝；OR等有多个可行真值分解时，在有限预算内尝试其他分解，不能因第一个非字面量分支不可满足就结束。

见证过滤与输入域事实继续使用不同量词。普通WHERE只要求所构造的有效行通过过滤，失败候选不被强迫恒真；guard、外层存在/空性等事实则需要覆盖实际输入域，并导出不可丢弃的装载检查。别名关闭不跨越独立子查询的局部WITH作用域；无外部导入的事实检查使用新鲜外部锚点，避免把内部同名`u`意外相关化。

属性搜索先在每个实际绑定域内检查正匹配需要的纯局部谓词；某个谓词涉及的属性一旦全部赋值，就剔除结果为FALSE/NULL的有效见证候选，再懒组合各域的候选赋值。决定性guard要求FALSE/NULL以及零匹配域的属性义务不被这个正见证剪枝覆盖。这样多层条件加多段链不必先展开全部跨域属性笛卡尔积；12个自由属性、50,000个候选模型的预算保持不变，预算内搜索失败仍不构成一般不可满足证明。

装载检查观察完整物理匹配域，而不是单个构造组。例如某个固定目标节点的入边计数，需要累加所有实际能连到该节点的关系组，包括源端用等差编号压缩的组。两个端点约束必须选择同一个边下标，不能把源、目标的候选下标独立相乘。该检查与完整查询结果检查分开；即使两份查询仍返回相同COUNT，也不能绕过失败的结构或属性事实。

### 14.3 工作目标按实际依赖枚举

`auto`根据标记及其观察结构提出可行工作轴。在MATCH交换中，候选限于真正被搬动的读及它在两个顺序中的输入依赖，未变动的后续第三段不能充当顺序差异的替代目标。向条件的未选替换分支增加工作时，候选来自该实际行流中的多个匹配原子，而非只取第一条边。

不同候选工作轴需要不同的工作量解释：

- 已绑定输入上的重复展开，按实际输入重复数与每输入额外候选量计算潜在候选工作。
- 被搬到生产者之后的过滤，不把其已绑定端错误当作可重复fanout。若增长该端的失败候选，必须证明前面的实际生产者能读取它们、形成额外行，再由后置过滤排除；证据记录生产者位置、增长位置及传播系数。
- 被屏蔽的行流可以沿不同匹配轴增长，但每个增长族仍要通过全查询物理读取闭包；未保护的额外读取导致拒绝。

重复系数不能只把前面MATCH的数量相乘。当前构造域内，同一绑定域的普通属性共享赋值，物理`uid`逐副本不同；只有沿定义–使用关系展开别名后、由非`uid`普通属性和纯标量运算组成的前缀过滤，才获得“对该构造域均匀”的证明，允许继续使用数量乘积。普通WITH中的标量别名过滤可以通过这项检查。含`uid`、COUNT/EXISTS/ALL图读取的MATCH或WITH过滤，以及`WITH DISTINCT`，没有相应逐域/去重证书时会使该工作轴被拒绝；单个通过过滤的见证不能证明全部重复输入都保留下来。

工作轴中的`candidate_kind`也是构造约束。`right`要求失败候选属于被增长读的右端绑定域；`right_scalar`还要求保留该域的标签及固定属性，只通过真实局部标量条件产生失败赋值。后者保证前置生产者确实能读到这些中间候选。若局部条件恒真或没有相容失败赋值，图实现必须拒绝该生产者增长计划，再尝试其他合法轴；不能改成别的端点、缺少标签的节点或另一个增长族却沿用原工作证据。

因此工作证据不仅列出一个不同地址，还要对应实际图中的失败候选或额外生产者行。它描述潜在执行工作，不替代数据库对访问方向、执行顺序与物理代价的诊断。

### 14.4 面向13P+10S的能力矩阵

## 15. 标量语法、一般值需求与工作屏蔽（2026-10-22冻结历史）

本节保留将P4、P5、P13、S1、S2、S4、S7接入共享标量语法及`output/value/work`目标的冻结批次；后续匹配演进见第16节。独立原生AST、公共组合入口和真实数据库验收分别执行；最终冻结记录在本节末单独登记。第14节的能力矩阵说明前一批状态，不再作为这七项的迁移结论；本节第15.5节对P10两种形式及P11的未迁移说明，也由第16节的新状态取代。

### 15.1 局部律选择与递归产生式分开

`ScalarGrammar`接收局部运算和变异动作：P4/P5是AND/OR交换，P13是CASE互补交换，S1/S2/S4/S7分别是OR、AND、CASE、coalesce的被屏蔽参数替换。这个有限映射只决定测试什么等价关系及标记哪个接口，不给任何原子的数量、UID或连接表。

递归上下文共用AND、OR、CASE-THEN、CASE-ELSE、coalesce产生式。AND/OR需要布尔接口；CASE与coalesce保持当前标量类型。图读取由相同`RowGrammar.matching`产生，可作为COUNT或EXISTS的输入；整数、布尔、浮点数及字符串接口由带类型的标量表达式连接，不能把所有值统一改成TRUE。

公共参数`scalar_depth`为0–4层，默认按种子选择1–3层；也可用从内到外的`scalar_contexts`显式选择上述产生式，二者互斥。`scalar_type`区分boolean、integer、float、string；`scalar_value`给出实际观察值，包括False、0、空串、1.5或NULL。类型不匹配及语义矛盾应拒绝。`chain_length`为1–6段，控制标量子查询的匹配语法；`contexts`继续控制外部COUNT/EXISTS/WITH行消费者。它们均不指定图中的有效数或候选数。

显式`MutationMark`仍指向唯一词法位置。同一表达式里可以有多个合法CASE/coalesce位点；选择内层或外层fallback时，只替换相应参数。标记位于更深表达式时，需求传播还需激活通向该局部律的CASE分支、coalesce前缀及布尔兄弟，不能让祖先常量先屏蔽整条待测路径。

### 15.2 精确值、NULL和非空是三种不同义务

一般值目标携带实际AST地址、`equal`关系及类型化literal；`nonnull`只要求不为NULL。值需求沿WITH的真实生产者传播，CASE先选择TRUE或FALSE/NULL分支，coalesce逐项排除NULL，COUNT把整数等式转换为相应行数区间。精确标量赋值与结果多重集保留False、0、0.0的类型区别；这与匹配谓词的等值比较是不同层次，后者的数值语义在第16节补充说明。

S7的一个典型位点为`coalesce(prefix, payload, fallback)`中的最后参数。其前提是`prefix=NULL`、`payload≠NULL`；若最终值目标为0，则继续推出`payload=0`。0、False、空串均可作为非空决定值，不能将非空证明记作`payload=TRUE`。一般coalesce的候选位点按真实参数前缀分析：替换`args[j]`时，要求`args[0..j-2]`为NULL、紧邻前项`args[j-1]`非NULL；当前finder按这个前缀分解登记位点。调用者须显式标记预期位点，而不是依赖遍历顺序挑第一个候选。

P13的互补条件为`NOT coalesce(condition,FALSE)`。原条件为FALSE或NULL时，都保留原ELSE的值；直接使用`NOT condition`会在NULL时仍得NULL，不能证明交换后的分支选择相同。S4则保留选中的THEN值，只提高未选ELSE的工作；一般值可以是整数、字符串、浮点数或NULL。

标量核在一个已绑定锚点输入下返回一行，值为NULL也不把该行删去。外层`COUNT{标量核}`观察的是这一行，与核内COUNT/EXISTS读取多少图匹配不同。因此`COUNT{标量核}>1`不能通过扩大H或复制已绑定锚点满足；若最终要求非空输出，这个组合应拒绝。数量传播必须区分图匹配的基数、标量值及包裹查询的输出行数。

算法2为精确值、NULL及非空分别构造等值、`IS NULL`和`IS NOT NULL`装载观察，并将它们加入必需检查。别名关闭仍服从词法作用域；同名重绑不能引用旧生产者，被丢弃的实体名不能在后续表达式中被悄悄捕获。算法1接受的图、共同赋值与这些事实一起进入算法2及存档，算法2不另选一份使结果容易相等的值。

每条`ValueDemand`还有独立的值不变证书与增长读取闭包。外部coalesce使COUNT不影响最终输出，并不能证明该COUNT仍等于1；若事实直接观察`COUNT=1`，增长必须另外保持这个等式。相反，COUNT/EXISTS的非空事实只证明结果类型非NULL，不冻结其数值；事实自身的表达式也可通过三值规则证明不变，例如`FALSE AND UNKNOWN=FALSE`。`scalar_value_certificates`记录这些区别，避免用整份查询的屏蔽证据替代某条内部事实的证明。

### 15.3 标量工作轴需要语义屏蔽和真实可达性

标量工作轴首先从实际改变的表达式里寻找COUNT/EXISTS读取，再寻找使该读取不影响外层值的证据：未选CASE分支、AND/OR的吸收兄弟，或coalesce前面的非空值。L→H替换只从替换H内选择增长读取；不能放大将被删除的L，并把其增长量记成H的成本。P4/P5/P13的重排则保留源、目标副本中实际被移动读取的候选。

外部屏蔽证明结果不变；被屏蔽表达式若被求值，内部路径还须能到达被放大的读取。L→H的屏蔽证据须位于替换接口外，H内部恒FALSE的CASE或已有非空项的coalesce不能充当“高成本读取”的证明。内部CASE须选择该读取所在分支，coalesce更早参数须为NULL，布尔兄弟须取中性值。多MATCH子查询还要证明至少一个有效前缀输入能到达增长原子；不能把前序零匹配之后永远不会执行的后段登记为工作目标。COUNT的有效增长要求匹配域过滤具有均匀性证明，沿用第14节的词法及构造域规则。

这项可达性还需跨过每一层Query观察域：RETURN中的嵌套COUNT需要外层全部生产与过滤之后的真实行；WHERE中的嵌套COUNT需要当前模式绑定之后、本次过滤应用之前的真实输入，不能把该WHERE本身已通过作为调用前提。若前序`WHERE FALSE`已经删除全部行，不能独立创建一批可供内部COUNT读取的全局节点来伪造工作。OPTIONAL产生的一行NULL扩展也不足以证明相关实体非空；缺少导入实体的非空见证规则时必须拒绝，不能只检查外层查询非空。当前跨Query过滤接受常量/已获证恒真条件及已认证的右端局部标量匹配条件；具有独立类型化事实证明TRUE的纯WITH别名过滤也可接入。其他涉及左端、Node扫描或WITH别名的过滤若没有输入域证书，保守拒绝。

COUNT通常通过增长有效匹配数增加工作；保持EXISTS为FALSE时则需增长真实过滤前候选，最终有效匹配仍为0。两者不能都用“子查询返回N行”验证。生成器按实际方向、关系类型、端点域及失败条件实现相应需求，并对两棵完整AST的全部读取检查增长闭包。另一个未保护COUNT读取相同物理域时，即使标记处被屏蔽，也应拒绝整个状态。

### 15.4 从标量骨架到图状态的一个推导

设源式返回`CASE WHEN route THEN coalesce(prefix,payload,9) ELSE 0 END`，标记最后的9，H为包含三段匹配链的COUNT；目标为保留整数0、至少一行输出，并放大H。算法1根据标记激活外层THEN路径，推出`route=TRUE`；局部S7前提推出`prefix=NULL`与`payload≠NULL`；精确值目标进一步推出`payload=0`。这些值来自实际表达式及观察目标，不来自属性名字。

H中的三段链由行语法产生。需求层选择其中一个合法增长轴，要求其前缀可达，并将工作目标降低为有效匹配或候选数量；其他数量由行基数约束分配。图实现再为相应词法绑定分配稳定见证和增长域，检查全部读取、精确值和完整结果。算法2只消费已接受赋值，复制源式并把标记的9替换成同类型H；外层CASE、coalesce前缀和payload保持不变。

若要求同一payload同时为0和非0，或要求选中的NULL结果同时非空，应拒绝。若把H的图域再暴露为独立COUNT输出，也应拒绝工作增长。在保持CASE/coalesce接口类型相容的产生式中，将payload的观察值改成False、空串或1.5时，应由同一值传播与类型规则改变构造赋值，不能换用新的配图函数。

### 15.5 尚未统一的部分

七项迁移加上P10链及S3形成目标驱动的局部律入口，但P10的independent/shared_anchor形式仍未迁入同一工作轴规则。其余十四个论文ID仍分别使用旧intents或原语义求解器：P1、P2、P3、P6、P7、P8、P9、P11、P12、S5、S6、S8、S9、S10。它们缺少的规则仍包括访问选择性、逆边双射、有界路径/ALL、OPTIONAL空值扩展、UNION/LIMIT的Q0见证及DISTINCT不同值见证，不能从本轮标量支持直接推出。

当前还需人工维护有限产生式、类型规则、局部律及其前提、读取域和屏蔽证明。COUNT到字符串/浮点数的连接表达式、默认观察样值和有限属性/数量域也仍是受限选择；它们不等于任意Cypher标量程序的综合器。语法候选在图搜索前按种子选定，失败时尚未联合回溯全部schema及结构候选。工作目标是潜在读量要求，不是数据库优化器的物理成本模型。

## 16. 匹配组件、逐输入数量与OPTIONAL的NULL扩展

本节保留上一批匹配组件/OPTIONAL重构的冻结记录；其中覆盖10个论文ID、其余13项及2,518/277项验证均是该批次口径。后续P3迁移与最终验证见第17节，不能将旧计数当作当前全套结果。

本轮迁移范围为P10的independent、shared_anchor形式及P11；P10的chain形式继续走同一机制。论文第6页表1要求P10保留实际独立、共享锚点或链式绑定，P11仅共享必选锚点且无跨支依赖。因此统一的是语法、依赖及需求规则，不能把独立组件或OPTIONAL改写成链来获得表面覆盖。本节的最终验证与历史批次分开登记。

### 16.1 同一行语法表达三种绑定策略

`RowGrammar.matching`在同一产生式中选择绑定策略：chain使前一端点成为下一起点；shared使各分支读取同一已绑定锚点；fresh使组件使用互不相连的词法绑定。OPTIONAL是shared策略上的行流语义，不另选一张按P11命名的图。

公共`chain_length`在P10三形式和P11中表示2–6个匹配生产者：链中是边段，共享锚点中是分支，独立形式中是互不相连的组件。`conditional_depth`、`guard_kind`、`branch_path`继续控制相同的条件行流递归；外部COUNT/EXISTS/WITH继续复用原接口。P11裸形式保留锚点与全部可选端点的UID投影，以便实际观察NULL扩展。

`match_state`只把前两个被交换分支转换为实际Node occurrence上的`null/nonnull`绑定目标；多余分支由外层语义需求决定。骨架的`intents`为空，不填每条边的有效数、候选数或固定乘数。显式标记确定被交换的两个生产者，后续第三分支不能成为次序差异的替代增长轴。

### 16.2 先区分匹配数与输出行数

对一个输入锚点u，设分支i的有效匹配数为`m_i(u)`。必选MATCH产生`m_i(u)`行；OPTIONAL产生`max(1,m_i(u))`行。零匹配时保留一行，并把该分支新引入的实体绑定设为NULL。两个独立可选分支的逐输入输出数因此为`max(1,m_left(u)) × max(1,m_right(u))`，不能沿用必选MATCH的零乘积。

绑定状态与行数分开传播：`nonnull`要求相应可选分支有有效匹配，`null`要求该绑定在实际子句输出中为空。后续`IS NULL`/`IS NOT NULL`过滤、COUNT下界和工作目标再共同约束数量。实体存在但某个普通属性缺失，与实体绑定为NULL不同；`a.tag IS NULL`不能独自证明a为空，`a.uid IS NOT NULL AND a.tag IS NULL`应保留存在的a及缺失属性。`a.uid = NULL`的结果为NULL，不能用来通过WHERE。

`EntityBindingDemand`绑定实际AST中的Node位置，而非“图里存在某标签节点”。新引入的可选端点在子句输出后观察；后续匹配导入的实体在当前匹配之前观察。NULL导入不能通过同名Node语法被重新当作新实体绑定。即使图里有孤立的同标签节点，也不能用它证明该输入行上的实体非空。

实体经WITH别名传递时保留类型、NULL性及真实生产者。匹配数量检查有时需要释放本查询内先前枚举的目标绑定，以观察每个逻辑源的邻接数；若该目标只是外部实体的局部别名，就必须沿定义–使用关系追溯外部来源并保留约束。例如外层固定b=节点2，局部`WITH b AS target`后只能匹配节点2；图中u到节点3的一条边不能使该匹配计数变成1。

### 16.3 数量证据必须针对实际物理读取域

算法1把外层需求降低为逐输入匹配数量，而不是直接把每个组件的构造组大小记作匹配数。对于两个必选独立分支，`COUNT>5`可与重复输入目标共同推出2×3的有效组合；数量由约束分配，不在骨架中写成8×1。每个实际输入u都需要满足相应局部匹配数，不能把全图总量2/3误记成每输入2/3。

低层对照例显式要求两个输入锚点、每个锚点左2右3。正确状态应返回12行，按u分组各6行，并且分别有2条左邻接、3条右邻接。这是构图器的逐输入合同验收，显式MatchDemand只用于该验收，不是公共pattern的数量配置。

词法绑定不同也不意味着物理读取域独立。`a:Same`与`b:Same`若都扫描同一标签，分别安排2个和3个节点后，两次实际扫描可能都看到5个节点。相同锚点、关系类型、端点标签和过滤的两条分支也可能读取同一邻域。前者不能宣称实际匹配数仍为2/3，后者不能宣称一边空、一边正；需要实际数量/绑定证明，无法满足时拒绝，不能靠查询对最终相等放行。

同标签也不等于必须拒绝。实际过滤分别为`flag=FALSE`和`flag=0`时，类型语义可区分两个读取域；2个布尔FALSE节点和3个整数0节点应产生6行。装载统计须保留分别为2和3的检查，不能把实现语言中的`False == 0`直接用于图查询的布尔/数字匹配或检查去重。

匹配比较按目标语言的数值语义解释：本批Neo4j中`0=0.0`为TRUE、`FALSE=0`为FALSE。因此同域中`flag=0`与`flag=0.0`不能被强行分成互不相交的2/3匹配；无法同时满足的精确需求应拒绝。完整结果的类型化多重集仍区分整数0与浮点0.0，匹配等值不能替代输出类型检查。

数量观察是对实际非NULL逻辑源输入的全称约束；工作目标还须独立证明这个输入域非空。空输入上的全称式不能提供额外工作，绑定NULL事实本身也要求所观察的行域存在。增长闭包继续检查整棵源/目标AST和每条值事实。UID或关系属性随压缩组编号变化时，不能仅凭小证明图未出现某常量，就推出全规模也没有相应匹配；未经认证的读取或筛选应拒绝。

当前图族仍按均匀构造域实现每输入相同的q，并对实际读取进行认证。这不等于可以综合任意异质的`m(u)`；按不同输入属性分区、部分锚点零匹配而其他锚点多匹配等一般目标，还需要分区和非均匀数量规则。未知或冲突的物理域不能被默认当作均匀域。

### 16.4 一个目标驱动的三分支推导

设叶查询有三个OPTIONAL，标记前两个交换；前两个绑定目标均为NULL，外层要求`COUNT>9`。前两分支的有效匹配数被约束为0，各自产生一行NULL扩展。输出需求于是传给未标记的第三分支，推出它至少提供10行。前两个分支在两个次序中的输入前缀仍只有一行；第三分支后面产生10行，不能反向成为前面读取的重复次数。

若工作预算为7，`auto`可给前两个被移动读取之一安排7个真实失败候选，并记录重复系数1及`nontrivial_repetition=false`。这形成候选工作目标，不认证非平凡的次序收益。显式要求重复次数至少2时，该状态应拒绝。前两分支存在有效匹配且能提供非平凡重复时，自动策略优先选择相应合法工作轴。

这一推导同时用到OPTIONAL的`max(1,m)`、显式变异位置和外层COUNT需求，没有三分支专用配图函数。把前两状态改为left_only或both，会改变零/正匹配约束及可用重复前缀；保留前两为neither、增加第三分支数量，只改变输出，不改变被移动读取的前缀。

### 16.5 算法分工与剩余边界

算法1读取完整符号AST、标记、绑定/行数/工作目标，解析作用域及跨副本来源，分配数量并构造图。接受条件包括实际逐输入匹配数、NULL/非NULL绑定、增长闭包和完整类型化结果。算法2消费同一图与赋值，在相同标记交换子句，并保留前述事实为不可丢弃的装载检查；不能在实例化时再复制锚点、改变状态或重新挑选数量。

公共语法覆盖条件行流递归及COUNT/EXISTS/WITH外层组合。独立AST另覆盖RETURN的COUNT中嵌套P11，并分别选择内层或外层标记；只导入真正的必选锚点，不把外部可NULL端点偷换成新锚点。此类验收说明通用机制能接收更广AST，不表示公共语法已能随机产生任意P11套P11。

本批之后，P10全部三形式、P11、S3及前批七个标量ID共10个论文ID进入目标路线。剩余13项为P1、P2、P3、P6、P7、P8、P9、P12、S5、S6、S8、S9、S10，仍需访问选择性、逆边、有界路径/ALL、UNION/LIMIT见证及DISTINCT等各自算子规则。有限的局部律映射、语法候选、schema候选、构造族和搜索预算仍需人工维护；独立组件当前选择扫描与独立查找根的一跳族，也不是任意连接拓扑。历史手工路径为兼容回放继续存在，不能将新入口的统一描述成仓库中已消除全部历史硬编码。

目标驱动入口的scale约束潜在候选工作，不能等同节点数；重复系数为2时，预算10,000可由5,000个新增候选承担。低层两份案例没有work目标，只记录其构图调用规模与精确数量合同。本批证明受限语法、逐输入数量、NULL绑定事实及既有编译/运行/回放流程；这些规模和高筛选阈值下的`no_candidate`不作为物理性能差异或数据库缺陷结论。第16.5节列出的其余13项与均匀构造域边界仍保留。

## 17. 有界路径、ALL与安全路径扩张

本节记录P3进入目标求解路线后的实现。第16节的计数、覆盖范围和存档属于上一批冻结结果；本节不把旧结果累加为新的验收结果。

### 17.1 语法和需求仍沿公共入口传播

`RowGrammar.bounded_path`只产生有限跳数的路径语法、`nodes(p)`上的节点局部ALL及投影。`RowGrammar.expand`把这个叶子放入与匹配组件相同的条件行流产生式，因而可选择THEN或ELSE递归，并复用COUNT、EXISTS、WITH外层组合。公开P3仍使用`path_bounds`表达路径长度预算，未把链的`chain_length`偷换成路径长度。显式标记定位实际路径AST，P3骨架的`intents`为空。

公共需求层将路径作为行数原子：外层`COUNT>k`要求有效路径行数至少为k+1；WITH变量通过真实生产者传递该区间；`COUNT { RETURN COUNT { path } }`仍只计一条标量投影行。`length(p)`的比较与语法跳数区间取交集，保留非连续比较所得的候选区间，再选一个具体长度见证。路径符号、ALL量词变量及别名均通过词法依赖识别，不能仅凭打印名称合并不同作用域的路径。

ALL的值分为TRUE、FALSE和NULL：TRUE要求所有元素为TRUE；FALSE需要至少一个FALSE；NULL需要没有FALSE且至少一个NULL。`nodes(p)`包含起点和终点。公共需求层输出`PathDemand`记录实际路径位置、长度区间和ALL的三值目标，匹配数量仍由`MatchDemand`表示；`ValueDemand`约束ALL投影及其别名的精确值，并要求实际观察行域非空；值本身允许NULL。NULL不是“没有要求”，也不能替代显式FALSE来认证失败前缀。

### 17.2 同一数量求解器如何生成真实路径

路径后端先将有界路径降低为连接相同两端的固定长度关系原子，将长度观察替换为所选长度，将ALL观察降低为端点上的节点局部谓词。该降低具有明确的构造条件：起点与普通内部节点具有共同TRUE赋值，因而端点的TRUE/FALSE/NULL值正好等于整条路径的ALL值。共同关系构图器据此求解外层行流、普通匹配组件、绑定事实、有效数量及失败候选，不另写按P3命名的配图器。

随后将商图中的每条关系提升为所选长度的唯一树路径。新内部节点使用新鲜标签，边不复用；每条端点关系与一条实际路径一一对应，真实ALL重新包含两端与所有内部节点。完整源/目标查询在提升后的证明图上重新解释；小于具体解释上限的全图也重新核对。提升前固定关系上的检查不能冒充真实有界路径的数量证据。

因此，`COUNT>4`与`length(p)=2`会共同约束至少五条有效二跳路径，而不是先配一张默认图、再调整COUNT阈值或查询长度。三值ALL的原生AST验收使用同一条公共求解路线，但不要求其必须带有扩张工作目标。

### 17.3 工作目标与扩张证书

`auto`工作轴从被标记路径的真实正合取ALL过滤中选择增长位置；ALL被`OR TRUE`绕过时不能提供这项证书。当前增长族要求长度至少为2，在TRUE起点之后插入共享的显式FALSE内部节点，并在其后增加分离的路径后缀。端点同时保留商图中失败候选的局部谓词值，以保留既有读取域排除证书。每条新增路径经过FALSE节点，因而有效路径数与外层结果保持不变；共享前缀的数量不随候选规模增长。

这项证书依赖实际图族及完整查询的读取范围。额外同类型关系读取、无标签扫描、端点标签扫描、未受保护的第二词法路径不能仅凭小图结果不变放行。两个不同词法路径即使都叫`p`，也不能被当作一个数量原子。关系唯一性与树中的唯一路径保证TRAIL不会绕过失败节点或把后缀重组为新的有效路径；当前不把这项证明借给一般WALK或零跳构造。

真实路径检查包括逐逻辑输入的过滤后匹配数、未过滤候选数、已选长度和ALL三值事实；具有显式标量目标时，另外要求所观察的实际行域非空。算法2将这些检查加入必需装载检查，使用算法1接受的同一图、符号赋值与标记进行路径镜像。它不改变长度、阈值或路径数量。

### 17.4 当前边界与剩余人工内容

当前路径构造证书覆盖一条物理有界路径及其变异副本、1–8跳的TRAIL/ACYCLIC树族、分离的起终点标签和统一的已选长度；公开语法仍将路径预算限制在1–6跳，无增长目标时可以使用单跳。增长工作要求至少二跳。一般多路径连接、环结构、不同路径混合长度、任意逐节点真假向量、可NULL导入的OPTIONAL路径和一般WALK仍没有构造证书，不能宣称已支持任意路径语义。共同TRUE起点/内部赋值与固定树提升族仍限制语义空间：ALL谓词恒为FALSE或NULL时，即使存在合法有限模型，也会因没有共同TRUE赋值被保守拒绝；涉及UID的谓词尚无仿射内部节点证明，也被拒绝。失败前缀位置当前取最早内部点1，是该族的固定策略，尚未根据一般前缀代价约束求最优失败位置。这些属于算子构造策略，而不是对论文等价律的新增前提。

本批后共有11个论文ID进入目标路线，剩余12项为P1、P2、P6、P7、P8、P9、P12、S5、S6、S8、S9、S10。局部变异律、有限语法/模式候选、值域与搜索预算仍由人工维护。公开ALL叶子仍从`keep`属性的三种布尔谓词形式中选择；构图规则不识别该属性名，原生AST的改名与否定谓词另有验收。仅`composition`/`paper-v1`的P3新生成入口已使用统一目标路线；没有`composition`的legacy默认入口仍保留旧模板与`GraphSpec` v1配方，旧路径有限搜索接口也继续兼容。新入口不再使用旧的独立路径全查询试配器，不能据此宣称仓库所有P3调用均已迁移。
