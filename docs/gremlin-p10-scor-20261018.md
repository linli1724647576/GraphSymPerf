# P10 扩规模复测与 S1–S10 Gremlin 接入

本轮继续使用 ArcadeDB 26.10.2、TinkerPop 3.8.2、默认 Java Gremlin 引擎和此前的专用实例。只使用已有 Pattern、图配方、候选池、变换和测量流程；没有新增索引设计、Native 性能探针或数据拓扑。前轮证据见 [首轮记录](gremlin-experiment-20261018.md)。

## P10 的复测设计

对种子 0–63、复杂度 0／1／2 的 192 次离线生成进行去重后，实际只有 **6 种不同查询对**。P10 的复杂度参数在此只改变角色选择，不增加嵌套表达式。`complexity=0, seeds=[0,1,2,3,4,5]` 覆盖全部六种；历史 seed 17 与 seed 5 等价。不能把重复种子说成新增机制覆盖。[枚举证据](../results/gremlin-p10-scor-20261018/p10-seed-inventory.json)

| seed | Low 约束 | High 分支谓词 |
|---:|---|---|
| 0 | 属性映射 | `keep = true` |
| 1 | WHERE | `keep = true` |
| 2 | 属性映射 | `NOT(keep = false)` |
| 3 | WHERE | `NOT(keep = false)` |
| 4 | 属性映射 | `coalesce(keep,false) = true` |
| 5 | WHERE | `coalesce(keep,false) = true` |

主矩阵采用 `scale=30000/100000/300000`、六个种子、`data_seed=0`，共 18 个输入；再在 `scale=100000, data_seed=17` 下重复六种变体。节点数为 `5N+3`，边数为 `4N+1`。`data_seed` 只改变噪声 uid 偏移，不改变拓扑、基数、选择率或插入顺序，因此只算数据标识变化的复测。

原阈值保持不变：2 倍初筛；确认时配对中位倍率至少 5、95% bootstrap 区间下界至少 5、中位差值严格超过 100 ms、方向一致性至少 0.95、差值超过同查询噪声；报告前再检查两次独立确认分别满足倍率和差值门槛。未通过初筛的输入不会被描述为已经独立确认。

原态的 A/B 都需要执行 High 分支，B 的后续图扫描另外错过类型／索引替换。两侧共有大量随规模增长的工作，故增加规模不保证倍率增加。没有用 `empty_low` 的正常提前停止差异代替漏索引的因果证据。

## S1–S10 接入范围

这些是仓库已经存在的 SCor 适配模板，不是新 Pattern。S1、S2、S4–S10 的表达式生成原本已具备，新增实现集中于 S3：把顶层 `ConditionalQuery` 编译成一次输入注入和 `choose()`，仅 TRUE 选择 THEN，FALSE／NULL 选择 ELSE；保留两个分支及各自结果多重集，不提前折叠实验分支。执行器只在 Cypher 路径探测 Cypher 25，避免将源模板元数据误当作 Gremlin 的版本要求。

本轮仅对 **ArcadeDB Gremlin** 开放 S1–S10 的已验证能力名单；不能将这轮接口与性能结论归到尚未进行相同实测的 JanusGraph／HugeGraph。共用编译器的离线生成测试不等于跨数据库验证。

性能测试前，接口门禁通过了 10 项 S 模板 × 9 个代表种子 × 3 档复杂度的 270 项小图检查，以及 12 项条件查询、5 项非空预期的 NULL-safe 成员检查、3 项 `coalesce` 假值非 NULL 检查，共 290 项。代表种子为 `0,1,2,3,6,9,18,27,54`，覆盖不同返回行数、非空前缀、COUNT／EXISTS、根键及计数谓词形式。每项 S 模板检查构图、成本事实、完整类型敏感结果多重集、PROFILE、重连、重建和归档读回；语义检查不会计入性能贡献。收尾审查再补充并通过 1 项“运行表达式产生 NULL 的条件守卫”检查，合计 **291 项**；13 项条件查询的未选分支标记均实测为 `elements=traversers=0`。

S4 的 NULL 条件选择 ELSE；S6 的 LIMIT 1–3 保留重复常量行；S7 的 0、FALSE、空字符串都属于非 NULL；S10 沿用 DISTINCT 与 NULL-safe EXISTS／NOT EXISTS 适配，不改称原生集合算子。只有实际接口门禁通过后，才运行 S1–S10 的扩规模性能测试。

## P3、P7、P13、P16 为什么仍未开放

四项都保持原有拒绝边界，详见 [逐项说明、源码与反例](gremlin-pattern-boundaries.md)。P3 缺关系不重复的路径语义与路径表达式生成；P7 与当前单标签模型不匹配；P13 缺 OPTIONAL 的 NULL 延展和可空变量绑定；P16 缺列表、拼接、范围及 ALL 的三值标量编译。不能用相似 Gremlin 步骤机械替代，或换一个图模型后宣称复用了原机制。

## 执行结果

**P10 未达到阈值；S1–S10 中确认两个可报告的优化遗漏，分别登记为 ArcadeDB Gremlin BUG003（S8）和 BUG004（S5）。** 两份报告均完成规模缩减、独立重建和原存档重放，状态为本地复现，未提交上游。S6 提供与 S8 相同的邻居物化根因佐证，不另增一个 BUG。原始配置与证据保存在 `results/gremlin-p10-scor-20261018/`。

### P10：计划遗漏仍在，倍率不够

24 个输入全部为 `no_candidate`，144 对普通初筛样本均低于 2 倍初筛门槛；最大配对中位倍率为 **1.30585×**。因此没有执行 P10 的独立确认，也没有为它计算确认置信区间。最大图包含 **1,500,003 个顶点、1,200,001 条边**。

| seed 0 的图规模 N | data_seed | B/A 配对中位倍率 | 配对中位差值 |
|---:|---:|---:|---:|
| 30,000 | 0 | 1.21303× | 57.77 ms |
| 100,000 | 0 | 1.12467× | 125.46 ms |
| 300,000 | 0 | 1.23003× | 772.15 ms |
| 100,000 | 17 | 1.17693× | 164.94 ms |

12 个属性映射约束案例中，A 使用 Low 的属性索引，B 的后续 GraphStep 扫描全图；12 个 WHERE 对照中，A/B 均包含原始图扫描，不能全部称作“B 漏索引”。在最大 seed 0 案例中，B 的原始图扫描输出 1,500,003 个顶点；但 A/B 都承担 High 分支的大量共同工作，绝对差值扩大没有带来 5 倍倍率。故**没有新增 P10 报告**。[全部 24 例复算及计划](../results/gremlin-p10-scor-20261018/p10-final-audit.json)

### S1–S10：完整矩阵与严格筛选

主矩阵为 N=10,000／100,000 × 九个种子 × 十个 S Pattern，共 **180 个输入**，每项 Pattern 18 个；复杂度与数据种子均为 0。它们对应 **58 个不同 IR 查询对、51 个不同的编译后含绑定查询对**，不能称为 180 种语义变体。S1–S4、S7、S9、S10 的 126 例均未通过初筛；S5／S6／S8 的 54 例中，42 例未确认、12 例自动标记为耗时观察。

独立逐样本复算核对了 3,240 对普通测量、2,160 对同查询控制、2,340 项已保存状态检查及 360 份原生计划。12 个耗时观察中只有 5 个同时满足逐次确认的倍率及差值要求：S5 的 seed 1／3／9／27，S6 的 seed 54。其余案例全部保留，并明确降级；例如 S6 seed 3 在 N=100,000 的第二次确认只有 92.35 ms。性能归档保存结果条数和每次类型敏感校验的成功状态，但没有保存每次 A/B 的全部原始输出行，离线审计不宣称重新比较了不存在的行数据。[完整审计](../results/gremlin-p10-scor-20261018/scor-final-audit.json)

随后只调整既有模板的 N，执行 5 个验证／缩减输入与 2 次同输入重放，共 7 个运行记录；其中一个 N=100,000 的 S5 输入与主矩阵重复。S8 在 N=200,000 时虽然达到 23.86×／200.99 ms，却因同查询噪声 p99=306.76 ms 未通过，未隐藏或丢弃。S6 在同规模通过；S8 在缩减至 N=150,000 后通过，S5 在缩减至 N=50,000 后通过。两份规范报告均采用随后**原存档重放**的完整 40 对普通计时：

| 报告 | 既有 Pattern／种子／N | A/B 配对中位倍率 | 95% CI 下界 | 配对中位差值 | 同查询噪声 p99 |
|---|---|---:|---:|---:|---:|
| [BUG003](../BUG%20list/ArcadeDB/S8/BUG003.md) | S8／3／150,000 | 26.65743× | 24.79238× | 154.79 ms | 89.60 ms |

### 两个根因与报告证据

- **BUG003：邻居提前物化。** S8 的原生 VertexStep 两侧各输出一个顶点，但实际 build 的 `ArcadeVertex.vertices()` 在返回迭代器前先包装全部匹配邻居，令上层 EXISTS 的停止来不及避免内部工作。最终数据对应 HIGH 600,000 个匹配邻居、REF 3 个；这是源码与图态的推导，不是 PROFILE 对象分配或物理 I/O 计数。S6 的 LIMIT 走相同桥接路径，按根因合并。[源码与边界](gremlin-neighbor-materialization-audit.md)
- **BUG004：恒空子遍历未向前传播。** `filter(__.limit(0))` 对任意输入都为空；本例前缀只有读取、局部路径标签，后缀投影不会从空输入产生结果。计划仍先消费 200,000／3 个邻居再全部丢弃。这是对当前纯读遍历安全适用的空传播优化缺失，不要求已有规则曾承诺处理；即使修复惰性邻居包装，该过滤仍会要求上游全部输入，故与 BUG003 分开。[安全性、固定源码及有限去重](../results/gremlin-p10-scor-20261018/s5-audit.md)

两份正文中的 Python 建图代码分别从空库真实执行，随后通过原状态检查、原生索引检查和存档 A/B 原生完整结果检查。S8 返回 `[{"c0":1}]`，S5 返回 `[]`；报告中的普通计时取自正式重放，未采用这次独立脚本的单次耗时。完整原生 PROFILE 与普通样本分别保留，报告按 `BUG list/AGENTS.md` 的四节英文格式编写；有限上游检索未识别精确重复，不声称穷尽或首次发现。

最终离线回归 **1,362 passed，640 deselected**。`generator.py`、`mutator.py`、`state.py`、`ir.py` 与本轮起点保持一致；只新增目标接口／编译能力及验证，没有新增 Pattern、数据拓扑或 Native 性能探针。根目录 `bugs.csv` 与本轮作用域登记表只增加两个经过完整复验的代表输入，重放不重复计入发现吞吐；合并统计见 [本轮汇总](../results/gremlin-p10-scor-20261018/summary/summary.csv)。所有测量结束后关闭本轮专用容器，保留数据与证据。
