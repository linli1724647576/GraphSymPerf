# AST 与 Pattern 六阶段实现验收记录

日期：2026-10-26。方法版本：`ast-pattern-v1`。本文记录本次工作区实现、Git 边界和实际验收，不将构造成功或结果相同计为性能缺陷。

## 1 实现范围

默认 `main.prepare_case()` 与 CLI 运行入口使用 `ast-pattern-v1`。M1 在不知道 Pattern 和具体图状态的情况下生成子句骨架，再递归展开有类型的宿主结构。M2 选择兼容端口并嵌入局部规则；M3 联合求解源与备选的终端赋值和 GraphSpec v2；M4 只落实接受的终端；M5 执行一个指定变异；M6 校验根部结果关系，分析求值需求、输入域、外层模式及共享图读取。

论文目录 P1–P13、S1–S10 全部接入；P10 支持 independent、shared_anchor、chain。规则的局部语法仍由 Pattern 注册表定义，通用构图器依据匹配、路径、标量和绑定需求构图。新入口构造失败保存阶段与原因，不回退旧模板。

新增代码位于 `Src/ast_pattern/`。原 `symbolic.instantiate_pair()` 拆出源实例化与变异两个独立步骤，同时保留旧包装函数。历史用例通过显式 `legacy-v1` 或 `symbolic-v1` 入口和配置继续使用原断言；新管线另有独立验收测试。

新案例使用归档格式 4，包含 M1–M6 记录、摘要链、图与联合绑定、实际编译查询、依赖证书及源码指纹。执行前重新从 IR 编译并核对实际文本、参数和元数据。读取或直接执行时，阶段缺失、输入漂移或必要检查被删除均被拒绝。执行回放不重新生成；生成再现要求源码指纹一致并比较各阶段摘要。

## 4 审查修正

本次使用独立的规范检查与方法合同检查，修正了以下有复现的问题：

- 随机外层 WITH 的变量未被旧局部前提检查保留：改为沿实际词法定义链封闭观察。
- MATCH 及关系类型元数据的跟踪地址不一致，导致 P8/P10/P11 被误判不可达：将其连接到实际匹配请求。
- 实际 Cypher 文本与 IR 证书脱离、直接执行绕过阶段链：在连接数据库前校验完整阶段、重新编译的文本及参数。
- 格式 4 回放重新编译时被降为格式 3：保留新归档版本。
- 结构摘要抹去 AND/OR、函数名和方向差异：保留运算语义字段，只规范化终端与标识符。
- OPTIONAL 实体属性投影丢失可空性、嵌套子句绕过能力限制：补全类型传播及递归能力检查。
- 将压缩证明图中的计数写为完整图精确数量：保留 `proof_model_*` 观察，完整图没有数量证书时使用未知区间。
- 共享图读取仅覆盖关系类型：增加节点标签、无标签、多标签实体域与别名属性读取。
- 外层 COUNT/EXISTS 仅消费行数或见证时，内部未使用的 RETURN 值被当作有需求：增加投影需求检查，并为标量规则提供保留其值观察的插入方式。
- EXISTS 的保留 UNION 分支见证不能推广到一般随机宿主：增加正数量义务、实际输入覆盖及增长读域独立性证书，并保留加载后的检查。

## 5 当前边界

首版生成一个显式目标端口，支持声明的行流、整数和布尔接口；M6 可以识别外层已有运算结构满足的模式前提。原生标量规则的自由 guard/prefix/payload 使用符号字面量，图工作子查询在内部绑定锚点；宿主节点导入型 native guard 尚未接入。多个显式 Pattern 同时嵌入与同时变异仍需要额外组合接口和证明。

图构造和解释验证均限定在当前语法和有限搜索预算内。不支持与预算耗尽分别记录，不将未知解释为无解。新显式状态加载首先验证 Neo4j；其他后端通过显式历史配置保留既有支持范围。

M6 的逻辑输入机会与物理调用次数分开。执行器保存真实结果、计划和计时证据；没有可靠的 AST 到物理算子映射时，局部物理调用次数仍为未知。压缩证明图保证的结果关系不能直接推出完整图的精确输入数量或运行时间下界。

本轮 CLI 接受运行用于检验管线与归档，不产生新的 BUG 数量结论。
