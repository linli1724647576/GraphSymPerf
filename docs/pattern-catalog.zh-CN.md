# 测试模式变换及适用条件

**表 1：测试模式变换及其适用条件。SC 表示短路类，SY 表示对称类。**

`D_T`、`D_F` 分别表示对每个适用输入绑定都为真、为假的决定项，变换前后保持不变。`E_L`／`E_H`、`Q_L`／`Q_H` 分别表示低／高潜在工作量的表达式和查询。`Q_0` 是不变的见证查询，`c` 是固定的常量结果行。`↦` 表示受决定条件保护的替换，`↔` 表示对称变换。所有形式均为只读查询，保持输出接口一致，并在同一张图上按多重集（multiset）语义比较结果，即保留重复行数量。

| 编号 | 类型 | 变换形式 | 适用条件 |
| --- | --- | --- | --- |
| SC1 | SC | `D_T OR E_L ↦ D_T OR E_H` | 决定项在每个输入绑定上均为真且保持不变；替换前后的表达式均返回布尔值或 null。 |
| SC2 | SC | `D_F AND E_L ↦ D_F AND E_H` | 决定项在每个输入绑定上均为假且保持不变；替换前后的表达式均返回布尔值或 null。 |
| SC3 | SC | `CASE WHEN D_T THEN V ELSE E_L END` ↦ `CASE WHEN D_T THEN V ELSE E_H END`<br>或<br>`CASE WHEN D_T THEN V WHEN E_L THEN V ELSE V END` ↦ `CASE WHEN D_T THEN V WHEN E_H THEN V ELSE V END` | 首个真条件及其选中的结果保持不变。替换未选结果时，结果类型须兼容；替换后续 WHEN 条件时，表达式须返回布尔值或 null。 |
| SC4 | SC | `coalesce(NULL, V, E_L) ↦ coalesce(NULL, V, E_H)` | `V` 在每个输入绑定上均非 null 且保持不变，false 和 0 也属于非 null 值；各参数类型兼容。 |
| SC5 | SC | `MATCH L RETURN c LIMIT 0` ↦ `MATCH H RETURN c LIMIT 0` | 两侧均保留 `LIMIT 0`，替换只读匹配部分后，输出仍为空。 |
| SC6 | SC | `(Q_0 UNION ALL Q_L) LIMIT k` ↦ `(Q_0 UNION ALL Q_H) LIMIT k`<br>或<br>`MATCH L RETURN c LIMIT k` ↦ `MATCH H RETURN c LIMIT k` | `k > 0`。UNION 形式中，`Q_0` 为每个输入绑定提供至少 `k` 行；直接 LIMIT 形式中，两个区域为每个适用锚点保留 `k` 个共用见证匹配。所有分支均返回相同的常量行 `c`，从而保持返回值和重复次数一致。 |
| SC7 | SC | `[NOT] EXISTS { Q_L }` ↦ `[NOT] EXISTS { Q_H }` | EXISTS／NOT EXISTS 要求两侧对每个输入绑定都至少有一条匹配。 |
| SC8 | SC | `MATCH A WHERE FALSE MATCH L RETURN c` ↦ `MATCH A WHERE FALSE MATCH H RETURN c` | 保持前面的必选空输入不变；中间不能出现聚合等从空输入重新产生结果行的子句。 |
| SY1 | SY | `E_1 AND E_2 ↔ E_2 AND E_1` | 两个表达式均返回布尔值或 null，且在同一输入上确定、可正常求值。仅交换位置，表达式本身及其读取的数据保持不变；交换律对 true、false 和 null 都成立。 |
| SY2 | SY | `E_1 OR E_2 ↔ E_2 OR E_1` | 两个表达式均返回布尔值或 null，且在同一输入上确定、可正常求值。仅交换位置，表达式本身及其读取的数据保持不变；交换律对 true、false 和 null 都成立。 |
| SY3 | SY | `(u)-[:T]->(v) ↔ (v)<-[:T]-(u)`<br>或<br>`(u)-[:T]-(v) ↔ (v)-[:T]-(u)` | 保持端点身份及约束、关系类型和方向含义；已绑定的关系仍须指向同一条边。若路径被命名，外层对它的观察须在反转前后保持不变。 |
| SY4 | SY | `p=(u)-[:T*1..b]-(v) ↔ p=(v)-[:T*1..b]-(u)` | 路径无向且长度有界，`b` 为 2–4。保留端点约束及 `all(x IN nodes(p) WHERE x.keep = true)`。仅允许长度、与节点顺序无关的谓词等反转不变的路径观察，不直接观察完整路径序列。 |
| SY5 | SY | `MATCH A MATCH B ↔ MATCH B MATCH A`<br>或<br>`MATCH A, B ↔ MATCH B, A` | 两个匹配均为必选且相互独立，不使用对方新引入的变量；两个分量可以是两条子句，也可以是同一 `MATCH` 中逗号分隔的两个部分；局部约束、输出绑定和重复行数量保持不变。 |
| SY6 | SY | `MATCH (u)-[:R]->(a) MATCH (u)-[:S]->(b)` ↔ `MATCH (u)-[:S]->(b) MATCH (u)-[:R]->(a)` | 两个必选分支只共享 `u`，均不依赖对方的私有变量；端点约束和重复行数量保持不变。 |
| SY7 | SY | `MATCH (u)-[:R]->(v) MATCH (v)-[:S]->(w)` ↔ `MATCH (v)-[:S]->(w) MATCH (u)-[:R]->(v)` | 两段必选匹配通过 `v` 连接，各段放在交换前后的位置都合法；局部约束、端点绑定和重复行数量保持不变。 |
| SY8 | SY | `MATCH A OPTIONAL MATCH B OPTIONAL MATCH C` ↔ `MATCH A OPTIONAL MATCH C OPTIONAL MATCH B` | 必选锚点 `A` 不参与交换。两个可选分支只共享该锚点，不存在跨分支依赖；保留未匹配时的空值扩展及重复行数量。 |

其中，`L`、`H` 表示低／高成本图匹配区域，`A`、`B`、`C` 表示匹配分量。带括号的 UNION 形式省略了施加外层 LIMIT 所需的 CALL 和投影；`[NOT]` 表示可带或不带 NOT，但变换前后须一致。本表定义 Cypher 变换形式，各目标支持的模式见[后端能力表](backends.md#capability-matrix)。Gremlin 实现全部 16 个测试模式，其中 SY3–SY8 嵌入在声明式 `match()` 步骤中（见[Gremlin 实现](architecture.zh-CN.md#6-gremlin-语言层)）。图构造提供潜在工作量差异，实际执行成本仍需通过运行验证。

## SC1/SC2 与 SY1/SY2 的区别

SC1/SC2 利用布尔吸收律，固定决定项和操作数位置，将 `E_L` 替换为 `E_H`。两个工作项可以返回不同的值，因为决定项已经确定整个表达式的结果。测试改变的是受保护部分的潜在工作量。

SY1/SY2 有两种实例。`guard_swap` 把决定项与一个工作项交换，SY1 使用假决定项，SY2 使用真决定项。`predicate_swap` 从同一个布尔候选分别生成读取 low、high 区域的两个谓词，再交换它们。例如两个计数谓词可以同时为真，此时 AND 的等价性仍由交换律保证。

| 对比项 | SC1/SC2：工作项替换 | SY1/SY2：操作数交换 |
| --- | --- | --- |
| 等价依据 | 决定项使整体结果与被替换项无关 | 同一对操作数满足交换律 |
| 改变什么 | `E_L` 换成 `E_H` | 两个表达式的位置互换 |
| 保持什么 | 决定项、操作数位置及整张图 | 两个表达式及整张图 |
| 比较的执行成本 | 低成本与高成本工作是否仍被执行 | 固定两个操作数，比较交换前后的执行成本 |

两类变换分别改变工作量和操作数位置。例如，若数据库总是先执行图查询表达式再计算 OR，SC1 可因 low/high 规模差异产生耗时差距，SY2 两侧则都执行同一个 `E_H`。若求值策略受操作数顺序影响，SY2 也可能观察到差异。执行计划和根因分析用于判断两类模式的报告是否对应同一缺陷。

## 一次用例怎样构造

先生成宿主查询，在作用域和类型允许的位置嵌入模式。生成器为该用例选定候选，用候选生成查询片段并在背景图上构造局部区域。名字和常量在创建时固定。构图完成后，在查询副本中施加表 1 的变换。两侧共用图、索引和参数；运行时先核对输出列及带重复次数的完整结果，再比较耗时和执行计划。

| 模式 | 用例中选择的候选 | 图上固定什么、扩张什么 |
| --- | --- | --- |
| SC1/SC2，SY1/SY2 | 一跳计数、两跳计数、无匹配存在性判断 | low 每锚点有一个候选末端，high 按锚点分配总预算。计数候选的末端通过过滤，无匹配候选的末端全部失败。需要图见证的决定项单独取证。 |
| SC3/SC4 | 根据被替换位置的类型选择表达式 | 布尔位置可用三种表达式。整数、浮点数和字符串位置使用一跳或两跳计数，并按类型转换。SC3 固定首个命中条件及其返回值，SC4 固定非空前缀。 |
| SC5–SC8 | 返回常量行的一跳或两跳匹配 | 扩张可替换分支的完整匹配数。零需求、有限行数、存在性见证或前置空输入分别约束可观察的输出，具体条件见表 1。 |
| SY3 | 从选定端点扩张，或从不满足端点条件的同标签节点扩张 | 后一种布局为选定端点留一条有效边，其他边集中到干扰节点上。两种布局都保持原边的存储方向。 |
| SY4 | 在共享中间点或各分支末端设置失败谓词 | 保留一条通过谓词的两跳路径。另造的有界路径在不同深度遇到 `keep=false`，两侧保留同一个全路径条件。 |
| SY5 | 让左侧或右侧独立匹配具有选择性 | 选定分量命中零个或一个节点；另一分量增加 N 个候选节点。 |
| SY6 | 在共享根的左臂或右臂扩张 | 一臂有一条匹配边，另一臂有 N 条。 |
| SY7 | 脱离完整链的右段分别使用独立中点，或共用一个中点 | 保留一条完整链。新增 N 条右段边，其起点都无法接上选定根的左段。 |
| SY8 | 扩张两个可选分支中的左侧或右侧 | 固定四个根，分别覆盖双侧命中、仅左、仅右和双侧缺失。把 N 个额外匹配分配到能命中所选分支的根上。 |

归档中的 `work_candidate` 标记表达式或行源，`graph_candidate` 标记 SY3–SY8 的图布局。N 的单位取决于候选，例如两跳计数按完整匹配分配，SY7 按新增右段边分配。数据库实际访问的边数需要从具体执行中核对。
