# Path-node checks do not prune failed repeat prefixes

## Describe the situation

Hi, JanusGraph developers,

Please consider these two queries:

q1:

```groovy
g.inject(1)
    .V()
    .hasLabel('GspLow')
    .has('id', P.eq(_gsp_p0))
    .as('_gsp_v0')
    .as('_gsp_tmp0')
    .repeat(
        __.as('_gsp_tmp2')
            .union(
                __.outE('GSP_LINK')
                    .as('_gsp_tmp1')
                    .filter(
                        __.select(Pop.all, '_gsp_tmp1')
                            .unfold()
                            .where(P.eq('_gsp_tmp1'))
                            .count()
                            .is(P.eq(1))
                    )
                    .inV(),
                __.inE('GSP_LINK')
                    .as('_gsp_tmp1')
                    .filter(
                        __.select(Pop.all, '_gsp_tmp1')
                            .unfold()
                            .where(P.eq('_gsp_tmp1'))
                            .count()
                            .is(P.eq(1))
                    )
                    .outV()
                    .where(P.neq('_gsp_tmp2'))
            )
            .as('_gsp_tmp0')
    )
    .emit(
        __.loops()
            .is(P.gte(1))
    )
    .times(3)
    .hasLabel('GspHigh')
    .as('_gsp_v1')
    .project('_nodes', '_length')
    .by(__.select(Pop.all, '_gsp_tmp0'))
    .by(
        __.coalesce(
            __.select(Pop.all, '_gsp_tmp1')
                .count(Scope.local),
            __.constant(0)
        )
    )
    .as('_gsp_v2')
    .select('_gsp_v1')
    .filter(
        __.map(
            __.coalesce(
                __.select('_gsp_v2')
                    .is(P.neq(null))
                    .select('_nodes'),
                __.constant(null)

        )
            .is(P.neq(null))
            .filter(
                __.not(
                    __.unfold()
                        .as('_gsp_v3')

                            __.select('_gsp_v3')
                                .values('keep')
                                .is(P.eq(_gsp_p1))
                        )
                )
            )
    )
    .project('c0', 'c1', 'c2')
    .by(
        __.select('_gsp_v0')
            .coalesce(__.values('uid'), __.constant(null))
    )
    .by(
        __.select('_gsp_v1')
```
```groovy
            .coalesce(__.values('uid'), __.constant(null))
    )
    .by(
        __.coalesce(
            __.select('_gsp_v2')
                .is(P.neq(null))
                .select('_length'),
            __.constant(null)
        )
    );
```

I traverse the same undirected trails from opposite endpoints and check that all path nodes have `keep=true`. Both queries return the same one row, including its path length. On the graph below, q2 takes about 13.91 times as long as q1 and extends paths after they have already reached a node with `keep=false`.

## Which JanusGraph versions are affected?

I reproduced this on JanusGraph 1.1.0 with Apache TinkerPop 3.7.3, using Gremlin-Groovy over HTTP, BerkeleyJE storage, and a 4 GiB JVM heap in an ARM64 Docker container on macOS. The client and server evaluation limits were 30 seconds.

## How to reproduce

Start with an empty JanusGraph graph and fresh schema. Run these commands with its traversal source bound to `g`.

```groovy
def graph = g.getGraph()
graph.tx().rollback()
def m = graph.openManagement()
['uid', 'id'].each {
    m.makePropertyKey(it).dataType(Long.class)
        .cardinality(org.janusgraph.core.Cardinality.SINGLE).make()
}
['keep'].each {
    m.makePropertyKey(it).dataType(Boolean.class)
        .cardinality(org.janusgraph.core.Cardinality.SINGLE).make()
}
['_gsp_identity'].each {
    m.makePropertyKey(it).dataType(String.class)
        .cardinality(org.janusgraph.core.Cardinality.SINGLE).make()
}
['GspLow', 'GspMiddle', 'GspHigh', 'GspBad'].each { m.makeVertexLabel(it).make() }
['GSP_LINK'].each {
    m.makeEdgeLabel(it).multiplicity(org.janusgraph.core.Multiplicity.MULTI).make()
}
m.buildIndex('gsp_internal_identity', org.apache.tinkerpop.gremlin.structure.Vertex.class)
    .addKey(m.getPropertyKey('_gsp_identity')).unique().buildCompositeIndex()
m.buildIndex('gsp_cost_lookup_GspLow_id', org.apache.tinkerpop.gremlin.structure.Vertex.class)
    .addKey(m.getPropertyKey('id')).indexOnly(m.getVertexLabel('GspLow')).buildCompositeIndex()
m.commit()

def low = g.addV('GspLow').property('uid', 1L).property('id', 1L)
    .property('keep', true).property('_gsp_identity', 'GspLow:1').next()
def middle = g.addV('GspMiddle').property('uid', 2L)
    .property('keep', true).property('_gsp_identity', 'GspMiddle:2').next()
def high = g.addV('GspHigh').property('uid', 3L)
    .property('keep', true).property('_gsp_identity', 'GspHigh:3').next()
def bad = g.addV('GspBad').property('uid', 0L)
    .property('keep', false).property('_gsp_identity', 'GspBad:0').next()
low.addEdge('GSP_LINK', middle)
middle.addEdge('GSP_LINK', high)
low.addEdge('GSP_LINK', bad)
(1L..200L).each { i ->
    long uid = 895440L + 2L * i
    def branchMiddle = g.addV('GspMiddle').property('uid', uid)
        .property('keep', true).property('_gsp_identity', 'GspMiddle:' + uid).next()
    def branchHigh = g.addV('GspHigh').property('uid', uid + 1L)
        .property('keep', true).property('_gsp_identity', 'GspHigh:' + (uid + 1L)).next()
    bad.addEdge('GSP_LINK', branchMiddle)
    branchMiddle.addEdge('GSP_LINK', branchHigh)
}
graph.tx().commit()
```

Run q1 and q2 with `_gsp_p0` bound to `1` and `_gsp_p1` bound to `true`.

The `GspLow` vertex with `uid=1` has a valid two-edge trail through `GspMiddle(uid=2)` to `GspHigh(uid=3)`. It also connects to `GspBad(uid=0, keep=false)`. Beyond that vertex are 200 separate Middle-to-High branches. All other vertices have `keep=true`. The edge-identity check preserves TRAIL semantics, including distinct parallel edges, and allows vertex revisits.

For q1, I get one row:

```json
[
  {
    "c0": 1,
    "c1": 3,
    "c2": 2
  }
]
```

Median runtime: **13.570770 ms**.

For q2, I get one row:

```json
[
  {
    "c0": 1,
    "c1": 3,
    "c2": 2
  }
]
```

Median runtime: **182.579020 ms**.

I used two sessions with an independent graph rebuild before each, five warm-up pairs and 20 balanced AB/BA pairs per session, and ten same-query control pairs for each side per session. Ordinary HTTP timing includes complete result retrieval and decoding; I collected `profile().next()` separately. Across the 40 ordinary pairs, the median paired q2/q1 ratio was **13.910900×**, the paired time difference was **169.025042 ms**, and the bootstrap 95% ratio interval was `[13.370845, 14.258182]`; the largest same-query control p99 was **40.087475 ms**.


Both queries apply the all-node check after `RepeatStep`; the check itself stops at the first false node. In q2, the 200 branch High vertices each reach the shared Bad vertex and then produce 200 further trails, including trails into the other Middle branches. Those 40,000 extensions cannot contribute a passing result because their prefix already contains `keep=false`. q1 starts at the single Low vertex and avoids this quadratic combination of branch starts and continuations, although it also checks completed paths.

## Expected performance

Please stop extending a path when its prefix contains a node with `keep=false`, while preserving TRAIL semantics, so q2 can skip the rejected combinations that q1 avoids through its starting endpoint.
