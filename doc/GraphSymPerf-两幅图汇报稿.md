# GraphSymPerf 方法汇报：两幅图与 P3／S3 案例

2026-10-22

> 第一幅图配一张能暴露优化机会的图，第二幅图在这张图上生成结果相同、只差一个局部变换的两条查询。下面按这两幅图走一遍流程，再用 P3 和 S3 各做一个完整例子。

## 1. 两幅图的分工

两幅图对应论文里的 Algorithm 1 和 Algorithm 2。

- 第一幅图（图状态生成）：输入骨架 S、模式 p、规模 N，输出共同图 G，或者拒绝。
- 第二幅图（查询生成与变异）：输入同一份 S、p、G，还可以带一个外层语境 C；输出查询对 (Q1, Q2)，或者拒绝。

两幅图之间靠 G 和一份构造记录（I）传递。G 是两条查询共用的同一张图；记录里存着角色绑定、成功/失败条件、数量和结构对应。第二幅图填空时只能引用这些已经成立的事实。

| 记号 | 含义 |
|---|---|
| S | 查询骨架：结构、空位、变量依赖、语义要求（含外层 COUNT、EXISTS 等）和变异位置 |
| p | 测试模式：允许的变换和适用条件 |
| N | 扩张规模，图中记作 s |
| L / H | 低成本 / 高成本角色。L 是能走索引的小邻域或常量，H 是一大批候选；说的是这次访问要处理多少候选，不是节点真假 |
| Q0 | 保留结果的见证分支，和 H 分开 |
| C | 可选的外层语境，比如把骨架放进 COUNT、EXISTS |
| I | 构造记录：角色绑定、成功/失败条件、数量和结构对应 |

```text
(S, p, N) ──图1──▶ G ──图2──▶ (Q1, Q2)
```

## 2. 第一幅图：先把图配出来，再把可避免的工作放大

| 行 | 步骤 | 做什么 |
|---|---|---|
| 1 | Init(S) | 建锚点、标签、关系名，定下哪些匹配共用节点、哪些分开 |
| 2 | Populate(G,S,L) | 填低成本区域：能走索引的小邻域，或不用读图的常量 |
| 3 | Populate(G,S,H,N) | 填高成本区域：候选节点、路径分支、匹配数量，规模由 N 控制 |
| 4–6 | SetGuards / AddWitnesses | 短路模式：守卫定分支或决定性取值；见证保证 Q0 的行数（S6）或存在性（S8） |
| 7–10 | Skew / Preserve | 对称模式：Skew 调标签频率、邻域度数、分支基数；Preserve 保住反向边配对和分支独立 |
| 11 | AddIndexes | 给 L 建选择性入口 |
| 12–15 | Validate / Reject / return | 检查模式条件，不满足就拒绝，否则返回 G |

这里有个容易忽略的细节：第4–10行是 if/else，不是四步都做。短路模式走守卫和见证，对称模式走 Skew 和 Preserve。P3 属于对称模式，S3 属于短路模式，下面两个例子刚好各走一条。

第5、6行容易混：

- SetGuards 决定“走哪一支”，或者“哪个值已经决定结果”。S3 里就是让 outer、inner 两个条件为真。守卫条件要对每个可用锚点都成立，不能只对原来那批成立。
- AddWitnesses 决定“要返回的结果确实存在”。S6 看行数，S8 看存在性；最简单的 S3 里，选中的“一行 0”本身就是见证，不用额外建节点。
- Q0 就是这条保留结果的见证分支。它要和 H 分开，扩 H 才不会把决定结果的事实冲掉。

## 3. 第二幅图：填好查询，只改指定位置

| 行 | 步骤 | 做什么 |
|---|---|---|
| 1 | Embed(C,S) | 放进外层语境（比如 COUNT、EXISTS），标记变异位置，确定哪些外层变量可见 |
| 2 | Instantiate(Q1,G) | 用 G 里的标签、关系、属性、条件填空；子查询按同样规则递归 |
| 3–5 | Applicable | 检查源查询是否满足 p 的前提，不满足就拒绝 |
| 6 | Copy(Q1) | 完整复制，保留外层条件和返回内容 |
| 7–11 | RaiseCost / Rewrite | 短路模式把 L 换成 H；对称模式交换端点、匹配次序 |
| 12–15 | ValidPair | 检查完整查询的结果关系，不满足就拒绝 |

实例化不是随便挑一个能跑的表达式。候选来自三处：骨架允许的语法和嵌套深度、当前位置能看见的变量、G 里真实的标签/关系/属性和取值。类型对不等于能填，还要保住构图时定下的条件。

RaiseCost 的一个例子是 S7：`coalesce(NULL, 0, 1)` 换成 `coalesce(NULL, 0, 统计所有终点)`。最后一项变贵了，但前面的 0 已经决定结果，两边都返回 0。

## 4. 案例一：P3（走对称分支）

### 4.1 第一幅图：三条路径，只有一条有效

骨架要求：从 s 出发找二跳路径，路径上所有节点 keep=true。

```text
s(T) — a(T) — t(T)    有效
s(T) — b(F) — x(T)    无效
s(T) — b(F) — y(T)    无效
```

T/F 是属性的真假，后两条共用 s 和 b。

- Init：建 s、a、b、t 四个锚点，边标成 LINK，s 是 Start，终点统一标成 End。
- Populate L：连出 s-a-t 这条成功路径，很小，能直接定位。
- Populate H：给 b 接上 x、y，再继续加，最终挂 N 个终点；它们都能匹配，但都过不了 ALL。
- Skew：从 s 分出去，a 这一支只有 1 个终点，b 这一支有 N 个，两边候选数不对称。
- Preserve：保留无向边的两个方向和端点对应；交换 s 和 v 之后，走的还是这些节点，失败路径仍然经过 b。
- AddIndexes / Validate：给 Start 建入口，检查成功路径全真、失败路径含 b。

结果：b 后面挂 N 个终点，候选就是 1+N 条，有效结果始终只有 t。如果执行时从 s 走到 b 就发现 false，b 后面不用展开；先展开再过滤，就得多处理 N 条。

Populate、Skew、Preserve 合起来做的，就是这件事：把候选撑大，同时守住结果成立的依据。

### 4.2 第二幅图：填空，再交换两端

- Embed：可选，比如套一层 COUNT 或 EXISTS。
- Instantiate：起点用 Start，终点用 End，关系用 LINK，节点条件用 keep=true。
- Applicable：P3 的前提是无向路径，两端可以互换；外层观察的量在反转后也要不变。
- Copy：Q2 先完整复制 Q1。
- Rewrite：交换两端。
- ValidPair：检查完整结果，两边都只返回 t。

```text
Q1: MATCH p = (s:Start)-[:LINK*2..2]-(v:End)
Q2: MATCH p = (v:End)-[:LINK*2..2]-(s:Start)

# 两条查询共用
WHERE all(n IN nodes(p) WHERE n.keep = true)
RETURN v.name
```

`*2..2` 就是二跳。两条查询看的是同一批节点，只是首尾互换。外层套 COUNT，两边都是 1；套 EXISTS，两边都为真。

边界：如果直接返回 `nodes(p)`，两条查询分别得到 `[s,a,t]` 和 `[t,a,s]`，元素一样但顺序不同，不满足多重集相等。所以这里只返回终点 v 的名字。

## 5. 案例二：S3（走短路分支）

### 5.1 骨架和图

两层条件，每个分支都返回一行，列名都叫 value：

```text
外层条件为真：
    内层条件为真：返回一行 0
    否则：返回一行 1        ← 只改这里
否则：返回一行 2
```

图很小：一个 u，挂两个 H 邻居，value 都是 9；outer、inner 两个属性由 SetGuards 设成 true。

- Init：建 u。
- Populate L：不用额外数据，L 是常量“一行 1”。
- Populate H：挂两个 H 邻居，按 N 继续加。
- SetGuards：outer、inner 都设为 true。
- AddWitnesses：选中的“一行 0”本身就是 Q0，不用再建节点。
- AddIndexes / Validate：u 能按标签或 id 定位，两个条件都为真。

### 5.2 第二幅图：只换内层的“否则”

- Embed：内层 CASE 放在外层 CASE 的 THEN 分支里。
- Instantiate：外层条件填 u.outer=true，内层填 u.inner=true，分支照骨架。
- Applicable：S3 的前提是有一个没被选中的分支可以换；列名和类型要兼容，值可以不同。
- Copy：完整复制 Q1。
- RaiseCost：把内层的“否则”从“返回一行 1”换成“沿 H 边取邻居的 value”，得到两行 9。
- ValidPair：两层条件都为真，两边都走“返回一行 0”，结果都是一行 0，外层数行都是 1。

为什么不变：先看内层。内层条件为真，原来和变异都选 THEN，根本没进被替换的分支。再看外层。外层也为真，两边都把内层这一行 0 原样返回。比较的是整个内层条件行流，不是“一行 1”和“两行 9”。

边界：内层条件一旦变成 FALSE 或 NULL，两边就会走进“否则”，一行 1 和两行 9 不同，这次变异就不成立。外层也设为真，是为了让查询真的执行到内层这个被改的位置。

## 6. 读图时要注意的三点

### 6.1 函数名只是概括

图中的 Init、Populate、Skew 都是动作标签，没有画出 AST 依赖分析、递归填充和逐层传递。详细算法文档把它们展开成：

```text
构图：沿依赖传递要求 → 保留见证 → 扩张候选 → 保持条件
查询：形成候选 → 递归填空 → 局部变异 → 把结果关系向外传
```

所以两幅图适合讲“做什么、为什么成立”，具体“怎么做到”在文档里。

### 6.2 外层语境要在构图前定

图2第1行才 Embed，容易让人以为外层条件可以最后再定。实际上，影响构图的要求——COUNT 阈值、EXISTS 真假、路径长度、非空前缀——必须先进骨架，否则图1不知道要配几条成功路径。

例子：只有一条成功路径的图能满足 COUNT=1，但不能满足 COUNT>2。Embed 只决定查询放在哪个语法位置、哪些外层变量可见、变异点在哪。

### 6.3 比较包含依据的完整结构

变异后不能要求 L 和 H 本身相等。P3 比整个匹配结果，包括端点和重复次数；S3 比整个内层条件行流；S7 比整个 COALESCE。外层观察的是这个完整结构的结果，不是被替换的参数。

## 7. 小结

先制造“有些工作可以避免”的图，再生成只差一个局部变化的查询对。结果保持靠模式语义和构图条件；数据库有没有真的避开这些工作，要靠执行结果和性能分析判断。
