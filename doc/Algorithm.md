# GraphSymPerf：图状态生成与骨架实例化算法

GraphSymPerf 围绕具体的遗漏优化（missed optimization）机会生成测试：先用图状态拉开不同访问或求值方式所需处理的候选规模，再构造结果相同的查询对，检验数据库能否避免其中多余的工作。

两个算法分别回答：**怎样配出能暴露优化机会的图，以及怎样把模式骨架填成访问这张图的查询对。** 第2节集中给出可用于论文正文的简洁伪代码；后续保留详细逐行解释及完整案例。

## 1. 两个算法如何连接

一个测试模式（pattern）给出局部变换及其适用条件。例如，P3 允许交换无向路径两端的书写位置；S7 允许在已有非空前缀的 `coalesce` 中，把后面可以跳过的低成本表达式换成高成本表达式。

查询骨架（query skeleton）将这个模式放入具体的运算结构，保留标签、关系类型、属性、谓词和子查询等空位。骨架还声明哪些变量共享、哪些条件必须成立，以及低成本角色 `L` 和高成本角色 `H` 分别位于何处。源形式和变异形式可能读取的区域，都包含在这份声明中。

**构图前固定语义要求，构图后选择满足要求的写法。** 例如，骨架先声明“二跳路径上的节点条件应接受成功见证、排除指定失败前缀”，算法1据此设置属性；算法2再选择表达这些条件的谓词。路径长度、COUNT 阈值、共享变量及子查询的消费关系也在构图前确定。若更换候选会改变这些要求，就将其作为新骨架重新进入算法1。

这里的成本角色描述预期的访问工作：`L` 可以是常量、唯一定位的节点或小邻域；`H` 可以是大量候选节点、较大的路径扇出，或读取这些区域的计算。节点本身没有固定的“高成本”或“低成本”属性，区别来自查询怎样访问它。

```text
选择 pattern，并确定完整骨架及外层语境
                    ↓
算法1：建立必要见证 → 安排 L/H 区域 → 扩大候选工作
                    ↓
             共同图 G 与构造条件 I
                    ↓
算法2：按依赖填充空位 → 得到源查询 → 局部变异
                    ↓
                 查询对 Q1、Q2
```

外层语境在构图前确定。例如，要求 `EXISTS` 为真时，其直接子查询需要产生至少一行；要求 COUNT 的值大于2时，被计数的子查询需要产生至少三行。算法1据此准备数据；算法2递归填充同一骨架，沿用这些要求。

| 记号 | 含义 |
|---|---|
| `S` | 完整符号骨架，包括既定嵌套结构、变量依赖、候选形式及语义要求、成本角色、源／变异形式和变异位置 |
| `p` | 选定的 pattern，规定变换及其适用条件 |
| `N` | 高成本区域的扩张规模 |
| `L`、`H` | 低成本和高成本角色，可以对应图区域、表达式或查询片段 |
| `Q0` | 保持结果所需的见证分支，与待替换的 L/H 分开 |
| `D` | 抽象语法树（Abstract Syntax Tree，AST）中的变量来源、共享绑定和结果使用关系 |
| `R` | 沿依赖传递的真假、非空性、数量及路径长度要求 |
| `G` | 原查询与变异查询共同使用的图状态 |
| `I` | 角色到图区域的对应，以及各相关输入上的必要事实：成功与失败条件、输出要求、匹配数量和变换对应关系 |
| `Q1`、`Q2` | 实例化后的源查询及其变异查询 |

每个规模下，查询对需要满足：

\[
\llbracket Q_1\rrbracket_{G_N}
=_{\mathrm{bag}}
\llbracket Q_2\rrbracket_{G_N}.
\]

其中，多重集相等保留重复记录、值的类型和 NULL；返回列表时还保留列表内部的顺序。扩张是否还保持跨规模的结果不变，取决于测试方式：P3 可以只增加被过滤的路径，使结果保持固定；匹配重排则可以增加双方共同返回的组合，用来扩大重复计算。

## 2. 论文正文用简洁伪代码

两个算法使用同一份完整骨架及其语义要求。算法1沿依赖把要求传向内部，再建立共同图；算法2消费图中的角色与事实，递归填充骨架并在标记处变异。以下均为逻辑操作，不指定实现方式。

### 2.1 算法1：共同图状态构造

**输入：**完整骨架 `S`、模式 `p`、规模 `N`。

**输出：**共同图 `G`、构造条件 `I`，或拒绝。

```text
 1: D ← 标明源／变异形式的变量来源、共享绑定和结果使用关系
 2: R ← S 与 p 要求的真假、非空性、数量及路径长度
 3: 沿 D 向直接生产者递归传递 R，逐层使用：
 4:     COUNT 区间→子查询行数；EXISTS 真假→非空／空
 5:     条件选择→守卫与所选分支；COALESCE→所需非空前缀
 6:     非 NULL 路径的 ALL 真／假／NULL→全真／含假／无假且含 NULL
 7: 合并共享绑定的要求及数量、长度约束；冲突则拒绝
 8: G ← 按 R 建立锚点、共享连接及各输入的行／路径见证
 9: 按 R 设置标签、属性和路径长度，为 L 提供选择性入口
10: 按 N 向 H 添加节点、边或匹配，按需组合以下增长规则：
11:     候选排除：赋失败值或省去连接，保留成功见证
12:     屏蔽／早停：保留相应守卫／非空前缀／Q0；LIMIT 须足行且同常量投影
13:     匹配重排：保持匹配对应及重复次数
14: 检查所有相关读取及新增输入；破坏 R 或 p 的条件则拒绝
15: I ← 记录角色绑定、成功／失败条件、数量及匹配对应
16: return (G, I)
```

第11—13行是可组合的结果保持依据。例如，P10 可增加无法连接的候选，同时保持连接对应；S3 可增加有效匹配，由守卫屏蔽它们。第12行中，EXISTS 需要 Q0 非空；LIMIT n 需要 Q0 至少 n 行，各分支同常量投影并保留重复记录。

### 2.2 算法2：递归实例化与局部变异

**输入：**同一骨架 `S`、模式 `p`、共同图 `G` 及条件 `I`。

**输出：**查询对 `(Q1,Q2)`，或拒绝。

```text
 1: Q1 ← 复制 S 的源形式，保留变异标记与共享绑定
 2: for 按定义—使用关系访问的每个未填空位 x do
 3:     V ← 用 S 的声明语法、可见变量及 G、I 的角色和取值形成候选
 4:     对子骨架递归执行第2—7行，继承输入，移除填充失败的候选
 5:     保留类型、作用域及 I 的成功／失败、数量和输出要求成立的候选
 6:     V 空则填充失败；否则选候选填入 x，复用共享绑定
 7: end for
 8: 若 Q1 不满足 p 则拒绝；Q2 ← 复制完整的 Q1
 9: if p 是短路模式 then
10:     用第2—7行填充已声明的 H，执行 L→H，保留决定性条件及所需见证／投影
11: else 在标记处应用 p 的对称变换，保留变量约束与投影
12: end if
13: E1、E2 ← 包含变异及其结果保持依据的完整局部结构
14: 按匹配对应、决定性条件或见证投影，逐输入建立 E1、E2 相同输出
15: 沿父算子的值、行数及顺序要求逐层传出；任一步无法保持则拒绝
16: 若 Q1、Q2 相同则拒绝
17: return (Q1, Q2)
```

第2—7行是唯一的递归填充过程，同时用于子骨架和 H 替代片段。子候选失败只移除该候选；整个源查询或 H 无法填充时才拒绝。第13—15行从完整局部结构开始：P10 比较连接结果，S3 比较包含守卫的整个条件行流，不能要求 L 与 H 本身相等。

## 3. 算法1详细说明与 P3 构图

### 3.1 构图思路

构图先保留使查询语义成立的少量结构，再扩大与优化机会相关的区域。例如，路径剪枝需要保留成功路径，同时在一个失败点后增加候选分支；短路测试需要固定决定结果的值，同时扩大本来可以跳过的计算。

骨架的 AST 用于识别这些结构之间的关系：两个匹配是否共享节点，条件依赖哪个变量，COUNT 统计哪段匹配，以及高成本计算的值是否会被外层使用。这些依赖与 pattern 的结果保持条件一起，约束哪些节点必须共用、哪些见证必须保留、哪些区域可以扩张。

| 要暴露的优化机会 | 图中保留什么 | 扩大什么 |
|---|---|---|
| 选择性入口与路径剪枝 | 少量入口、有效路径、能提前判定失败的节点 | 失败点之后的候选分支 |
| 短路求值与未选中分支 | 决定性真假、非空值或选中分支的结果 | 被屏蔽计算中的节点与有效匹配 |
| 提前结束 | EXISTS 的有效见证；LIMIT 的足够行及相同投影 | 已满足需求之后仍可能被继续读取的匹配 |
| 匹配顺序选择 | 两种顺序下相同的匹配及连接关系 | 会放大后续计算次数的输入或中间行 |

这些扩张遵循不同的结果保持理由。被过滤路径不能贡献有效结果；未选中分支可以有很多有效结果，但这些结果不能被外层观察；匹配重排可以增加结果数量，但两种顺序必须保留相同的组合与重复次数。

对于提前结束，EXISTS 和 LIMIT 需要分别处理。S8 保留独立见证分支 `Q0`，即可让存在性判断保持为真。S6 则要求 `Q0` 至少产生 n 行（n>0），且 `Q0`、待替换的 `QL` 和 `QH` 都投影为相同的常量行 c，不使用 DISTINCT。这样，`(Q0 UNION ALL QL) LIMIT n` 与替换后的形式都返回 n 份 c。仅有“足够行”不够：若一个分支返回0、另一个返回1，LIMIT 1 仍可能返回不同值。用于测试提前结束时，这些分支还应能逐行产生结果，避免排序或聚合要求先读完全部输入。

短路条件须对**扩张后每个实际传入的外层绑定**成立。例如，`coalesce(u.answer, L)` 中的 `u.answer` 必须对每个传入的 u 都非 NULL。保留旧锚点的属性，并不能保证新加入的输入也满足条件。新增区域也不能改变决定性守卫或破坏 `Q0` 的见证条件。

### 3.2 算法1逐行解释

以下行号对应第2.1节的正文伪代码。

| 行号 | 具体含义与必要条件 |
|---|---|
| 1 | 同时识别源形式与变异形式的变量来源和读取。共享锚点必须对应同一节点；P10 的共享 v 表示连接约束，首次绑定它的匹配位置可以变化。 |
| 2 | 读取构图前已声明的语义要求和 p 的前提，包括守卫真假、非空前缀、见证数量及路径界。R 是要满足的事实，不预先指定节点数量配方。 |
| 3 | 沿定义与使用关系，把外层要求传给直接产生相应值或行流的内部算子，再对它继续递归。不能跳过中间的 RETURN、COUNT 或条件分支。 |
| 4 | COUNT 大于2要求其直接子查询至少三行；EXISTS 为真要求直接子查询非空，为假要求为空。EXISTS 包住 RETURN COUNT 时，RETURN 本身仍可能产生一行。 |
| 5 | 条件行流或 CASE 把真假要求传给守卫和应选分支；COALESCE 把决定结果的非空要求传给相应前缀。FALSE 与 NULL 可能选择同一 ELSE，但仍是不同真值。 |
| 6 | 对非 NULL 路径的节点集合，ALL 为真要求每个节点条件为真；为假要求至少一个 FALSE；为 NULL 要求没有 FALSE 且至少一个 NULL。长度要求也须保留。缺失绑定的 NULL 先按非空性要求处理，不当作空集合。 |
| 7 | 合并同一绑定受到的条件，并求数量区间和路径长度界的交集。若同一事实被要求同时成立与不成立，或区间为空，则拒绝。 |
| 8 | 创建实际锚点、共享连接和必要见证。数量针对每个相关输入：一个输入需要三个匹配，就为它提供三个，而非只保证全图总数为三。 |
| 9 | 将要求落实为标签、属性、连接及路径长度。成功路径节点应通过相应条件；低成本角色可使用固定键定位、小邻域或无须读图的常量。需要选择性访问时建立相应入口。 |
| 10 | 在选定的候选入口、扇出或重复输入位置添加规模随 N 变化的结构。L/H 角色及这些连接已在 S 中声明，不能增加未经分析的读取关系。 |
| 11 | 通过真正的排除条件阻止新增候选贡献结果：P3 让路径经过失败节点，P10 让额外右段无法接上左段。成功见证保持完整，不能出现绕开排除条件的新匹配。 |
| 12 | 被屏蔽计算可包含有效匹配，但守卫或非空前缀须对所有实际输入成立。EXISTS 保留 Q0 的存在性；LIMIT 保留足够行、相同常量投影且不使用 DISTINCT。Q0 不与待替换的 L/H 混同。 |
| 13 | 保留 p 所需的节点、路径或连接对应。重排可以增加两侧共同返回的组合，但必须保留每个组合的重复次数；不统一要求跨规模输出固定。 |
| 14 | 检查完整骨架的两种形式。新增节点可能改变另一处 COUNT、守卫或外层输入；须覆盖新输入并保持所选扩张的语义依据。无法建立必要事实时拒绝。 |
| 15 | 将角色绑定、输入来源、关键属性、成功／失败划分、数量及结构对应记录为 I。算法2选择候选时必须保持这些事实。 |
| 16 | 返回共同图及条件；两条查询使用同一张图。 |

### 3.3 小例子：P3 的三条路径，只有一条有效

**骨架要求：**从 s 出发找二跳路径，要求路径上的节点都满足 `keep=true`。

**算法1配图：**只画三条路径：

```text
s(T) — a(T) — t(T)    通过
s(T) — b(F) — x(T)    不通过
s(T) — b(F) — y(T)    不通过
```

T 表示 true，F 表示 false。同名节点是同一个节点：后两条路径共用 s 和 b。图中只有这些边。

第一条是保留的成功见证。后两条都经过 b，所以不能通过 ALL。现在一共3条候选，只有1条有效。

**扩张：**继续给 b 接上更多终点。新增路径仍经过 b，不会增加有效结果。及时检查 b 可以跳过它后面的分支；先展开再检查则可能处理更多候选。

为了供查询填充，边都标记为 `LINK`，s 标记为 `Start`，t、x、y 标记为 `End`；终点的 `name` 分别为 t、x、y。

## 4. 算法2详细说明与递归实例化

### 4.1 实例化思路

实例化将骨架的抽象角色连接到图中的具体内容。一个节点空位需要标签和定位条件；谓词空位需要引用已绑定的变量；子查询空位需要确定输入变量、匹配区域和输出列。

候选来自 **S 事先限定的语法形式和嵌套深度、当前位置可见的变量，以及 G 和 I 提供的角色与事实**。语法规定可以使用哪些运算形式及子骨架；G 和 I 提供它们能引用的标签、关系、属性和值。例如，布尔位置可以使用比较或 EXISTS，数量位置可以使用 COUNT，但候选仍须保持该空位原先声明的语义，不能只凭结果类型相同就互换。

算法1提供满足声明条件的图，算法2选择保持这些条件的具体表达。两阶段共享的是这些条件和角色对应；新增读取区域、改变阈值或改变子查询消费方式的候选，须先形成新骨架，再重新构图。

| 空位类型 | 怎样形成候选 |
|---|---|
| 标签、关系类型、属性名 | 使用图中对应角色的名称，保持不同位置对同一角色的引用一致 |
| 定位条件 | 使用图中能选中目标锚点的键值，例如 `id=1` |
| 谓词 | 使用可见变量构造比较或布尔组合，同时保留成功见证通过、指定失败候选被排除的条件 |
| 标量表达式 | 按所需类型选择常量、属性或子查询结果，并保持所需值及非空性 |
| 匹配或子查询 | 使用已声明子骨架中的节点和关系角色，保留相关输入、直接消费关系、输出列及匹配数量要求 |

例如，在 P3 的布尔属性图上，`x.keep=true` 与 `NOT(x.keep=false)` 都接受 TRUE 节点、拒绝 FALSE 节点，可以作为相同空位的两种写法。常量 `true` 虽然类型正确，也让成功见证通过，却会同时放入失败路径，因此必须排除。候选还须只读、确定，并在构造的数据上能够正常求值，使逐层替换的结果关系成立。

递归填充时，每一层都先确定可用变量，再填入使用这些变量的条件和子查询。内层需要引用外层锚点时，沿用该锚点；内层新定义的变量则使用不冲突的名字。这样，增加嵌套后仍能明确每个值来自哪里、由哪一层使用。

### 4.2 算法2逐行解释

以下行号对应第2.2节的正文伪代码。

| 行号 | 具体含义与必要条件 |
|---|---|
| 1 | 复制骨架的源形式，保留嵌套语境、共享角色和指定变异位置。此时不重新选择外层条件或 COUNT 阈值。 |
| 2 | 先处理变量定义，再处理引用它的空位。例如先绑定路径 p，再填使用 nodes(p) 的 ALL；先产生别名 n，再填使用 n 的条件。已由递归填好的空位不重复选择。 |
| 3 | 从骨架允许的形式中生成候选，用图中的标签、关系、属性和值连接实际角色。候选来源明确，不另行创造未声明的语义结构。 |
| 4 | 进入既定子骨架时沿用允许的外层输入，并为新局部变量选择不冲突的名字。对子骨架重复同一填充过程，返回符合该位置输出要求的候选。 |
| 5 | 同时保持应通过和应排除的情况。P3 中常量 true 虽然类型正确，却放入失败路径，应排除。输出要求由语境决定：S3 的未选分支须列名和类型兼容，但其值、行数可与替换前不同。 |
| 6 | 候选集合为空时，本次填充失败；父层可移除该失败候选并尝试剩余候选。共享符号取值保持一致，相关变量不能被换成另一个节点。 |
| 7 | 完成当前层的填充；递归层使用同一规则。 |
| 8 | 检查完整源查询的类型、作用域和 p 的适用条件，再复制完整查询，包括外层条件、相关绑定和投影。G 与 I 不变。 |
| 9 | 根据 p 的类别选择局部变异方式。 |
| 10 | H 使用与源查询相同的填充规则及 I，不能临时引入新区域。只替换标记位置的 L，保留决定性守卫、非空前缀、Q0及所需投影条件。 |
| 11 | 在标记位置进行路径反转、匹配交换等对称变换。变量约束、共享连接和返回列保持不变；匹配首次引入变量的位置可按规则变化。 |
| 12 | 完成本次局部变异，其余语境继续沿用。 |
| 13 | 选择包含结果保持依据的完整局部结构。S7 是整个 COALESCE，S3 是整个 WHEN 行流，P10 是完整连接；单独的 L/H 参数可以不等价。 |
| 14 | 对每个实际传入的绑定，用路径／匹配对应、决定性条件或 Q0 的见证与投影条件建立相同输出。标量保留类型和 NULL，行流保留完整多重集。 |
| 15 | 沿父算子的实际使用关系逐层传递。COUNT 观察行数，EXISTS 观察非空性，投影保留所需值；LIMIT 或列表观察还须保持相应的行选择与顺序。任何一层所需性质无法建立都拒绝，不能仅凭类型相同继续嵌套。具体规则见第4.5节。 |
| 16 | 完全相同的查询不能形成所需局部变化，因此拒绝。 |
| 17 | 返回查询对，沿用 G 与 I，供后续结果核对和性能测试使用。 |

### 4.3 小例子：把 P3 的空位填好，再交换两端

**骨架保留三个空位：起点、终点范围和节点条件。**

用上面的图填入：起点用 `Start`，终点用 `End`，关系用 `LINK`，节点条件用 `keep=true`。算法2得到下面的路径写法，再交换两端：

```text
Q1：MATCH p = (s:Start)-[:LINK*2..2]-(v:End)
Q2：MATCH p = (v:End)-[:LINK*2..2]-(s:Start)

两条查询共同保留：
WHERE all(n IN nodes(p) WHERE n.keep = true)
RETURN v.name
```

`*2..2` 就是二跳。两条查询检查同一批节点，也都返回同一个终点变量 v 的名字。

**结果保持：**只有 `s—a—t` 全部为真，反过来仍是这些节点；另外两条仍经过 b。因此双方都只返回 t。

若外层只数有效匹配，两边都得到1；若只问是否存在有效匹配，两边都为真。

### 4.4 小例子：S7 把便宜计算换成贵计算

```text
原来：coalesce(NULL, 0, 1)
变异：coalesce(NULL, 0, 统计所有终点)
```

上图有3个终点，统计结果为3。但 COALESCE 遇到第一个非 NULL 的值就确定结果，因此两边都返回0。

变化只在最后一项。增加终点会增加统计的潜在工作，但它本来就可以被跳过。

### 4.5 递归嵌套为什么仍然成立

递归需要两个方向的推导。**构图时，沿变量来源把外层要求传向内层；变异后，从已经建立的局部结果关系逐层向外传递。** 前者确定要配什么数据，后者说明这次局部变化为何不改变完整查询。

结果关系应从包含其依据的完整局部结构开始。P3 先用路径反转的一一对应，建立相同端点输出及重复次数；S7 则从整个 `coalesce(NULL,0,…)` 开始。S7 中的常量1与高成本 COUNT 可以不同，不能先声称这两个参数等价。

| 外层算子 | 向内需要说明什么 | 向外怎样保留结果 |
|---|---|---|
| COUNT | 它直接统计哪个子查询产生的行，要求的数量区间是什么 | 被统计的行数相同，则计数相同；内层多重集相同足以保证这一点 |
| EXISTS | 它的直接子查询需要非空还是为空 | 两侧的非空性相同，则布尔值相同；S8 可以通过保留 Q0 保证两侧都非空 |
| WITH、投影与过滤 | 别名来自哪个表达式，哪些值被后续使用 | 对同一输入保留相同值及 NULL 后，相同过滤保留相同记录与重复次数 |
| CASE、布尔运算与 COALESCE | 哪个条件决定结果，哪些分支或参数被使用 | 使用相同子结果，或利用决定性条件建立完整结构的相同输出，再传给父算子 |
| LIMIT 或顺序相关观察 | 外层实际选择哪些行，是否观察列表或路径顺序 | 需要相同的被选行，或 S6 的相同常量投影条件；仅有内层多重集相同不足以处理不同的行顺序 |

每一步都针对相同的外层输入绑定进行。确定性的父算子接收到相同的所需值或行后，继续产生相同输出；如果某层需要的性质没有建立，就不能继续向外传递。

具体的两层嵌套见第6节：先说明内层为什么返回同样的行，再把这些行交给外层。

非空要求也要对每个输入成立：0可以屏蔽后面的参数，NULL却不能。COUNT 即使数到0，也可以返回一行值为0的记录；EXISTS 判断的是其直接子查询有没有行，不能跳到最里面的匹配来判断。

P3 若直接返回路径节点列表，则两边分别是 `[s,a,t]` 和 `[t,a,s]`，顺序不同。因此，上面的例子只返回终点，不返回这个列表。

## 5. 简单完整案例：P10 两边链

### 5.1 骨架：先找左边，再接右边

```text
左边：u —A→ v
右边：v —B→ w
返回：完整链 (u,v,w)
```

这里最重要的是：**两边必须通过同一个中间节点连接。** 这只是连接要求，不强制哪边先执行。

### 5.2 算法1：一条完整链，加一条接不上的右段

```text
u —A→ v —B→ w       完整链

x —B→ y             只有右段，没有接到 x 的 A 边
```

图中只有这三条边。第一行保证有一个有效结果；第二行是新增候选，本身能匹配 B，但不能组成完整链。

### 5.3 算法2：填入 A、B，只交换查找次序

```text
Q1：先找 A 边，再沿同一个中间节点找 B 边。
Q2：先找 B 边，再找接到同一个中间节点的 A 边。
两边都返回完整链。
```

若先找 B，会遇到两条右段：

| 找到的右段 | 能否接上 A |
|---|---|
| v→w | 能，前面有 u→v |
| x→y | 不能，前面没有 A 边 |

### 5.4 为什么交换后结果不变

无论先找哪边，最后都只有 `u→v→w`，另一条候选接不上。算法2改变查找次序，保留同一个中间节点的连接要求。

若在外面套 COUNT，两边都返回1。继续添加类似 `x→y` 的右段，会增加候选，但完整结果仍只有这一条。先从 A 取得中间节点，可以避开这些不相关右段；实际是否避开由执行计划决定。

这里复用了 P3 的“保留一个成功结果，再增加不贡献结果的候选”。区别只在排除理由：P3 经过假节点，P10 则接不上左边。

## 6. 简单完整案例：S3 套 S3

### 6.1 骨架：两层选择，只改内层的“否则”

下面每个分支都返回记录，输出列都叫 `value`：

```text
外层条件为真：
    内层条件为真：返回一行0
    否则：返回一行1             ← 只改这里
否则：返回一行2
```

这就是“条件行流里面再放一个条件行流”。本例要求两层都选择“条件为真”的分支，所以两层条件都应为 TRUE。

### 6.2 算法1：只需要三个节点

```text
u {outer:true, inner:true}
  ├─H→ h1 {value:9}
  └─H→ h2 {value:9}
```

u 是唯一输入。`outer`、`inner` 两个属性让两层条件都为真。选中分支直接返回一行0，这一行就是见证，无须再建一组见证节点。

两个 H 邻居供高成本替代读取。继续添加这样的邻居，就能扩大工作；两层条件和那一行0保持不变。

### 6.3 算法2：填条件，只替换一处

外层条件填 `u.outer=true`，内层条件填 `u.inner=true`。保留整个骨架，只替换内层“否则”：

```text
原来：返回一行1
变异：沿 u 的 H 边找邻居，返回它们的 value
      → 得到两行9
```

读取 H 时仍使用同一个 u，返回列仍叫 `value`。这里不要求“一行1”与“两行9”相同。

### 6.4 为什么嵌套后结果仍不变

```text
内层条件为真 → 原来和变异后都选“一行0”。
外层条件为真 → 两边都把内层这“一行0”返回。
```

因此，完整结果都只有一行0。外层若再数行，两边都为1。

关键是先比较**整个内层选择的结果**，再向外传；被替换的两个分支本身可以不同。若内层条件变成 FALSE 或 NULL，就会执行“否则”，一行1与两行9不同，这次变异就不成立。

## 7. 两个案例统一复用了哪些规则

| 共同规则 | P10 两边链 | S3 套 S3 |
|---|---|---|
| 先确定骨架与变异位置 | 共享中间节点的两段匹配 | 两层选择中，内层的“否则”分支 |
| 保持同一个输入或连接点 | 两段通过同一中间节点连接 | 两个条件及 H 读取使用同一个 u |
| 向内落实要求 | 保留一条完整链 | 两个条件为真，选中一行0 |
| 保留结果，增加候选 | 添加接不上左段的右段 | 添加 H 邻居，仍选择一行0 |
| 按已配好的图填骨架 | 左关系填 A，右关系填 B，共享中间变量 | 条件读取 u 的属性，替代分支读取 H |
| 只改标记位置 | 交换两个匹配的次序 | 替换内层“否则” |
| 结果逐层向外保持 | 完整链相同，计数也相同 | 内层一行0，外层也一行0 |

统一的是依赖分析、见证保留、角色填充及结果关系的组合过程；局部依据由 pattern 的语义给出。P3 用 ALL 排除新增路径，P10 用共享 v 的连接条件排除额外右段，S3 用守卫屏蔽未选中分支。新增结构不必都满足同一种“失败谓词”。

因此，递归扩大语义空间时，先在完整骨架中声明新的父层或子层，再沿相同依赖规则构图和实例化。每层只需建立它实际观察的结果关系，即可将已成立的内层关系继续向外传递。

## 8. 两个算法怎样服务于遗漏优化测试

算法1将优化机会变成可控的数据差异：必要见证保持成立，候选入口、路径分支或被屏蔽计算的规模随 N 增加。算法2将这些区域连接到具体查询，并通过局部变异形成比较：对称模式改变等价工作的表示或顺序，短路模式把可跳过位置的 L 换成 H。

结果保持的依据来自 pattern 的语义规则和图中的构造条件。执行阶段再核对完整结果，并通过随规模变化的运行时间、执行计划和工作计数，判断数据库是否实际做了可避免的工作。
