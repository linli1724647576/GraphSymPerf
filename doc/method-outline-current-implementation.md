# GraphSymPerf 方法部分大纲：当前实现版

> 文档性质：论文方法章节的详细大纲，仅供内部审阅，尚不是论文正文。
> 证据快照：2026-07-28 当前工作区代码。
> 范围约束：只描述仓库中已存在的实现；不采用 `doc/paper-v2/` 中尚未实现的目标设计。配置中的实验规模是方法参数，不是已完成结果。

## 0. 核心结论与写作边界

### 0.1 当前实现可以支撑的总体方法

GraphSymPerf 当前可被严谨地概括为一种面向图数据库管理系统（Graph Database Management System, GDBMS）的**受限等价查询变换与运行时配对筛选方法**：

1. 使用 GDsmith 生成相互匹配的属性图和 Cypher 基础查询；
2. 在保守支持的 Cypher 子集中定位普通 `MATCH` 谓词位点；
3. 应用经三值逻辑检查的冗余布尔变换，构造预期等价查询对；
4. 在目标 GDBMS 上执行两条查询，以完整、类型敏感的结果等价作为查询对接受条件；
5. 对接受查询对进行预热和随机化 `AB/BA` 配对计时，以运行时间倍率识别性能异常候选；
6. 通过确定性分片、版本清单、进程隔离、原因码和内容哈希保存可审计证据。

当前正式命令实际执行的主路径为：

```text
实验资格检查
→ 确定性分片
→ GDsmith 图—查询生成
→ 目标图重放
→ 查询资格与静态适用性检查
→ 三值逻辑冗余谓词变换
→ 完整类型结果等价过滤
→ 随机化配对计时
→ 运行时候选记录
```

### 0.2 当前最可辩护的创新点

不能声称首次提出等价查询重写（Equivalent Query Rewriting, EQR）或首次使用等价查询检测数据库性能问题：GRev 已将 EQR 用于 GDBMS 测试 \cite{mang2024grev}，Amoeba 已在关系数据库上比较等价查询的响应时间 \cite{liu2022amoeba}。

当前较稳健的研究增量是：

1. **有限 Cypher 片段上的保守等价实例化。** 变换前显式检查查询纯净性、作用域、模式结构、变量绑定、表达式片段和方言可执行性，并对布尔规则穷举 `true/false/null`。
2. **静态适用性与动态结果等价的双重门禁。** 静态检查降低偶然等价和错误变换风险，动态检查确认当前图实例上的完整可观察结果一致；二者职责不同。
3. **与执行计划解耦的运行时优先检测。** 正式筛选只使用普通执行时间，不以 `EXPLAIN`、`PROFILE`、计划差异或开发者状态改变候选判定。
4. **以“接受查询对”为实验单位。** 生成预算与真正进入性能 Oracle 的查询对预算分离，避免不同 GDBMS 因方言拒绝率不同而产生不可比的有效样本量。

### 0.3 必须提前承认的范围限制

- 正式工作器当前端到端使用一个通用布尔规则；ArcadeDB 分支实际退化为更简单的 `AND true`。
- 结果不一致当前被记为拒绝原因，而不是逻辑缺陷候选，因此本版不能主张“逻辑 + 性能”双 Oracle。
- 独立验证、噪声校准、约简和提升接口已有代码与测试，但尚未由正式工作器自动串联。
- 当前方法更接近“严谨、可审计但范围有限的原型”，尚不是通用 Cypher 等价验证框架。

## 2. 详细方法大纲

### 2.1 问题定义与目标范围

#### 本节目标

将研究对象限定为：**同一图、同一 GDBMS 版本和同一外部执行条件下，预期等价查询形态之间的方向性运行时不对称**。避免把慢查询、跨版本回归、逻辑不一致和根因诊断混为一个目标。

#### 形式化对象

给定：

- 目标 GDBMS 实例 \(S\)；
- 固定图快照 \(G\)；
- 基础只读查询 \(Q\)；
- 变换规则 \(r\)；
- 变换查询 \(Q'=r(Q)\)；
- 查询的外部可观察结果 \(\operatorname{Obs}_G(Q)\)。

当前实现的查询对接受条件可写为：

\[
\operatorname{Accept}(Q,Q',G) \iff
\operatorname{Eligible}(Q)
\land \operatorname{Applicable}(r,Q)
\land \operatorname{Executable}_S(Q,Q')
\land \operatorname{EqResult}_G(Q,Q').
\]

各谓词含义：

- `Eligible`：只读、无已识别非确定函数、无不稳定顺序依赖；
- `Applicable`：查询位于当前解析与证明支持域，且新表达式只引用目标 `MATCH` 中绑定的变量；
- `Executable`：两条查询通过方言与重放过滤，并在目标系统上完成执行；
- `EqResult`：结果未截断，且类型化行序列或行多重集相等。

对接受查询对，发现阶段使用：

\[
R(Q,Q')=\operatorname{median}_{i=1}^{m}\frac{T_i(Q')}{T_i(Q)}.
\]

当前配置 \(m=5\)，候选条件为 \(R(Q,Q')\ge2.0\)，并要求测量没有进入无结论状态。

#### 需要在正文中明确的边界

1. \(2\times\) 是项目的发现阈值，不是领域通用的缺陷定义。
2. 当前只保留 \(Q'\) 比 \(Q\) 慢的方向，未对相反方向做对称归一化。
3. 结果不一致不会进入性能测量，也不会在当前主路径形成逻辑缺陷候选。
4. 本文研究同版本内等价查询形态不对称，不是 APOLLO 的跨版本性能回归 \cite{jung2019apollo}。
5. 性能不对称是候选现象；优化器根因仍需独立解释和开发者确认。

#### 设计理由

- 等价查询对为同一计算任务提供内部参照，降低对人工性能答案的依赖；这一总体范式已有 Amoeba 作为直接先例 \cite{liu2022amoeba}。
- 同一系统内比较避免将不同 GDBMS 的实现目标、方言和硬件接口误当成性能错误。
- 把结果等价放在计时之前，确保性能 Oracle 比较的是同一可观察任务。

### 2.2 方法总览

#### 本节目标

用一张框架图说明每个阶段排除哪一种不可信来源，而不是罗列代码模块。

#### 九阶段流程

1. **实验资格检查**：检查生成器、驱动、连通性、图隔离、环境变量和制品空间。
2. **确定性任务划分**：根据实验种子、目标 GDBMS 和分片编号派生分片种子，保存代码与 GDsmith 版本。
3. **图—查询联合生成**：由 GDsmith 生成图构造语句和只读 Cypher 查询。
4. **目标图重放**：清空目标图并加载本分片图状态。
5. **资格与适用性检查**：排除写操作、非确定行为、不支持作用域、模式和方言。
6. **等价变体构造**：在受支持 `MATCH` 谓词位点插入三值逻辑冗余结构。
7. **动态接受门禁**：执行两条查询，拒绝异常、截断和类型结果不一致。
8. **运行时配对筛选**：预热并随机化执行顺序，以查询对内倍率识别候选。
9. **证据固化**：记录查询哈希、候选全文、倍率、绝对差、原因码和运行协议。

#### 每阶段克服的困难

| 阶段 | 困难 | 当前方法 |
|---|---|---|
| 生成 | 随机查询易语义无效或结果为空 | 复用 GDsmith 的语义约束、图引导和数据引导生成 \cite{hua2023gdsmith} |
| 重放 | GDBMS 的加载协议和隔离单位不同 | 适配器统一执行接口；无法无损重放时拒绝 |
| 变换 | 空值、作用域和图模式会破坏直觉等价 | 缩小支持域、保守跳过、三值真值检查 |
| 结果 Oracle | 字符串化会混淆类型，集合化会丢失重复项 | 类型规范化；有序序列或无序多重集 |
| 性能 Oracle | 缓存、JIT、顺序和系统噪声 | 预热和随机化配对；发现与确认接口分离 |
| 复现 | 挂起、重试和部分完成会污染统计 | 进程隔离、硬时限、事件日志和 `INCOMPLETE` 状态 |

#### 为什么不采用其他总体路线

- 不用跨 GDBMS 性能差异判错：系统实现目标与方言不同，缺少共同性能真值。
- 不以执行计划覆盖指导正式筛选：计划变化不是性能异常的充分或必要条件，且难以跨系统统一。
- 不重新实现查询生成器：本文焦点是等价实例化和性能证据，GDsmith 是输入依赖而非创新点。
- 不把所有规则同时纳入正式路径：规则数量不能替代单条规则的语义可信度和执行闭环。

#### 与最近工作的定位

- **GDsmith**：提供图与复杂 Cypher 查询生成；GraphSymPerf 不复用其差分结果 Oracle \cite{hua2023gdsmith}。
- **GRev**：是 GDBMS EQR 的最近工作；本项目不能把 EQR 或图数据库等价查询测试写成首创 \cite{mang2024grev}。
- **Gamera**：说明图结构感知蜕变关系可缓解 GDBMS Oracle 问题；当前规则不是其图结构关系族 \cite{zhuang2023gamera}。
- **Amoeba**：是“等价查询 + 响应时间差异”性能 Oracle 的直接关系数据库先例 \cite{liu2022amoeba}。

### 2.3 图与基础查询生成

#### 2.3.1 GDsmith 作为唯一生成器

本小节需说明：

- 当前正式配置固定使用 GDsmith，不以 LDBC 或手写查询自动补位；
- 每个 `(目标 GDBMS, 分片)` 使用确定性随机种子；
- 保存 GDsmith 命令、算法、种子、输出、错误流、日志和返回状态；
- 从日志中分离图构造语句、可接受只读查询和被跳过记录。

日志解析阶段拒绝：

- 写操作；
- 缺少 `RETURN`；
- 不支持的起始子句；
- `CALL`；
- 超过查询记录上限的输入。

#### 2.3.2 为什么采用图—查询联合生成

- 图查询是否可执行、是否非空依赖图拓扑、标签、关系类型和属性值。
- 只生成查询而不控制图状态，会产生大量空结果或不可满足模式。
- GDsmith 已通过图引导模式组合和数据引导条件生成提高复杂、非空 Cypher 查询比例 \cite{hua2023gdsmith}。
- 因而论文应把 GDsmith 写成输入生成组件，不把其技术重新包装为本文贡献。

#### 2.3.3 在目标系统上重放

- 分片开始前删除旧图，避免前一分片状态泄漏；
- 解析节点、标签、属性、关系方向、类型和属性；
- 通过目标适配器加载图；
- 对没有原生 GDsmith 后端的目标，可使用兼容代理生成，但查询必须在真实目标系统上重放、执行和计时；
- 代理不提供性能候选真值。

#### 关键设计选择

**为什么拒绝有损方言兼容，而不是删改语法：**

删除标签、关系类型、谓词或作用域结构会改变查询选择性或语义，也会改变待比较的优化问题。方言兼容的目标是保持查询对关系，而不是最大化执行率。

#### 当前限制

- GDsmith 日志解析只接收以分号结束的单行记录。
- 后续重放门禁进一步要求以普通 `MATCH` 开始。
- 重放过滤拒绝写操作、`CALL`、变长路径和部分列表/模式结构。
- 代理生成与原生生成的输入分布尚未系统比较。

### 2.4 查询资格与保守语义子集

#### 2.4.1 查询纯净性

当前实现排除：

- `CREATE`、`MERGE`、`DELETE`、`SET`、`REMOVE`、`DROP`、`LOAD CSV`；
- 已识别的非确定或时间函数；
- 无 `ORDER BY` 的 `LIMIT`/`SKIP`；
- 无稳定顺序保证的 `collect()`。

设计理由：

- 写查询会使执行顺序改变图状态，破坏同一输入上的成对比较；
- 非确定函数可能让等价查询在两次执行时观察到不同值；
- 无序截断与聚合会把实现相关行序暴露为结果差异。

#### 2.4.2 变换适用域

当前布尔变换进一步拒绝：

- 以 `WITH` 或 `OPTIONAL MATCH` 开始的查询；
- `CALL` 或 `EXISTS` 子作用域；
- 模式推导式；
- 变长路径；
- 无普通 `MATCH`、无绑定节点变量或超出局部解析器的模式。

这些限制分别对应变量重绑定、空值扩展、相关作用域、路径重复/唯一性和表达式内嵌图模式等当前未建模语义。

#### 2.4.3 方言门禁

- 原生 Cypher 目标主要依赖通用重放过滤；
- AgensGraph 对部分多标签形式做保守拒绝；
- Apache AGE 对代理不支持的子查询形式做拒绝；
- 目标适配器可以提供更窄的可重放判定。

#### 应当如何表述

可写：

> GraphSymPerf 将变换限制在显式、保守的可分析子集，并为每次跳过保留原因码。

不可写：

- 已实现完整 Cypher/GQL 语义分析；
- 七个 GDBMS 的方言差异均已形式化建模；
- 所有不支持查询均可通过无损重写兼容。

### 2.5 有限 Cypher 表示与静态等价检查

#### 2.5.1 局部抽象语法结构

当前解析器只覆盖与现有规则直接相关的结构：

- 顶层子句及源码区间；
- 普通 `MATCH`；
- 节点、定长边、有限无向变长路径和逗号分隔模式列表；
- `WHERE` 区域；
- 顶层合取谓词；
- 空值测试、字面量比较和受限比较项。

保留源码区间的目的，是只替换目标子句而不重新渲染整个查询，从而减少无关文本变化。

#### 2.5.2 小型关系代数式表示

受支持图模式可下降为：

- `node`；
- `directed_edge` / `undirected_edge`；
- `finite_undirected_path`；
- `selection`；
- `join`。

规范化包括：

- 对连接子项排序；
- 对标签和属性项排序；
- 对无向边端点排序；
- 对顶层合取谓词使用多重集签名。

当变换前后下降后的规范形式相同，证明记录保存：

- 定理名称；
- 适用片段；
- 前提集合；
- 保持的不变量；
- 原始与变换后的规范形式。

#### 2.5.3 当前证明能力的边界

仓库已为部分节点顺序、边记法、谓词顺序、模式顺序、标签顺序、属性映射顺序、路径端点和变量重命名规则实现证明元数据。但：

- 这些是规则特定的有限片段检查，不是完整 Cypher 等价判定器；
- 规范形式只覆盖已经编码的语义维度；
- 聚合、一般子查询、复杂列表、完整路径语义和全部方言差异不在当前证明域；
- 正式工作器当前只调用布尔冗余规则，没有调用完整对称规则库。

#### 为什么采用小型表示而不是直接宣称完整形式化

- 完整 Cypher/GQL 语义实现成本高，且不完整实现容易制造虚假的“已证明”外观；
- 小型表示能够显式检查当前规则需要的不变量，并让不支持构造安全失败；
- 代价是覆盖率下降，论文需通过适用率和拒绝原因报告这一代价。

### 2.6 当前正式变换：三值逻辑完备的冗余谓词

#### 2.6.1 规则定义

设原 `MATCH` 谓词为 \(P\)。若没有 `WHERE`，令 \(P=\texttt{true}\)。选择一个受支持的布尔表达式 \(E\)，构造：

\[
P' = P \land \left(E \lor \neg E \lor \operatorname{isNull}(E)\right).
\]

在 Cypher 三值逻辑域
\(\{\mathsf{true},\mathsf{false},\mathsf{null}\}\) 中：

- \(E=\mathsf{true}\) 时第一项为真；
- \(E=\mathsf{false}\) 时 \(\neg E\) 为真；
- \(E=\mathsf{null}\) 时 `E IS NULL` 为真。

因此括号项恒为真，理论上 \(P'=P\)。

当前实现对 \(P\) 和 \(E\) 的三种真值进行 \(3\times3\) 穷举；任一组合不保持 \(P'=P\) 即拒绝该规则。

#### 2.6.2 注入位置

- 只选择首个普通 `MATCH`；
- 有 `WHERE` 时替换原谓词，无 `WHERE` 时新增谓词；
- 新表达式只能引用该模式中已绑定的节点变量；
- 其他子句保持原文本。

选择首个普通 `MATCH` 的原因：

- 当前实现可明确恢复其模式绑定和源码区间；
- 避免跨 `WITH`、子查询或 `OPTIONAL MATCH` 推导变量可见性；
- 以位点覆盖换取当前语义检查的可审计性。

#### 2.6.3 受限表达式构造

表达式记录包含标识、家族、复杂度、风险、引用变量、Cypher 文本、表达式 AST 和证明说明。

Neo4j 路径可选择：

- `elementId(v) = elementId(v)`；
- `labels(v) = labels(v)`；
- `size(labels(v)) >= 0`；
- `v.p IS NULL OR v.p IS NOT NULL`；
- `coalesce(v.p = v.p, true)`；
- 受限布尔组合。

其他目标采用更保守的可移植候选，必要时退化为字面量 `true`。

#### 2.6.4 静态检查链

变换前依次检查：

1. 查询纯净且可重放；
2. 不含当前不支持的作用域和图模式；
3. 首个普通 `MATCH` 可解析；
4. 模式至少绑定一个节点变量；
5. 新表达式属于受支持布尔片段；
6. 新表达式只引用该 `MATCH` 的绑定变量；
7. 规则通过三值真值表；
8. 原模式可下降到当前关系代数式片段。

通过后生成语义证明元数据。正式工作器目前只保留查询文本、规则标签和查询哈希，未把完整证明元数据写入接受记录。因此宜写“生成时静态证明检查”，暂不写“持久化证明携带查询”。

#### 2.6.5 ArcadeDB 特例

ArcadeDB 分支会覆盖通用规则选择；在当前“每种子一个变体”设置下，实际使用 `P AND true`。但接受记录仍硬编码为 `and_excluded_middle_or_null`。

论文影响：

- 不能直接按记录中的 `rule_id` 比较 ArcadeDB 与其他目标；
- 修正规则来源持久化前，应单列 ArcadeDB 或不做按规则跨系统统计；
- 不能声称所有目标使用完全相同的三值结构。

#### 为什么不统一只用 `AND true`

- `AND true` 主要测试常量折叠；
- 三值完备结构同时引入属性访问、空值处理、否定和布尔简化压力；
- 更复杂的恒等结构更可能暴露不同查询形态的优化不对称；
- 但复杂度提高了语义风险，因此必须受绑定、表达式片段和真值表约束。

#### 创新点的准确写法

建议：

> GraphSymPerf 并未发明新的布尔恒等式；其增量在于把三值逻辑恒等式限制到可分析的 `MATCH` 谓词位点，并将作用域、绑定、表达式片段和真值表检查组合成保守实例化门禁。

避免：

- “提出新的三值逻辑定理”；
- “证明任意 Cypher 上下文中该变换等价”；
- “统一支持所有布尔与图模式规则”。

### 2.7 动态类型结果等价门禁

#### 2.7.1 接受流程

对每个候选 \((Q,Q')\)：

1. 分别检查两条查询的方言兼容性；
2. 分别检查目标适配器的可重放性；
3. 计算查询对哈希并去除当前分片内重复对；
4. 在同一目标图上普通执行 \(Q\) 与 \(Q'\)；
5. 执行异常、超时或结果截断时拒绝；
6. 对完整结果做类型敏感比较；
7. 仅结果等价时计入“接受查询对”并进入性能筛选。

#### 2.7.2 类型规范化

当前保留：

- `null`；
- 布尔值；
- 整数；
- 浮点数；
- 字符串；
- 列表/元组及递归元素类型；
- 映射及其排序键值；
- 其他驱动对象的运行时类型名与 `repr`。

因此整数 `1`、浮点数 `1.0`、字符串 `"1"` 和布尔值 `true` 不会因简单字符串化而混同。

#### 2.7.3 顺序与重复项

- 查询文本包含 `ORDER BY` 时，按类型化行序列比较；
- 否则按类型化行多重集比较；
- 多重集保留重复次数，不退化为集合。

设计理由：

- 无显式排序时按序列比较会制造伪不一致；
- 图模式和连接可产生重复行，集合比较会掩盖基数错误；
- 类型化多重集是当前返回值支持域上的折中 Oracle。

#### 2.7.4 静态与动态检查为何都需要

- 静态检查回答：当前规则实例是否满足已编码的充分条件？
- 动态比较回答：当前目标实现和图快照是否返回完整且相同的观察结果？
- 仅动态相等可能是当前图上的偶然等价；
- 仅静态检查又无法替代对目标 GDBMS 实际实现的观察。

#### 必须如实说明的问题

1. 配置项名为 `deduplicate_by_ast_hash`，但工作器实际使用空白规范化文本哈希；正文只能写“规范化内容哈希去重”。
2. `ORDER BY` 由关键字检测识别，不是完整顺序语义分析。
3. 结果不一致只作为拒绝原因，不构成当前逻辑 Oracle。
4. 驱动特有图对象的回退表示需逐适配器验证其跨会话稳定性。

### 2.8 运行时优先的随机化配对筛选

#### 2.8.1 普通执行

- 计时器只调用目标适配器的 `execute`；
- 即使适配器提供 `profile`，发现阶段也不调用；
- 执行计划、算子计数和开发者反馈不进入候选真值。

理由：

- `PROFILE` 可能引入额外开销或改变执行路径；
- 计划格式高度依赖 GDBMS；
- 计划变化不是性能缺陷的充分条件；
- 先观察性能现象、再提出计划或源码根因假设，能保持“发现—假设—归因”的证据顺序。

#### 2.8.2 预热与执行顺序

当前发现配置：

- 每条查询交替预热 3 次；
- 采集 5 组查询对；
- 用分片种子和查询对索引随机化 `AB/BA`；
- 5 组中包含 3 个一种顺序和 2 个另一种顺序，再随机打乱；
- 任一预热超时立即无结论；
- 配对中任一侧超时后停止采样并无结论。

随机化配对用于：

- 把同一时间窗口内的两条查询组成观测单元；
- 缓解缓慢环境漂移；
- 避免第二次执行总是获得缓存、编译或页状态优势。

同实例随机顺序和重复测量是处理性能高方差的一类已有策略 \cite{laaber2019microbenchmarking}。

#### 2.8.3 发现统计量

对每个完整配对计算：

\[
\rho_i=\frac{T_i(Q')}{T_i(Q)},\qquad
\Delta_i=T_i(Q')-T_i(Q).
\]

测量器返回的内存证据对象包含：

- 中位倍率；
- 中位绝对时间差；
- 方向一致率；
- 相对中位绝对偏差；
- 查询哈希和逐对样本。

但正式分片制品当前只持久化候选的中位倍率、中位绝对差和协议标签，没有写出逐对原始样本、方向一致率、相对中位绝对偏差或区间。因此这些字段不能直接作为当前正式实验的可审计输出。

当前工作器的实际候选条件为：

\[
\operatorname{verdict}=\texttt{PASS}
\land \operatorname{median}(\rho_i)\ge2.0.
\]

这里 `PASS` 只表示取得完整有效样本；工作器没有使用置信区间、绝对噪声下限或跨会话一致性。

#### 2.8.4 为什么发现协议较轻量

- 对所有接受查询对执行严格复验会显著增加成本；
- 轻量筛选用于缩小候选集，确认应使用新的样本和更强门槛；
- 发现样本与确认样本分离，可避免在同一小样本上先选择极端值再声称稳定性。

当前论文必须称其为“运行时候选”，而不是“已验证性能缺陷”。

#### 2.8.5 残余威胁

- 5 组配对仍可能受缓存、JIT、系统负载和计时粒度影响；
- 当前只检查倍率，不要求绝对差超过噪声；
- 当前只检测 \(Q'\) 变慢；
- 工作器把 bootstrap 重采样数设为 1，且不使用区间判定，不能写成“bootstrap 验证”；
- `runtime.noise` 配置尚未自动接入工作器。

### 2.9 实验可审计性与失败隔离

#### 2.9.1 实验资格检查

正式运行前检查：

- Java 和 GDsmith 制品；
- 显式破坏性加载开关；
- GDsmith checkout 是否干净；
- 目标驱动、环境变量和生成代理；
- 依赖、环境和连通性；
- 图隔离方式；
- 基于分片预算估算的磁盘空间。

本小节要强调：

> “程序能启动”不等于“实验结果可信”。缺失代理、隔离或磁盘空间可能导致系统性少跑，却被错误计为完成。

#### 2.9.2 确定性计划

- 对每个目标和分片构造任务；
- 分片种子由 `SHA-256(实验种子, 目标, 分片编号)` 派生，并限制在 63 位有符号整数范围；
- 保存 GraphSymPerf 与 GDsmith 提交标识和 GDsmith 脏状态；
- 写入解析后的运行清单。

#### 2.9.3 分片隔离与不完整状态

- 每个分片在独立子进程中执行；
- 超过硬时限时终止进程组；
- 失败分片可重试，且每次尝试使用新的制品目录；
- 事件追加记录，检查点原子替换；
- 未达到接受查询对预算的分片标为 `INCOMPLETE`，不静默计为完成。

#### 2.9.4 为什么按接受预算计量

正式配置区分：

- 目标接受查询对数；
- 最大生成种子数；
- 最长分片运行时间。

只有通过安全、执行和结果等价门禁的查询对进入性能分母。若生成或时间上限先耗尽，分片保持不完整。这减少了不同 GDBMS 因方言拒绝率不同造成的有效样本量不可比。

#### 当前边界

- 调度器实际按任务顺序执行，配置中的并发上限未驱动并行调度；
- `resume/status` 只打印运行标识，未实现检查点恢复或状态重建；
- 可主张确定性计划、进程隔离和不完整状态记录，不能主张完整的可恢复分布式实验系统。

### 2.10 已实现但尚未接入正式主路径的机制

> 本节建议写成“实现边界”或附录。若投稿前完成整合，再升级为正式方法小节。

#### 2.10.1 A/A 噪声校准

当前代码可以：

- 对探针查询执行 \(Q\) 与自身 \(Q\) 的配对测量；
- 汇总绝对时间差；
- 要求至少 200 个有效差值；
- 以第 99 百分位数作为经验噪声下限。

动机：

- 倍率会放大极短查询上的微小差；
- 自身对照估计“理论零差异”下的环境和计时波动；
- 候选绝对差应超过噪声，避免把微小抖动包装成大倍率。

边界：

- 校准函数已实现并有测试；
- 正式工作器未调用；
- 验证器只接收调用方传入的 `noise_floor_ms`。

#### 2.10.2 双会话验证接口

`IssueValidator` 当前检查：

1. 查询再次通过纯净性门禁；
2. 两个会话和进程标识不同；
3. 两会话均返回完整等价结果；
4. 图指纹、GDBMS 指纹和健康状态一致；
5. 两会话运行时证据有效；
6. 慢侧方向一致；
7. 保守倍率、区间下界和绝对差通过门槛。

默认接口可概括为：

\[
R_{\min}\ge3.0,\quad
CI_{\mathrm{low}}\ge2.0,\quad
\Delta_{\mathrm{median}}>\max(\Delta_{\mathrm{noise}},10\epsilon).
\]

方法理由：

- 新会话检查候选是否依赖单连接、单进程或短时缓存；
- 两会话取较小倍率，避免选择性报告；
- 区间与绝对差分别控制相对效应不确定性和计时噪声。

当前不足：

- 只有会话运行器协议，没有由正式 CLI 调用的生产运行器；
- `ValidationSession` 虽保存 `negative_controls`，验证器未检查这些记录；
- 不能声称正式候选已自动完成双进程、重载图和 A/A/B/B 对照。

#### 2.10.3 依赖约束约简

当前新约简器：

- 将顶层子句切分为删除单元；
- 通过变量依赖拒绝删除后续仍使用的定义；
- 对查询对对象生成单侧子句删除提案；
- 每个提案由外部症状谓词重新执行；
- 症状仍为 `PASS` 才接受；
- 输出 `REDUCED_VALID`、`REDUCTION_PARTIAL` 或 `REDUCTION_INVALIDATED`。

其思想与 delta debugging 的“反复删除并检查失败谓词”一致 \cite{zeller2002dd}；APOLLO 也说明数据库性能报告需要自动约简 \cite{jung2019apollo}。

当前不足：

- 提案基于顶层子句和正则变量分析，不是完整 AST 变换；
- 一次只改查询对的一侧，不是同步成对约简；
- `ddmin` 原语存在，但 `CandidateReducer` 未调用；
- 约简器不内置结果等价检查，取决于外部症状谓词；
- `issue reduce` 未接入该实现；
- 不能写“成对 AST ddmin、局部 1-minimal 和归约后双会话复验”。

#### 2.10.4 提升、去重与证据包

提升接口要求：

- 验证阶段为 `VALIDATION_PASSED`；
- 结果完整且等价；
- 约简状态为 `reduced_valid`；
- 存在 `core` 规则证书；
- 未标记可能重复。

精确重复键为：

\[
(\text{DBMS},\text{DBMS version},\text{pair hash},\text{slow direction}).
\]

证据包可保存 issue 标识、URL、文件清单和 SHA-256。

当前不足：

- 转换层和验证层存在两种 `SafetyCertificate`；
- 工作器未把变换证明元数据转成提升接口所需证书；
- CLI 只对已有 `submit_ready/reduced_valid` JSON 做导出门禁；
- 因而当前体现的是状态契约和防误提交接口，不是完整自动报告流水线。

### 2.11 方法取舍与创新性压力测试

#### 2.11.1 可靠性与覆盖率

- 放宽语法支持会生成更多变体，但未建模的空值、作用域、顺序或基数语义可能制造假等价；
- 当前选择“不能证明则跳过”，换取较清晰的接受依据；
- 代价是较高拒绝率，论文必须报告拒绝漏斗，而不能只报告最终接受数。

#### 2.11.2 静态与动态的互补

- 纯静态路线难以覆盖全部方言和实现差异；
- 纯动态路线只证明当前图上的相等，可能出现偶然等价；
- 当前组合以有限静态充分条件指导实例化，再以目标执行验证可观察一致性。

#### 2.11.3 运行时与根因证据分离

- 运行时不对称是发现事实；
- 执行计划、剖析指标和源码分析用于提出根因假设；
- 计划证据不能把未通过运行时门禁的查询对提升为问题；
- 开发者确认或修复是外部验证，不应反馈改变原实验真值。

#### 2.11.4 当前创新性的严格判断

- **可成立：** 在 GDBMS EQR 场景中，把有限三值逻辑规则、局部语义检查、类型多重集结果门禁和普通执行配对筛选组合成明确可信链。
- **仍不足：** 单一正式规则、局部解析器和未整合的确认/约简接口使其更像严谨原型，而非成熟通用框架。
- **不能依赖：** 历史 issue 数、代码模块数或配置中的七系统矩阵不能证明跨系统有效性。
- **建议定位：** “可审计的受限等价实例化与运行时候选筛选”，不提前包装为通用安全上下文框架。

## 7. 本版明确不写入方法主张的目标设计

以下内容不属于当前正式实现，只能留待后续版本：

- 属性化查询上下文图及跨子句语义依赖；
- 声明式证明义务语言；
- `SAFE/UNSAFE/UNKNOWN` 统一安全判定；
- 规则相关上下文切片；
- 结构化、可重放的重写适用性解释；
- 证明义务驱动的静态覆盖；
- 多步组合变换的逐步重新认证；
- 逻辑不一致与性能不对称双 Oracle；
- 基于上述机制的完整消融和正式跨系统结果。

当前小型 AST、关系代数式规范化、证明元数据和保守跳过机制可以作为未来工作的基础，但不能更名或包装为已经完成的通用框架。
