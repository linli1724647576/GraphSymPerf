# GraphSymPerf 方法大纲：受控图状态上的对称性测试

> 状态：当前实现版，更新于 2026-07-29。本文只描述已经接入正式运行工作器的主路径；未实现或尚未验证的扩展单列为后续工作。

## 0. 结论与研究边界

GraphSymPerf 当前主路径应定义为：

> 由 GDsmith 生成基础属性图，GraphSymPerf 对该图执行确定性的对合对称化，得到两个在保留重放身份键 `id` 之外严格同构的断开分量；随后从真实边、两跳路径和共享锚点模式中实例化图模式对称查询对，并以完整类型化结果等价和随机配对运行时间作为接受与筛选依据。

该定义严格遵守原始构想文档提出的两项要求：

1. `Q` 与 `Q'` 语义等价，或者在受控图数据上结果等价；
2. 两个查询的输入规模、选择性和结果规模相同或高度接近。

原始构想见 [GraphSymPerf.md](</Users/sakuraq/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/wxid_t9kcum5k5jqf22_7d60/msg/file/2026-05/GraphSymPerf.md>)。

当前方法明确排除：

- 布尔冗余、恒真式注入、短路或冗余计算类变换；
- 谓词交换、属性顺序、标签顺序、变量改名等普通等价重写；
- 不能证明逆关系语义的有向边反转；
- 任意可变长度路径反转；
- 使用执行计划、`PROFILE` 或开发者状态提升候选；
- 把运行时间差异直接表述为已经确认的性能缺陷。

仓库仍可能保留历史兼容模块，但正式实验工作器不再导入或调用这些模块。

## 1. 为什么必须控制图状态

只对随机查询做表面交换仍不足以建立强性能 Oracle，原因有三：

1. 两个查询可能落到不同度数、不同标签频率或不同属性分布的节点上；
2. 查询结果相同不代表访问规模、路径数量和中间结果规模相同；
3. 观测到的时间差可能来自数据不对称，而不是优化器对对称表达的敏感性。

因此，GraphSymPerf 不再只要求“查询文本对称”，而要求同时存在：

- **状态对称证书**：两个被查询的图分量具有显式对应关系；
- **查询对称证书**：查询对只使用图模式端点、路径端点或模式顺序对称；
- **动态结果门**：两个查询在目标 GDBMS 上普通执行并得到完整、类型化等价结果；
- **运行时间门**：随机化 AB/BA 配对执行后仍出现稳定、显著的不对称。

这将一般的 `Q → Q'` 等价重写问题改写为受控状态上的联合构造问题：

\[
(G_0, G_1, \pi, Q, Q')
\]

其中 \(G_0\) 与 \(G_1\) 是两个断开的图分量，\(\pi\) 是交换两者的对合映射。

## 2. 受控图状态的形式化

### 2.1 基础图

GDsmith 输出一个可重放属性图：

\[
G=(V,E,\lambda,\tau,\rho)
\]

其中：

- \(V\) 为节点集合；
- \(E\) 为有向关系集合；
- \(\lambda(v)\) 为节点标签集合；
- \(\tau(e)\) 为关系类型；
- \(\rho(x)\) 为节点或关系的属性映射。

跨系统重放依赖保留属性 `id`。该属性用于定位重放实体，不作为本文比较的业务语义属性。

### 2.2 对合双拷贝

GraphSymPerf 从 \(G\) 构造两个断开拷贝 \(G_0\) 和 \(G_1\)，并组成：

\[
G^\star = G_0 \uplus G_1
\]

对每个基础节点 \(v\) 和基础关系 \(e\)，建立：

\[
\pi(v_0)=v_1,\quad \pi(v_1)=v_0
\]

\[
\pi(e_0)=e_1,\quad \pi(e_1)=e_0
\]

因此：

\[
\pi^2 = \mathrm{id}
\]

构造器必须保持：

- 对应节点的标签完全相同；
- 除 `id` 外，对应节点属性完全相同；
- 对应关系的类型、端点对应关系和除 `id` 外的属性完全相同；
- 两个分量之间不存在交叉关系；
- 所有重放 `id` 唯一。

为兼容 AgensGraph 和 Apache AGE 的当前重放能力，构造器显式把 GDsmith 多标签节点投影到其主标签，并以 `portable_primary_label` 写入元数据。该步骤发生在对称构造阶段，不由适配器静默丢弃标签；因此这里保持的是两个派生分量之间相同的单标签着色，而不是对 GDsmith 原始多标签集合的无损复制。

严格表述应为：

> \(G_0\) 与 \(G_1\) 在擦除保留重放身份键 `id` 后同构。

当前证书字段使用 `involutive_isomorphism_modulo_replay_id`，不宣称包含 `id` 在内的完整属性图自同构。

### 2.3 状态相对查询等价

查询 \(Q\) 锚定 \(G_0\) 中的节点 \(v_0\)，查询 \(Q'\) 锚定对应节点 \(\pi(v_0)=v_1\)，并同时施加一种图模式对称。

当前查询统一返回：

```cypher
RETURN count(*) AS gsp_count
```

聚合投影避免暴露不同的重放 `id`，并使两个查询的可观察结果在同构下可直接比较。最终接受仍以目标 GDBMS 返回的完整类型化结果为准，而不是只信任构造证书。

## 3. GDsmith 能否直接生成受限图状态和查询

### 3.1 已确认可以控制的内容

GDsmith 当前命令行支持：

- 随机种子；
- 查询数量；
- 生成算法；
- 标签数量；
- 最大节点数；
- 手工图和手工查询输入模式。

当前 GraphSymPerf 使用 `COMPARED3`，并显式传入：

```text
--max-node-num 1024
--label-num 4
```

GDsmith 的图引导模式生成、数据引导条件生成和差分测试范围以 Hua et al.（2023）为依据：

- Ziyue Hua et al. 2023. *GDsmith: Detecting Bugs in Cypher Graph Database Engines*. ISSTA 2023. [DOI](https://doi.org/10.1145/3597926.3598046)
- [GDsmith 官方仓库](https://github.com/ddaa2000/GDsmith)

### 3.2 已确认不能直接表达的内容

当前随机图管理器会随机选择关系数量和关系端点。现有选项不能声明：

- 两个严格同构的断开分量；
- 给定阶数的图自同构；
- 指定节点度数序列；
- 指定枢纽节点、稀有标签或固定选择性；
- 指定路径数量或中间结果规模；
- 查询锚点必须落在某个已知对称轨道；
- 查询必须携带可验证的状态对称证书。

手工输入模式可以读取受限图和查询，但它只是输入通道，不会自动求解结构约束，也未接入当前正式生成路径。

因此，准确结论是：

> GDsmith 可以生成基础图、控制粗粒度规模并生成数据相关查询，但不能原生保证 GraphSymPerf 所需的精确状态对称；GraphSymPerf 必须在 GDsmith 输出之后执行证书化的确定性对称构造。

这仍符合“GDsmith 是唯一基础生成器”的架构约束，因为对称化步骤不引入独立随机数据源，只对 GDsmith 基图做确定性的主标签投影、身份重编号和双拷贝派生；关系类型、语义属性及两个分量之间的拓扑对应关系保持不变。

## 4. 当前实现流程

正式分片执行流程为：

```text
GDsmith 基图生成
  → 日志解析与可重放图提取
  → 对合双拷贝状态构造
  → 从真实拓扑实例化三类图模式对称查询对
  → 纯净性与目标方言门禁
  → 目标 GDBMS 普通执行
  → 完整类型化结果等价
  → 随机化配对运行时间筛选
  → 候选证据保留
```

正式工作器只需 GDsmith 生成一个引导查询；GDsmith 查询文本不再是变换输入。这样可以避免为得到 10,000 个候选而让 GDsmith 生成大量最终不会使用的普通查询。

每个接受记录至少包含：

- 查询对哈希；
- 两侧查询哈希；
- 图模式规则编号；
- 状态对称证书；
- `complete_typed_equivalent` 动态等价结论。

如果一个分片没有达到配置要求的接受查询对数量，工作器直接失败，不把未满配额的分片记为完成。

## 5. 首轮三类图专属对称

### 5.1 无向端点轨道对称

基础拓扑中存在：

\[
u \xrightarrow{R} v
\]

查询使用无向 Cypher 模式：

```cypher
Q:
MATCH (a:L_u {id: left_id})-[r:R]-(b:L_v)
RETURN count(*) AS gsp_count

Q':
MATCH (b:L_v)-[r:R]-(a:L_u {id: right_id})
RETURN count(*) AS gsp_count
```

安全条件：

- 锚点对应关系由状态证书给出；
- 只反转无向匹配的文本端点；
- 关系类型和两端标签保持不变；
- 不改变有向关系的语义。

规则编号：`undirected_endpoint_orbit_symmetry`。

### 5.2 固定两跳路径端点轨道对称

基础拓扑中存在两条不同关系组成的两跳路径：

\[
u -^{R_1} m -^{R_2} v
\]

查询对为：

```cypher
Q:
MATCH (a:L_u {id: left_id})-[r1:R1]-(m:L_m)-[r2:R2]-(b:L_v)
RETURN count(*) AS gsp_count

Q':
MATCH (b:L_v)-[r2:R2]-(m:L_m)-[r1:R1]-(a:L_u {id: right_id})
RETURN count(*) AS gsp_count
```

当前只实现固定两跳、无向路径。可变长度路径涉及重复路径语义、关系唯一性和方言差异，不在首轮安全域。

规则编号：`two_hop_path_endpoint_orbit_symmetry`。

### 5.3 共享锚点模式顺序轨道对称

基础拓扑中存在共享节点 \(u\) 的两个关系模式：

\[
(u)-^{R_1}(v),\quad (u)-^{R_2}(w)
\]

查询对交换逗号分隔的模式顺序：

```cypher
Q:
MATCH (a:L_u {id: left_id})-[r1:R1]-(b:L_v),
      (a:L_u)-[r2:R2]-(c:L_w)
RETURN count(*) AS gsp_count

Q':
MATCH (a:L_u)-[r2:R2]-(c:L_w),
      (a:L_u {id: right_id})-[r1:R1]-(b:L_v)
RETURN count(*) AS gsp_count
```

该规则保留共享变量、标签、关系类型和聚合投影，只改变图模式书写顺序及其对应状态轨道。

规则编号：`incident_pattern_order_orbit_symmetry`。

## 6. 为什么不采用其他候选规则

### 6.1 不采用谓词顺序

`p_1 AND p_2` 与 `p_2 AND p_1` 属于一般逻辑交换，不足以体现图数据库特有的拓扑、遍历起点和模式连接特性。

### 6.2 不采用无证书的边方向反转

`(a)-[:R]->(b)` 与 `(b)-[:R]->(a)` 通常不等价。除非 schema 显式声明逆关系并且数据状态满足双向对应，否则不能作为 CORE 规则。

### 6.3 不采用任意普通等价重写

Song et al.（2024）提出的 GRev 已经直接把等价查询重写（Equivalent Query Rewriting, EQR）用于 GDBMS 性能测试，并比较等价查询的运行时间。GraphSymPerf 若继续以普通 EQR 为主要贡献，差异化不足。

参见 Wenjie Song et al. 2024. *GRev: A Novel Testing Technique for Graph Database Engines*. ICSE 2024. [论文 PDF](https://joyemang33.github.io/assets/pdf/GRev.pdf)。

GraphSymPerf 的区分点不是“再增加若干等价规则”，而是：

> 同时约束图状态、查询锚点和图模式对称，并为每个查询对提供状态相对的证书。

### 6.4 与其他图数据库测试工作的边界

- Zhuang et al.（2024）的 Gamera 关注图感知变形关系和逻辑错误检测，但本文的候选信号是同一受控状态上的运行时间不对称。参见 [PVLDB 论文](https://www.vldb.org/pvldb/vol17/p836-zhuang.pdf)。
- Jiang et al.（2026）的 Dinkel 建模查询上下文和图 schema 以提高复杂查询有效率。基于其公开方法描述，本文推断它没有给出实例级同构分量和轨道锚点生成机制；该判断需要以论文全文复核为准。参见 [PVLDB 论文](https://www.vldb.org/pvldb/vol19/p1198-jiang.pdf)。

## 7. 接受、筛选与证据纪律

### 7.1 静态门禁

两侧查询都必须：

- 为只读查询；
- 不包含 `CALL`、写操作或可变长度关系；
- 通过目标方言检查；
- 通过目标适配器的重放能力检查。

### 7.2 动态结果门禁

两侧查询在同一目标图上普通执行。仅当：

- 均执行成功；
- 结果未截断；
- 类型化结果等价；
- 查询对哈希未重复；

才计入接受预算。

### 7.3 运行时间筛选

当前发现阶段使用：

- 3 次预热；
- 5 组随机 AB/BA 配对；
- 中位数运行时间比至少 2.0；
- 普通 `execute`，不调用 `PROFILE`。

2.0 只是候选阈值，不是通用缺陷标准。候选仍需独立会话复验、噪声下界、方向一致性、图重载和约简后验证，才能进入问题报告。

### 7.4 发现、假设与归因分离

必须区分：

1. **发现事实**：受控查询对出现稳定时间不对称；
2. **根因假设**：优化器可能对模式顺序、端点位置或扩展起点敏感；
3. **归因证据**：计划、算子计数、源码定位或开发者确认。

第二步不能冒充第三步。执行计划只用于候选产生后的解释和去重。

## 8. 可行性评估

| 子问题 | 结论 | 当前证据 | 主要风险 |
|---|---|---|---|
| 从 GDsmith 基图构造精确配对状态 | 高 | 已实现双拷贝、唯一身份、无交叉边和属性保持测试 | `id` 必须作为保留重放键排除 |
| 生成图专属查询对 | 高 | 三类规则由真实边和两跳拓扑实例化 | 首轮不含可变长度路径和有向逆关系 |
| 跨七类目标重放 | 中 | 查询使用固定长度、标签、类型、`count(*)` 的保守子集 | 各方言、标签模型和 schema 行为仍需真实系统验证 |
| 保证每分片 1,000 个接受对 | 中 | 节点上限提高到 1,024，并从边、路径和共享锚点组合生成 | 随机图过稀、重复模式或方言拒绝仍可能导致配额不足 |
| 形成高选择性锚点 | 中 | `id` 在数据上唯一 | 并非所有目标都会为派生标签自动建立索引 |
| 形成扩展压力 | 中低 | 查询来自真实关系和两跳邻接 | GDsmith 随机图不能保证高阶枢纽或特定度数分布 |
| 发现新的性能缺陷 | 未验证 | 尚未运行本方案的正式多系统实验 | 查询可能被规范化为同一计划，或图规模不足以超过噪声 |

总体判断：

> 工程实现可行，语义证书链也可成立；但性能缺陷产出率目前没有实验数据支持，不能从实现完成推断研究有效性。

## 9. 实验前必须完成的试点

正式 7×16 分片实验前，先运行小规模试点并报告：

1. 每个 GDsmith 基图的节点数、关系数、度数分布和三类规则候选数；
2. 各目标的方言拒绝率、执行错误率、结果不等价率和最终接受率；
3. `id` 锚点是否存在可用索引及实际查找方式；
4. A/A 配对的绝对时间差分布；
5. 三类规则分别达到 1,000 个接受对所需的生成规模；
6. 交换左右拷贝加载顺序后，候选方向是否保持；
7. 增大节点规模后，时间差是否随图规模呈可解释变化。

若第 3 项显示多数目标没有索引，论文不得写成“索引锚点对称性”；应先实现目标特定、左右一致的索引准备步骤，或把研究问题改为无索引状态下的模式枚举稳定性。

## 11. 当前可以与不可以写入论文的主张

可以写：

- GraphSymPerf 从 GDsmith 基图构造忽略保留重放身份键后的对合图同构；
- 查询对联合使用状态轨道和图模式对称；
- 当前实现覆盖无向端点、固定两跳路径端点和共享锚点模式顺序；
- 接受门要求目标系统上的完整类型化结果等价；
- 候选筛选只使用普通执行时间。

暂时不可以写：

- GraphSymPerf 已发现新的性能缺陷；
- 所有目标 GDBMS 都会为 `id` 使用索引；
- 当前状态满足包含 `id` 在内的完整属性图自同构；
- GDsmith 原生支持图自同构或受限拓扑生成；
- 首轮规则覆盖有向逆关系、可变长度路径或一般 join 交换；
- 1,024 个基础节点足以稳定产生每分片 1,000 个接受对；
- 运行时间差已经归因于特定优化器模块。
