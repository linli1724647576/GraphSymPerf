# GraphSymPerf 方法汇报：图状态生成与查询实例化

汇报日期：2026年10月22日｜建议时长：8-10分钟

## 一、汇报目标

本次主要汇报测试用例的生成机制。核心思路是：围绕一个明确的优化机会安排图状态，再构造结果相同的查询对，让可避免的工作随图规模增加，以便在执行时观察数据库是否遗漏了相应优化。

生成过程分为两个算法：**算法1负责配图，让图中存在可避免的候选工作；算法2负责填充查询骨架，并通过局部变异形成比较。** 下面用 P3 和 S3 套 S3 两个小例子说明。

遗漏优化（missed optimization）关注的是可避免的扫描、路径扩张或重复计算。查询结果相同是比较的前提；是否确实遗漏优化，还需要结合执行计划和实际工作量判断。

## 二、整体方法：语义先确定，图和查询相互约束

测试模式（pattern）规定局部变换及其前提；查询骨架（query skeleton）规定运算结构、变量依赖和待填空位。

- P3：交换无向路径两端的书写位置，保留端点约束和反转不变的观察。
- S3：在条件已经选定另一分支时，把未选中分支的低成本查询换成高成本查询。

```text
模式 + 完整骨架（包含所选外层语境）
                 ↓
算法1：保留必要结果，扩大候选工作
                 ↓
共同图 G + 构造条件 I
                 ↓
算法2：填充骨架，复制并局部变异
                 ↓
结果相同的查询对 Q1、Q2
```

低成本角色 L 可以是常量、唯一入口或小邻域；高成本角色 H 可以是大候选集合或读取它的计算。成本角色来自访问方式，不是节点自带的真假属性。

G 是两条查询共用的图。I 记录图中哪些区域对应哪些角色、成功或失败条件、必要数量和匹配对应关系，供实例化时保持。

影响构图的要求须提前确定。例如，外层要求 COUNT 大于2，就要给它直接统计的子查询准备至少三行。不能先配一条成功路径，再在实例化时临时增加这个要求。

## 三、算法1：怎样配出能暴露优化机会的图

算法1输入完整骨架、选定模式及扩张规模，输出共同图 G 和条件 I。第一幅算法图可以分成三组动作理解。

| 动作 | 对应图中步骤 | 方法含义 |
|---|---|---|
| 建立基础 | 初始化（Init）、图填充（Populate） | 确定锚点、共享连接和图中名称；建立必要见证，并安排可扩张区域 |
| 保持结果依据 | 设置守卫（SetGuards）、添加见证（AddWitnesses）、制造不平衡（Skew）、保持结构（Preserve） | 短路模式固定决定性条件与必要结果；对称模式放大候选差异，同时保留匹配对应 |
| 完成检查 | 添加索引（AddIndexes）、检查状态（Validate） | 提供所需的选择性入口，检查新增结构是否破坏模式条件或其他读取 |

其中，守卫是决定结果的条件，见证是保证所需结果存在的行或匹配。例如，S3 的条件为真决定选择哪一支；选中分支返回的一行0就是结果见证。

构图时，先沿抽象语法树（Abstract Syntax Tree，AST）的变量来源和结果使用关系，把外层要求传到直接生产者：COUNT 传递行数要求，EXISTS 传递空或非空要求，条件选择传递真假要求。随后创建满足这些要求的见证，再扩大指定区域。

扩张主要依靠两种直观机制：**新增候选被过滤或连接条件排除；新增计算有效，但它的输出被外层条件屏蔽。** 两种机制将在下面的 P3 和 S3 中分别展示。

## 四、算法2：怎样填骨架，并得到查询对

第二幅算法图也可以分成三组动作。

| 动作 | 对应图中步骤 | 方法含义 |
|---|---|---|
| 放置与填空 | 嵌入语境（Embed）、实例化（Instantiate）、适用性检查（Applicable） | 在既定语境中，按变量依赖填标签、关系、谓词和子查询，并保持 I 中的条件 |
| 复制与变异 | 复制（Copy）、提高潜在成本（RaiseCost）、对称变换（Rewrite） | 复制完整源查询；短路模式只做 L→H，对称模式只改变指定表示或次序 |
| 逐层检查 | 查询对检查（ValidPair） | 先建立完整局部结构的结果关系，再沿外层算子的使用关系向外传递 |

候选有三个来源：骨架允许的语法、当前位置可见的变量，以及 G 和 I 给出的角色与取值。类型正确仍不够，候选还要保持成功与失败的划分、数量和输出要求。

子查询使用同一填充规则：沿用允许的外层输入，先绑定变量，再填引用它的表达式。高成本替代 H 也遵循这套规则，不在变异时引入未经构图分析的新要求。

截图将嵌入语境放在算法2描述；在方法衔接上，凡是影响真假、数量或读取范围的外层要求，都要先纳入完整骨架，再交给算法1。

## 五、P3 案例：扩大无效路径，结果仍只有一个

### 1. 骨架要求

从 s 出发找二跳无向路径，要求路径上的每个节点都满足 keep=true，返回终点名字。

### 2. 算法1配图

```text
s(T) -- a(T) -- t(T)    有效
s(T) -- b(F) -- x(T)    无效
s(T) -- b(F) -- y(T)    无效
```

T、F 表示 keep 属性的真假。同名节点是同一个节点，后两条路径共用 s 和 b；图中只有这些边。

三条候选中，只有 s-a-t 全部为真。第一条保留成功结果，另外两条都经过假节点 b，不能通过全称条件（ALL）。继续给 b 接更多终点，只增加无效候选，有效匹配仍只有一条。

### 3. 算法2填充与变异

边的类型填 LINK，s 的标签填 Start，t、x、y 的标签填 End；各终点的 name 就是图中的名字。节点条件填 keep=true。

```text
Q1：MATCH p = (s:Start)-[:LINK*2..2]-(v:End)
Q2：MATCH p = (v:End)-[:LINK*2..2]-(s:Start)

共同保留：
WHERE all(n IN nodes(p) WHERE n.keep = true)
RETURN v.name
```

两条查询只交换无向路径两端。端点约束和返回变量没有改变；反向路径经过同一批节点，ALL 的真假也不变。因此两边都只返回 t。若外层统计有效匹配，计数都为1。

### 4. 要暴露的优化机会

如果到达 b 时及时检查条件，就可以排除它后面的失败分支；如果先展开路径再过滤，就可能处理更多候选。增加 b 后的终点数量，可以放大这部分潜在工作。

这里构造的是访问与剪枝机会。两种书写形式是否实际采用不同计划，须由执行证据确定。

## 六、S3 套 S3：扩大未选中分支，结果仍是一行0

### 1. 骨架要求

下面是两层条件行流。各分支返回同一整数列 value，但允许返回不同的值和行数。

```text
外层条件为真：
    内层条件为真：返回一行0
    否则：返回一行1          <- 只改这里
否则：返回一行2
```

本例选择外层和内层的“条件为真”分支，因此要求两个条件都为 TRUE。选中分支直接返回一行0，这一行本身就是见证。

### 2. 算法1配图

```text
u {outer:true, inner:true}
  |--H--> h1 {value:9}
  `--H--> h2 {value:9}
```

u 是唯一输入。两个属性用于实例化两层守卫；两个 H 邻居用于高成本替代。继续增加 H 邻居时，守卫属性和选中分支保持不变。

### 3. 算法2填充与变异

外层条件填 u.outer=true，内层条件填 u.inner=true。保留完整骨架，只替换内层“否则”：

```text
原来：返回一行1
变异：沿 u 的 H 边读取邻居的 value
      -> 返回两行9
```

低成本分支的一行1与高成本分支的两行9不相等；它们只需满足该位置的输出接口，并保留分支被屏蔽的条件。

### 4. 结果为什么能逐层保持

```text
内层条件为真 -> 两边都选择“一行0”
外层条件为真 -> 两边都返回内层的这“一行0”
```

因此，完整结果都为一行0。若外层再统计行数，两边都为1。结果关系从整个内层选择结构开始，再向外层传递。

H 分支从语义上无需参与最终结果计算；数据库是否仍提前求值或读取它，正是测试要检查的内容。增加 H 邻居可以扩大这种不必要求值的潜在代价。

如果内层条件变成 FALSE 或 NULL，就会选择“否则”，一行1与两行9不同，本次变异的依据不再成立。因此，守卫条件必须覆盖每个实际传入的输入。

## 七、两个案例共用的规则

| 共同过程 | P3 | S3 套 S3 |
|---|---|---|
| 先确定骨架及语义要求 | 二跳、ALL、相同端点输出 | 两层条件、选中分支、相同输出列 |
| 保留使结果成立的见证 | 成功路径 s-a-t | 选中分支的一行0 |
| 扩大指定区域 | 在假节点 b 后添加终点 | 给 u 添加 H 邻居 |
| 保持变量和角色对应 | 交换后仍返回相同终点变量 | 各层守卫及 H 读取使用同一个 u |
| 建立结果关系 | 路径反转对应，ALL 不变 | 整个内层条件行流输出相同，再传到外层 |

统一的是依赖分析、需求传递、见证保留、候选填充及结果关系的逐层组合。局部依据由模式语义给出：P3 靠过滤排除候选，S3 靠条件屏蔽分支。

递归包含两个方向：构图前把外层的真假、非空性和数量要求传向内层；变异后，从包含结果保持依据的完整局部结构开始，把相同输出逐层传向外层。这样才能扩大嵌套空间，同时保持方法逻辑自洽。

## 八、后续验证与汇报结论

验证依次回答三个问题：

1. 图与查询是否满足声明条件，完整结果是否相同，包括重复记录、NULL 和类型？
2. 扩大候选区域后，是否出现稳定的性能差异？
3. 执行计划及原生工作计数能否说明，差异来自可避免的路径扩张、分支求值或重复计算？

规模增长趋势是定位线索，不能单独证明遗漏优化。需要结合重复测量、执行证据及缩减后的案例，区分可避免工作与正常的必要工作。

本次汇报的结论是：**图状态决定优化机会是否存在、错过它会多处理多少候选；骨架实例化与局部变异决定怎样构造可比较的查询对。** P3 和 S3 分别展示了候选排除与语义屏蔽，两者可以使用共同的依赖和递归规则组织。
