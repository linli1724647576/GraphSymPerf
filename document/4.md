❌ 问题1：PMC evidence 写出链路断裂
------------------------------------------------------------
现象：
- pmc_summary.json 正常
- pmc_units.json 有统计
- pmc_evidence.jsonl 为空

说明：
PMC 只存在“内存统计”，没有“事件级证据记录”

这会导致：
- PMC 无法用于论文 trace
- 无法做 case-level analysis
- 无法支持 ablation study

------------------------------------------------------------
修复目标：
------------------------------------------------------------

必须保证：

1. 每一个 result-equivalent case 必须生成 PMCEvidence
2. 每个 PMCEvidence 必须写入：
   - pmc_evidence.jsonl（append mode）
   - case-level pmc_evidence.json
3. pmc_summary 必须由 pmc_evidence.jsonl 聚合生成，而不是内存 state

------------------------------------------------------------
检查点：
------------------------------------------------------------

- pmc_evidence.jsonl 不得为空
- pmc_units.json 必须可从 jsonl 重建
- summary 与 jsonl 必须一致（允许 small rounding）

============================================================
❌ 问题2：rule_stats 不自洽（严重统计错误）
============================================================

现象：
- generated=11
- equivalence_failed=91
- errors=7

这在统计上是不可能成立的

说明：
rule-level 统计混入了：
- family-level stats
- case-level stats
- 或重复累计

------------------------------------------------------------
修复目标：
------------------------------------------------------------

必须重构 rule_stats 统计语义：

规则：

1. rule_stats 必须是 “rule-level attempt counter”
   - attempted = 该 rule 实际被调用次数
   - generated = 该 rule 成功生成 query pair 次数
   - equivalence_passed / failed = 只针对 generated subset
   - errors / skipped = 独立统计，不可跨 rule 传播

2. 禁止：
   - family-level error 计入 rule
   - case-level重复计入多个 rule
   - pipeline failure 被重复归因

------------------------------------------------------------
约束：
------------------------------------------------------------

必须满足：

generated <= attempted
equivalence_passed + equivalence_failed + errors + skipped <= generated

如果无法满足：
必须显式拆分统计层级（不要硬修数字）

------------------------------------------------------------
输出要求：
------------------------------------------------------------

增加：

- rule_stats_consistency_check()
- calibration_health_report 中必须包含：
  rule_stats_valid: true/false

============================================================
❌ 问题3：Oracle gating 不严格（runtime / profile 混用）
============================================================

现象：
- latency ratio 7x
- threshold 不满足
- 但 runtime_confirmed = 1

说明：
runtime oracle 没有严格依赖 profile oracle gating

------------------------------------------------------------
修复目标：
------------------------------------------------------------

必须建立严格 oracle 层级：

1. result_equivalence (hard gate)
   -> 必须通过

2. profile_oracle (primary performance signal)
   -> 决定 profile_supported

3. runtime_oracle (secondary confirmation only)
   -> 只能在 profile_supported == true 时生效

------------------------------------------------------------
严格规则：

如果：
- latency_ratio < threshold
- OR latency_delta < threshold

则：
- runtime_confirmed MUST = 0
- support_level MUST NOT include latency_supported

------------------------------------------------------------
禁止行为：
------------------------------------------------------------

- 不允许 runtime 单独升级 candidate
- 不允许 latency override profile

------------------------------------------------------------
输出要求：
------------------------------------------------------------

新增字段：

- oracle_layer_status:
    result_equivalence: pass/fail
    profile: pass/fail
    runtime: pass/fail
