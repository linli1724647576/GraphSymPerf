二、修复目标
============================================================

修复后应该达到以下目标：

1. PMC artifact 完整
   - pmc_summary.json 可以保留。
   - pmc_evidence.jsonl 必须非空，至少包含每个 result-equivalent case 的 PMCEvidence。
   - pmc_units.json 必须非空，包含 run-level unique coverage units 或 unit count。
   - per-case pmc_evidence.json 必须能写出。
   - aggregate/triage 不应该只依赖内存 state。

2. PMC 语义更清晰
   - transformation_context 不再计入 core PMC total。
   - summary 中同时输出：
     - pmc_total_units_seen_all
     - pmc_total_units_seen_core
     - pmc_new_units_all
     - pmc_new_units_core
     - context_units
   - Top Units 默认展示 core units；context units 单独展示。
   - 当 metric_deltas 中存在 rows/actual_rows/records/db_hits/latency ratio 时，应该生成 cardinality_delta 或 work_delta coverage units。
   - 不要把 missing metric 当成 0。
   - 支持 metric 名称归一化：
     - rows / actual_rows / records / records_produced -> row_work 或 cardinality_delta
     - db_hits / actual_hits -> work_delta
     - latency_ms / median_ms -> runtime_delta 或 latency_delta
   - ratio buckets 使用配置中的 [1.5, 2, 5, 10, 50, 100, 1000]。

3. Rule config 和 registry 对齐
   - 不允许运行未出现在 enabled_rules 中的 rule，除非配置显式声明 alias。
   - 如果内部 rule 名和配置名不同，必须建立明确 alias mapping，并在 rule_stats 中使用 canonical rule name。
   - where_and_true_or_expr 如果是 and_true_or 的内部实现，要统一命名，不要在输出中出现未配置名称。
   - 对于 enabled 但没有运行的 rule，要在 summary 中给出 reason：
     - disabled_by_max_variants_per_case
     - not_applicable_to_case
     - no_safe_injection_site
     - unsupported_by_target
   - alpha_renaming_symmetry 不能悄悄 0 attempted。如果因为 max_variants_per_case 截断，要输出 warning 或使用 fair rotation，避免长期饥饿。

4. RuleStats 计数必须自洽
   - 每个 rule 的统计必须按真实生成的 variant 或真实尝试的 rule 记录。
   - 至少满足：
     - generated <= attempted
     - skipped <= attempted
     - equivalence_passed + equivalence_failed + errors + timeouts <= generated
       或者如果统计口径不是 variant-level，必须重命名字段并文档说明。
   - 不要把 family/case 级错误重复计入多个未生成的 rule。
   - feedback reward 只能基于自洽 stats 计算。
   - feedback.enabled=false 时可以被动收集 passive_rule_stats，但不要在 summary 中叫 feedback_top_rules；应叫 passive_top_rules 或 rule_stats_top_rules。

5. Support level / claim level / runtime confirmed 语义修复
   - 不要使用 states.confirmed 表示工具发现的候选；confirmed 应只用于 developer confirmed 或明确 runtime-confirmed。
   - 推荐状态：
     - equivalent_no_candidate
     - profile_supported_candidate
     - latency_supported_candidate
     - profile_and_latency_supported_candidate
     - plan_only_candidate
     - equivalence_failed
     - skipped
     - error
   - runtime_confirmed 只能统计满足 runtime threshold 的候选。
   - 如果 latency.worsened=false，则不能计入 runtime_confirmed。
   - 如果 support_level=profile_supported，不能标记 RuntimeOnlyOutlier。
   - RuntimeOnlyOutlier 只能用于没有 plan/profile 支持、只有 latency signal 的候选。
   - latency ratio 可作为 observed_latency_ratio 记录，但不能进入 runtime_supported，除非满足 min_latency_ratio 和 min_latency_delta_ms。

6. Symmetry candidate fast/slow 方向修复
   - 对 symmetry family，报告中应统一使用 fast_variant 和 slow_variant。
   - metric_signature 应基于 slow/fast ratio，而不是模糊的 original/transformed。
   - 如果仍保留 original/transformed 字段，必须同时写出：
     - original_variant_id
     - transformed_variant_id
     - fast_variant_id
     - slow_variant_id
     - delta_direction
   - review_candidates.md 中的 Metrics 应该和 evidence 中的 metric_deltas 方向一致。
   - plan_diff 对 symmetry 应支持 comparing fast plan vs slow plan，避免因 original/transformed 命名造成误读。

7. Skip/error diagnosis
   - 增加 skip_reason_summary.json。
   - summary.json 中增加：
     - skipped_by_system
     - skipped_by_rule

     - skipped_by_reason
     - errors_by_system
     - errors_by_rule
     - errors_by_reason
   - 每个 skipped case 必须尽量记录具体 reason：
     - no_safe_injection_site

     - result_timeout

   - 对跨系统运行，特别要统计 Neo4j-generated GDsmith queries 在 Memgraph/FalkorDB/ArcadeDB/AGE 上的兼容性问题。
   - 如果 skip rate > 50%，calibration_health_report.md 应给出 warning。
