# Missed optimization: mirroring an undirected path loses node-predicate pruning

Hi Neo4j team,

I found that mirroring an undirected path prevents the same `ALL` predicate from being pushed into `VarLengthExpand`. Both queries return the same result and start from the same indexed node, but the mirrored form traverses a large branch that could be rejected at its first node.

I reproduced this on Neo4j 2026.09.0 Community, Cypher 25, in Docker on macOS ARM64.

### Reproduction

Please use an empty database and create this graph:

```cypher
CREATE INDEX gsp_cost_lookup IF NOT EXISTS
FOR (n:GspLow) ON (n.id);

CREATE (u:GspLow {uid: 1, id: 1, keep: true})
       -[:GSP_LINK]->(:GspMiddle {uid: 2, keep: true})
       -[:GSP_LINK]->(:GspHigh {uid: 3, keep: true})
CREATE (u)-[:GSP_LINK]->(:GspBad {uid: 0, keep: false});

MATCH (b:GspBad {uid: 0})
UNWIND range(1, 10000) AS i
CREATE (b)-[:GSP_LINK]->
       (:GspMiddle {uid: 895440 + 2*i, keep: true})
       -[:GSP_LINK]->
       (:GspHigh {uid: 895440 + 2*i + 1, keep: true});

CALL db.awaitIndexes(60);
CALL db.prepareForReplanning();
```

The branch through `GspBad` cannot produce a valid result because `keep=false`. The separate two-hop path is the only valid witness.

Run the first query:

```cypher
PROFILE
MATCH p = (u:GspLow {id: 1})-[:GSP_LINK*1..3]-(v:GspHigh)
WHERE all(x IN nodes(p) WHERE x.keep = true)
RETURN u.uid, v.uid, length(p) AS hops;
```

Then run the mirrored query:

```cypher
PROFILE
MATCH p = (v:GspHigh)-[:GSP_LINK*1..3]-(u:GspLow {id: 1})
WHERE all(x IN nodes(p) WHERE x.keep = true)
RETURN u.uid, v.uid, length(p) AS hops;
```

### Observed behavior

Both return one row: `(u.uid, v.uid, hops) = (1, 3, 2)`.

The following is a compact excerpt of the recorded PROFILE fields:

```text
First query:
Operator               Rows   DB Hits   Relevant detail
Filter                    1         2   v:GspHigh
VarLengthExpand(All)      2        12   WHERE all(x IN nodes(p) WHERE x.keep = true)
NodeIndexSeek             1         2   u:GspLow(id)
Total DB Hits: 18

Mirrored query:
Operator               Rows   DB Hits   Relevant detail
Filter                    1     50006   v:GspHigh AND all(x IN nodes((v)-[anon_0*]-(u)) ...)
VarLengthExpand(All)  20003     40010   (u)-[anon_0:GSP_LINK*..3]-(v)
NodeIndexSeek             1         2   u:GspLow(id)
Total DB Hits: 90020
```

The mirrored plan still expands from `u`; it does not switch to the high-cardinality endpoint. The difference is that `ALL` becomes a filter after expansion, so traversal continues beyond the `keep=false` node. The first plan rejects that node during expansion.

I also reproduced this with 50,000 noise branches and the anchor condition written as `WHERE u.id = 1`: the result was unchanged, while total DB Hits were 18 versus 450,020. Rebuilding the graph, refreshing statistics and the query cache, and warming both queries did not remove the plan difference.

### Expected behavior

Reversing the path preserves its nodes and length. Since this predicate only checks each node's `keep` property, it should remain eligible for the same early pruning in either orientation.

Could you please look into why predicate pushdown is lost for the mirrored form? Thank you for your time and for maintaining Neo4j.
